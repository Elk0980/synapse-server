# reels-check — автопроверка роликов перед показом Владу

Каждый рилс и каждое видео для сайта проверяется по общему списку правил [RULES.md](RULES.md). Правила собраны из прежних замечаний Влада и документов по видео. Ролик с хотя бы одним ✘ Владу не показывают.

## Зависимости

- Python 3.9+ и `numpy` (`pip install numpy`).
- `ffmpeg` и `ffprobe` в `PATH`: Ubuntu — `apt-get install ffmpeg`, Windows — сборка с ffmpeg.org, добавленная в `PATH`. Фильтры `ebur128`, `geq`, `reverse` и кодер `libx264` входят в обычную сборку.

Сеть скрипту не нужна. Он ничего не публикует и не меняет исходный файл.

## Запуск

```bash
# фон на сайте, который крутится сам (механики M1 и M4)
python3 tools/reels-check/check.py hero-loop.webm --profile site-loop --mechanic M1
# блочный ролик для телефона: лимит 350 КБ
python3 tools/reels-check/check.py block.mp4 --profile site-loop --mechanic M1 --mobile
# ролик под прокрутку (M2 — проезд, M3 — сквозной)
python3 tools/reels-check/check.py pass.mp4 --profile site-scrub --mechanic M2
# рилс: проект задаёт правило звука, титры проверяются по файлу .srt или .ass
python3 tools/reels-check/check.py reel_v4.mp4 --profile reel --project avokado \
    --subs reel_v4.ass --source raw_from_generator.mp4 --frames-dir out/frames
# отчёт для доски или другого инструмента
python3 tools/reels-check/check.py reel_v4.mp4 --profile reel --project alvi --json
```

Ключи:

| Ключ | Зачем |
|---|---|
| `--profile reel` / `site-loop` / `site-scrub` | Набор правил. По умолчанию `site-loop` проверяется как M1, `site-scrub` — как M3 |
| `--mechanic M1…M5` | Механика из MEHANIKI_DVIZHENIYA: лимит веса, кодек, счёт событий. M5 — движение кодом, видео не проверяется |
| `--source` | Исходник от генератора или съёмки. Без него увеличение (R05) и кроп вертикали (R04) отмечаются «—» |
| `--project alvi\|avokado\|palitra\|synapse` | Правило звука рилса (R16). Без проекта — «—» |
| `--subs` | Файл титров `.srt` или `.ass` для R19 |
| `--frames-dir` | Сохраняет первый, средний и последний кадр для ручных правил |
| `--mobile` | Лимит 350 КБ для блочного ролика на телефоне |
| `--json` | Машиночитаемый отчёт |

Отметки: ✔ — правило выполнено, ✘ — брак, ⚠ — посмотреть глазами или оговорить в отчёте, «—» — не проверялось (нет данных или правило не относится к профилю). После автоматических строк идёт список «Проверить глазами» — это ручные правила профиля.

Код выхода: `0` — нет ✘; `1` — есть ✘; `2` — ошибка запуска (нет numpy или ffmpeg, неверный ключ, файл не найден или не читается, любой внутренний сбой). На вход принимается только локальный файл: адреса и протоколы ffmpeg (`http://`, `concat:` и т. п.) отклоняются.

### Как измеряется

- **Шов петли (R07)** — RMS разницы последнего и первого кадра в градациях серого 0–255, кадр уменьшен до 160 px по ширине. До 3 — ✔, от 3 до 8 — ⚠, больше 8 — ✘.
- **Реверс (R06)** — для каждой возможной точки разворота сравниваются пары кадров `c−d` и `c+d` на отрезке 0,5–1 с. Если зеркальные кадры почти совпадают (отношение к движению от точки разворота меньше 0,2), это ✘. От 0,2 до 0,3 — ⚠. Статичный кадр не оценивается: R06 получает «—». Детектор ищет только обратный ход с той же скоростью: реверс на половинной или другой скорости (кадры `c−d` и `c+2d`) он не ловит — такой ролик проверяют глазами. Естественное качание тоже может дать ✘; такой случай показывают человеку, а исключение для него вносят в RULES.md только по решению Влада.
- **События (R09)** — для каждой пары соседних кадров берётся 99,7-й процентиль модуля разницы. Событием считается всё, что выше двух фоновых значений (медиана, но не ниже 2). Соседние срабатывания ближе 0,25 с объединяются.
- **Ключевые кадры (R13)** — флаги пакетов `ffprobe`, самый длинный промежуток не больше 15 кадров.
- **Громкость (R18)** — интегральная громкость `ebur128`.

Пороги взяты из документов. Если они неверны для реальных роликов, их меняют вместе с правилом в RULES.md и тестом.

## Новое замечание Влада → правило в тот же день

1. **Замечание → правило.** В тот же день добавить строку в [RULES.md](RULES.md): следующий свободный `id`, формулировка проверяемым действием, источник (документ или замечание, дата, код проекта), «Авто», профиль, статус. Если замечание отменяет прежнее правило, старое переносится в «Отменённые» с основанием. Противоречие записывается в раздел «Противоречия», и действует последнее решение Влада.
2. **Можно измерить — добавить проверку.** Новая функция в `check.py` с тем же `id`, тест на синтетическом ролике в `test_check.py`. Нельзя измерить — строка в `MANUAL` нужного профиля, чтобы правило попадало в список «Проверить глазами».
3. **Прогон по всем роликам в работе.** В тот же день перепроверить все ролики в работе всех проектов, а не только тот, к которому было замечание. Ролики, которые теперь получают ✘, возвращаются в монтаж до показа Владу.
4. **Тесты.** `python3 -m unittest discover -s tools/reels-check -p 'test_*.py'`. Тест `RulesFileTest` не даст сослаться в скрипте на правило, которого нет в RULES.md.

В публичный репозиторий не попадают имена людей (кроме «Влад» и «владелец»), телефоны, адреса, переписка, ссылки на частные диски и сами ролики. Проекты называются кодами: `alvi`, `avokado`, `palitra`, `synapse`.

## Куда прикладывать отчёт

Отчёт прикладывается к задаче этого ролика на доске Synapse **до показа Владу**: комментарий с текстом отчёта (или JSON) и строкой «правила: N, ✔ X, ✘ Y, вручную Z, проверил: <исполнитель>». Ручные правила отмечает тот, кто смотрел кадры. Проверяющий должен быть не автором монтажа (R31). Самоотчёт без замера считается непроверенным.

## Что не входит в скрипт

- Проверки на живой странице: атрибуты `autoplay muted playsinline`, число живых блоков, отключение на телефоне (R14, R15). Их проверяют в браузере.
- Содержание кадра: лицо под титрами, лист персонажа, палец, маска телефона, личные данные, цена (R20–R24, R27–R30). Скрипт только выгружает кадры для просмотра.
- Сами ролики. Они хранятся на Google Диске проекта, в репозиторий не кладутся.
