# Авто-слияние контента сайтов

Задача №249: постоянное поручение владельца от 08.11.2026. Workflow `Site content auto-merge` делает squash PR, если все файлы входят в статические корни и расширения, перечисленные **в самом workflow**. Изменение этого списка, скрипта или workflow требует обычного независимого ревью. Защита main и её метки остаются действующими; служба не добавляет метки, не одобряет собственные изменения, не использует admin/bypass и не меняет настройки репозитория.

Обработчик использует только GitHub metadata API. Привилегированный job получает код исключительно из `main`, не исполняет PR, не читает артефакты или кеш PR. Новых ключей нет: применяется штатный короткоживущий `GITHUB_TOKEN` с contents/pull-requests write и checks/statuses read. Тестовый job имеет только contents read.

Допуск требует:

- Открытый готовый PR в main из того же репозитория от OWNER/MEMBER/COLLABORATOR; нет конфликтов или запросов исправлений.
- Не больше 200 добавленных/изменённых статических файлов; каждый обычный blob 100644 не больше 5 МиБ, все страницы списка файлов и дерево получены полностью. Удаления, переименования, симлинки, исполняемые файлы, серверные/config/test файлы, ключи и скрытые пути исключаются.
- Последние проверки **точного head** завершены успешно; обязательные guard-tests/process-check и статус production-sites/path-approval принадлежат GitHub Actions. Дополнительная незавершённая или упавшая проверка также задерживает merge.
- Head включает актуальный main. Перед squash повторно сверяются PR/head/base/метки и main. API merge получает ожидаемый head SHA; правила GitHub остаются последним барьером.

Если main ушёл вперёд, автор обновляет свою ветку обычным способом и получает новые проверки. Автомат не подменяет проверенный head или конфликтующую ветку. Обработка начинается по готовности проверок через workflow_run; расписание раз в 5 минут — резерв, оно не даёт гарантии времени доставки событий GitHub.

Автосинк статических сайтов уже поддерживает squash: подтверждает merged PR, равенство дерева main проверенному head и зелёные проверки до merge. При продвижении main между последней проверкой и merge равенство дерева не подтверждается, и автосинк ждёт CI main; это безопасная остановка, а не доказательство публикации. Merge от GITHUB_TOKEN может не запустить другие workflows: нельзя подменять эту проверку обещанием push CI.

Проверки: `python -m unittest discover -s tools/site-content-automerge -p 'test_*.py' -v`. Моки не выполняют настоящих слияний. Живая приёмка отдельно: тестовый PR автора с HTML в drafts → squash без ручного вызова за ≤5 минут после зелёного CI → HTTP200 exact bytes. Отдельный PR с ops-файлом не должен автоматически сливаться. До этих наблюдений механизм не считать принятым.

Отключение: отключить workflow штатным управлением GitHub Actions; никаких изменений защиты main. Откат кода — обычный PR с независимым ревью. Не снимать protection и не менять ключи ради продолжения.

Источники поведения GitHub: [безопасный pull_request_target](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target), [события и GITHUB_TOKEN](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow).
