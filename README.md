# synapse-server

Конфигурация сервера **synapse-core** (72.56.249.147, Timeweb Cloud, Москва).
Сервер забирает этот репозиторий каждые две минуты и применяет изменения сам.

## Что здесь

| Путь | Что это |
|---|---|
| `docker-compose.yml` | Единственный сервис — Caddy: принимает 80/443, сам выпускает и продлевает сертификаты |
| `caddy/Caddyfile` | Соответствие «домен → папка». Новый клиент = новый блок |
| `panel/` | Панель черновиков: все сайты в одном месте, `panel.synapsebusiness.ru` |
| `sites/<клиент>/` | Файлы сайта клиента |

## Как добавить сайт

1. Положить файлы в `sites/имя/`.
2. Добавить блок в `caddy/Caddyfile`:

```
имя.synapsebusiness.ru {
	root * /srv/sites/имя
	import static
}
```

3. Закоммитить. Через две минуты сайт откроется по адресу с рабочим HTTPS.

Поддомены резолвятся заранее: в DNS стоит `A * → 72.56.249.147`, поэтому
заводить запись на каждый новый поддомен не нужно.

## Черновик и публикация

Черновой вариант — обычный поддомен с `header X-Robots-Tag "noindex, nofollow"`:
открывается по ссылке, но не попадает в поиск. Публикация — снять эту строку
и привязать домен клиента.

## Что здесь не хранится

Пароли, токены, ключи — никогда. Репозиторий публичный, всё содержимое
и так отдаётся посетителям сайтов.

## Ручное применение

```
systemctl start synapse-sync.service   # применить сразу, не дожидаясь таймера
journalctl -u synapse-sync -n 50       # что делал таймер
tail -50 /var/log/synapse-sync.log     # лог синхронизации
docker compose -f /opt/synapse/docker-compose.yml ps
```
