# Palitra: товар → оформление

Кнопка «Перейти к оформлению» в окне товара открывала корзину без добавления товара. При пустой корзине форма отклоняла отправку до запроса к серверу.

Теперь кнопка передаёт настоящий id товара общему обработчику корзины. Он добавляет одну штуку, если товара ещё нет, сохраняет уже выбранное количество, закрывает окно товара и открывает оформление. Повторный переход не увеличивает количество. Открытие/закрытие карточки, обычный значок добавления и остальные кнопки корзины сохраняют прежнее поведение. Неверный id и заполненная корзина дают сообщение внутри окна; оформление не объявляется открытым успешно.

## Проверка

Root выполнил 14 сценариев в изолированном headless Chromium: исходный дефект, CTA, значок, количество4, повтор, неизвестная цена, открытие/закрытие, неверный/пустой id, лимит30, два accepted mock receipt, отказ и receipt безorderId. Все HTTP запросы перехвачены; реальных заказов или сообщений нет. Это локальная проверка, не приёмка сайта или доставки Telegram.

Стенд исполняет настоящие price-render/price-format/order в порядке сайта. Требуются Node.js и Playwright с Chromium. Запуск: node test/cart-flow.test.cjs. Для установленного Chrome можно передать PALITRA_QA_CHROME, для отдельного установленного модуля Playwright — PALITRA_QA_PLAYWRIGHT_MODULE. Пользовательский профиль не используется; контексты/браузер закрываются в finally.
