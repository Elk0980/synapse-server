# Сторож «Монтаж» — №285

Node 24, встроенные модули. Интервал 150 секунд; рабочий путь — один worker внутри действующего content и его постоянной SQLite-БД, рядом с существующими фоновыми обработчиками. Используются projectChat.fallback, его провайдеры, цены и бюджет. Нового процесса модели/службы/ключей нет.
Пустая очередь не обращается ни к модели, ни к монтажёру. EDL передаётся без модели.

Альтернативный самостоятельный режим: `node ops/montage-watcher/main.js`. Не запускать одновременно со встроенным worker. `MONTAGE_WATCHER_ENABLED=0` отключает встроенный обработчик для адресной остановки/отката.

Окружение: существующие `CRM_URL`, `CRM_API_KEY`; `HUGH_RUNTIME_URL`, `CHAT_API_KEY` для уже
подключённого изолированного Hugh. Отсутствие runtime или исполнителя приводит к задаче
Claude, не к выдуманному успеху. Ключи не печатать и не переносить в YAML/описания.
`MONTAGE_WATCHER_DB` задаёт постоянный путь (по умолчанию `/data/montage-watcher.sqlite`).

Для нескольких **уже подключённых** runtime `MONTAGE_RUNTIMES_JSON` задаёт массив объектов
`{name,url,keyEnv,model?,price?}`, где price содержит `promptMicroUsdPer1k` и
`completionMicroUsdPer1k`. keyEnv — имя существующей переменной, не значение ключа.
Выбор — по фактическому `/status`, model проверяется в ответе. При нескольких доступных
runtime без полной информации о цене обработка закрывается с эскалацией. Единственный
доступный runtime используется без выдуманной денежной оценки. Для интеграции в content
экспортирован `createBudgetedClassifier(projectChat.fallback)`: используются существующие
провайдеры, цены и бюджет, никаких дополнительных финансовых таблиц.

`MONTAGE_EXECUTOR_URL` — подтверждённый endpoint действующего монтажёра. Сторож отправляет
POST `{idempotencyKey,item}` и одноимённый заголовок `Idempotency-Key`, ожидает
`{accepted:true,companyCode,id,type}`. Поле item — данные проверенной CRM, не команды shell.
Существующий служебный ключ берётся из `MONTAGE_EXECUTOR_KEY` или `CRM_API_KEY`.
Действующий исполнитель обязан постоянно хранить ключ повтора и сам выполнить CRM claim,
рендер/проверку и addVersion. Принятие HTTP-задания не означает фактический монтаж.
До подтверждения Claude конкретного входа этот параметр не заполнять по догадке.

SQLite координации хранит ключ/метаданные/фазу и SHA-256 неподтверждённого ответа, но не
тексты просьб/ответов и не ключи сервисов. После crash `dispatching` не повторяется. Для неизвестного
reply — задача Claude; повтор того же reply запрещён, чтобы не плодить события.
Эскалация создаётся через существующий `/tasks` по служебному ключу, `sourceRef` постоянный;
повтор после сетевой ошибки возвращает прежнюю задачу. Учётные записи не имитируются.
stdout — белый список кодов, время и числа, без произвольных ошибок/переписки/адресов.

## Выпуск

Рабочая упаковка: `node ops/montage-watcher/build-content-bundle.js`; проверка точного соответствия исходникам — та же команда с `--check`. Generated ops/content/montage-watcher-bundle.js нужен для существующего COPY *.js и штатного адресного prpatch, вручную его не редактировать. В него упакованы новые модули и неизменённые limits/errors Hugh; runtime и провайдеры не копируются.

Выпуск после ревью: проверить свободный ресурс у оператора, backup БД ДО сборки, prpatch только ops/content/server.js + ops/content/montage-watcher-bundle.js, PREP fail0, прочитать rollback, prgo только content. Общий compose, ключи, права и другие сервисы не менять. Убедиться в одной копии, обоих GET каждые150с, отсутствии вызовов модели на пустой очереди. Затем тестовая просьба/реальный монтаж — новая версия должна появиться от настоящего исполнителя. При ошибке — штатный rollback образа content, сохранённую forward-БД не затирать. Все таблицы watcher добавочные; прежние данные не переписываются.

`health.js` — необязательная read-only диагностика успешного poll в SQLite, ни моделей, ни очереди он не вызывает. В production путь БД — действующая content.sqlite (передать MONTAGE_WATCHER_DB для этой диагностической команды), standalone — его собственная БД. Свежесть — до6минут.

Тесты: `node --test ops/montage-watcher/*.test.js`. Настоящие ключи и реальные сообщения для локальных тестов не нужны. До живой проверки не объявлять worker подключённым.
