# Palitra: весь пользовательский контент внутри приложения

Spec: specs/049-palitra-content-calendar

Внутренние карточки, список материалов, редактирование той же записи, предпросмотры, согласование и отдельное планирование отправки работают в клиентской оболочке. Связанные версии брифа/плана имеют собственный native экран, CAS полного плана и отдельные действия owner. Реальные внешние ссылки опубликованной площадки сохранены; административных Synapse переходов нет. Общая модель остаётся одной — собственник видит ту же запись в Synapse Business.

Два CRM изменения только для readonly currentProfileRevision/profileState в существующем GETsettings и повторной проверки контекста после await. Новых прав, таблиц или интеграций нет. Native patch построен на свежих source-пинах с byte-exact сохранностью вне уникальных замен. Установка: runtime2, static9/new4, один дочерний CRM image и один CRM restart, остальные сервисы не перезапускаются; HTML последним. Нет восстановления БД и повторов неизвестных отправок.

Связанный draft после переноса допускает подготовку медиа/времени и точной связанной площадки с явным подтверждением. Текст/формат/подписи плана защищены, редактируются в native плане. Согласование и создание draft не запускают отправку; schedule — отдельное явное действие с серверными guards.

Полные технические гарантии и ограничения установщика см. INSTALLER.md. DirectDBwrites0 не равняется отсутствию действий демонов после перезапуска: prepare/apply/inspect проверяют readonly DB/очереди, защищённый backup безrestore и полную сохранность строк. Legacy deployment не включать. Старые apply не повторять, общий deploy ветки не применять.

Тесты компонентов и настоящего CRM/SQLite выполняются отдельно; личная браузерная/native приёмка фиксируется в приватном отчёте и specs evidence. Физический телефон и внешняя публикация этим пакетом не считаются принятыми. Пользовательские фото, материалы, BASE, backup и секреты в пакет не входят.
