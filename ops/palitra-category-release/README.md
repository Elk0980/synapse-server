## Состав и отдельные этапы

1. `manifest.json` и `install.py`: только три static-файла — `sites/synapse/palitra-editor.js`, `palitra-editor-model.js`, `palitra-occasions.js`. В manifest записаны полные BASE/AFTER SHA. Установщик скопирован из проверенного manager-entry пакета; единственная перемена — allowlist этих трёх путей. Проверка обратной замены этого блока даёт исходные байты. Его алгоритм, защита путей, SHA, резервных копий, повторного применения и отката сохранены.
2. `Dockerfile`: основа `palitra-main-usability-content:20261013`; копируются только `payload/content/palitra-price-validate.js` и `palitra-occasions.js` в соответствующие `/app/` файлы. Установщик не пишет host `ops/content` и не устанавливает backend-группу. Root отдельно сверяет фактические runtime SHA и делает image preflight/переключение своего единственного сервиса.
3. `payload/site/assets/catalog-live.js`: справочный кандидат для отдельного штатного native workspace save с fresh BASE и CAS. Этот файл не входит в static install и Docker COPY. Root читает свежую workspace revision и сохраняет через существующий store с историей и readback, без прямой замены файла.

`METADATA.json` содержит инвентарь байтов пакета, полные SHA и отдельно известные runtime BASE. В нём нет частных путей источников. Справочная SHA каталога из локального BASE не заменяет свежую native проверку.

## Проверка и установка — только Root

До применения Root проверяет владельца ресурса, свежие три static BASE SHA, runtime BASE, свободного единственного installer и фактическую workspace revision. Изменение BASE означает отказ и новую сверку, а не ослабление guard. Локальный пакет не означает публикацию.

Штатные параметры установщика: `--check --root /opt/synapse --backup-dir <absolute-backup-path>`, затем после принятой проверки `--apply --group static` с теми же явными путями. Backup должен находиться вне target root и каталога пакета. Root сначала выполняет необходимую офлайн проверку на изолированной копии BASE; подготовщик её не запускал.

После каждого отдельного этапа нужны точные readback SHA, проверка реального редактора и каталога. Роль, CSRF, свежая сессия, native history/CAS и price-validation остаются обязательными. Не выдавать принятую локальную реализацию за установленную, а изменение кода — за пользовательское «Проверил».

## Откат

Для static использовать только собственный receipt/backup этого package_id и `--rollback --group static`. Установщик сверяет current AFTER и backup BASE перед восстановлением; при чужом изменении отказывает. Image откатывается Root к лично сохранённой предыдущей конфигурации сервиса. Каталог — отдельной штатной операцией workspace с fresh CAS и нужной исторической версией. Сначала установить фактическое состояние; не повторять неизвестную запись вслепую.
