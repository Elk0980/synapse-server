Форма прежде связывала «Согласован» с немедленной постановкой в расписание и смешивала выключенную доставку с потерей подключения. Native host не принимал публикуемые опции при создании. Адаптер TikTok безусловно отклонял даже явно согласованный режим.

Исправления:

- Новая и старая карточки предлагают отдельное согласование без отправки. Оно не требует включённой доставки или будущей даты. Действие «Согласовать и запланировать» сохраняет прежние серверные права, актуальную версию, будущий срок и проверенные включённые назначения.
- В обеих формах есть явная аудитория TikTok и необязательные параметры комментариев, дуэтов и сшивания. Значения сохраняются в версии; правка отзывает согласование. Неизменённая старая карточка не перезаписывается, файлы и прочие опции сохраняются. Ограниченный редактор связанного плана сохраняет свои прежние границы.
- Host принимает опции новой карточки и независимо перечитывает их; при правке сравнивает порядок ключей по смыслу, сохраняет явное `false`. Неизвестный исход не повторяется.
- TikTok использует существующий REST-контракт Onlypult: четыре literal официального SDK 0.1.9, ровно одно видео и явно выбранная аудитория. Это **не** доказательство creator capabilities. Наше приложение является потребителем Onlypult; доступность выбранного режима проверяет провайдер. Нет нативного TikTok API, выдуманного endpoint, умолчания или fallback на другую аудиторию. Отказ или неизвестный результат не превращается в успешную публикацию.
- Материал без аудитории или подходящего видео блокируется до постановки группы в очередь. Старая очередь с таким материалом также останавливается до первого внешнего POST. Существующий общий механизм известных delivery blockers сохраняется.
- Instagram Story/Reel передаются отдельными параметрами выбранного формата новой карточки; при правке сохранённые параметры меняются только вместе с форматом. Маски, исходники видео и предыдущие экспорты не переделывались.
