# MCP задач Synapse — PR-1

## Архив модулей — задача #38, кодовый PR

Добавлены `archive_list`, `archive_read`, `archive_write` (всего 13 инструментов). Контракт, карта источников, отдельная offline-миграция с проверенным backup и границы выпуска описаны в [MODULE_ARCHIVE.md](MODULE_ARCHIVE.md). До её выполнения архив возвращает 503, прежние инструменты задач продолжают работать. Этот PR не устанавливает схему на сервер и не добавляет экран доски.

## Совместимость SQLite

PR #472 выпущен со схемой версии 8. Отдельное исправление добавляет миграцию 9: короткий индекс и триггеры сохраняют нормализацию имён и открываются SQLite 3.45.1. Миграция не переписывает бизнес-данные; перед применением нужен штатный backup и приёмка. По текущему поручению SQL-исправление **не сливать и не выпускать до ответа Claude «принято»**, текущий боевой не менять. Проверки и ограничения — в `specs/092-tasks-mcp/evidence.md`.

Единый реестр — существующая таблица `tasks` в CRM. Сервис предоставляет задачи, координацию, комментарии, ручной каталог агентов, рабочие сессии и журнал архива модулей. Контакты, лиды, сделки и автоматический запуск агентов не доступны.

Среда: Node 24. Официальный SDK MCP закреплён в `package-lock.json`; Streamable HTTP работает без транспортных сессий, отдельная рабочая сессия хранится в CRM. HTTP GET/SSE и DELETE возвращают 405; JSON-RPC передаётся POST, ответы — JSON. Поддерживается согласование версий SDK, включая `initialize` прежних MCP-клиентов. Проверяются Host, Origin, размер запроса и строгие схемы инструментов. Секреты и полные URL запросов не журналируются приложением.

## Временная авторизация

**OAuth 2.1 выполняется отдельной задачей после выпуска.** Постановщик подтвердил временный способ — секретный путь `https://tasks.synapsebusiness.ru/mcp/<токен>`. Сам `/mcp`, неверный токен и URL с дополнительной строкой запроса возвращают 401. Токен хранится только в окружении сервера. В отчётах указывать `SECRET_VALUE=REDACTED`. Ссылка с токеном даёт полномочия Owner на указанные проекты; передавать её только в собственные настройки подключения Owner. Не добавлять её в Git, переписку задач, снимки экрана и журналы HTTP-прокси.

Регистрация в каталоге или доступ по этому токену не подтверждает личность отдельного агента: это временная единая учётная запись Owner. Имена авторов — ручной учёт, `tracking: manual`. Полноценное разделение пользователей потребует OAuth и привязки личности.

## Настройка

Все новые переменные описаны пустыми значениями в корневом `.env.example`:

| Переменная | Назначение |
|---|---|
| `PORT` | Внутренний порт, по умолчанию 8080 |
| `CRM_URL` | Внутренний адрес CRM, по умолчанию `http://crm:8080`; разрешён также loopback для локальной проверки |
| `CRM_API_KEY` | Существующий межсервисный ключ CRM |
| `TASKS_MCP_TOKEN` | Случайный секрет длиной 32–256 символов `A-Z a-z 0-9 _ -` |
| `TASKS_MCP_OWNER_ID` | Положительный числовой ID существующего Owner |
| `TASKS_MCP_PROJECTS` | Явный список разрешённых кодов компаний через запятую, без `*` |
| `TASKS_MCP_PUBLIC_ORIGIN` | Публичный HTTPS origin; по умолчанию `https://tasks.synapsebusiness.ru` |
| `TASKS_MCP_DOCS_DIR` | Каталог утверждённых документов; в контейнере `/app/docs/handoff`, монтируется только для чтения |

Без Owner ID, allowlist, ключа CRM и токена сервис не запускается. Ключ CRM и identity Owner передаются только по внутренней сети, не принимаются из MCP-аргументов. `/health` возвращает только `{ "status": "ok" }`: это проверка процесса, а не подтверждение подключения CRM или готовности документов.

Карта не нужна для запуска процесса и инструментов задач/агентов. В Compose `create_host_path: true`: если `./docs/handoff` отсутствует, создаётся пустой каталог, поэтому отсутствие канона не останавливает общий `docker compose up` и запуск остальных сервисов. В контейнере каталог остаётся только для чтения. До передачи карты `session_start` возвращает MCP-ошибку со статусом 503 и сообщением «Карта не установлена», без регистрации сессии; `doc_read` также требует карту. Задачи, агенты и завершение существующей сессии продолжают работать. Появление карты и документов подхватывается следующим запросом без перезапуска.

Локальная установка и проверка:

```powershell
cd ops/tasks-mcp
npm ci --ignore-scripts
npm test
```

На этом компьютере обычный npm-cache вернул `EEXIST`. Проверенный отдельный cache для этой задачи — `D:/Codex/Worktrees/tasks-mcp-20261103/npm-cache-mcp`; при повторении той же ошибки можно добавить `--cache` с отдельным каталогом. Существующий общий cache не удалять.

## Инструменты

Постановщик подтвердил **10 инструментов**. Расхождение исходной строки приёмки закрыто; одиннадцатый инструмент не требуется.

| Инструмент | Аргументы и результат |
|---|---|
| `tasks_list` | `project`, `status`, `executor`, `parent_id`, `today`, `search`, `limit` ≤100, `offset`; `{tasks,pagination}` |
| `task_get` | `task_id`; необязательные `comments_limit` ≤20, `comments_offset`, `subtasks_limit` ≤100, `subtasks_offset`; задача с подзадачами, комментариями, координацией и `comments_pagination`/`subtasks_pagination` |
| `task_create` | `client_ref`, `title`, `project`; необязательные `description`, `priority`, `due_date`, `executor`, `reviewer`, `parent_id`, `source`, `status`, `links`; `{task,created}` |
| `task_update` | `task_id` и изменяемые `status`, `stage`, `executor`, `reviewer`, `due_date`, `blocker`, `next_step`, `links`, `revision`; для `stage` нужны `evidence` и `checked_at` |
| `task_comment` | `task_id`, `author`, `text`; добавляет неизменяемый комментарий |
| `agents_list` | Без аргументов; агенты с активными задачами и отметкой «нет отчёта» |
| `agent_report` | `agent`, `state`, `last_event`; необязательные `kind`, `mode`, `function`, `chat` |
| `session_start` | `agent`, `kind`, `request`; обязательные правила, документы с причинами, задачи агента, `session_id` |
| `doc_read` | `path` из карты; `{path,text}`, только чтение |
| `session_end` | `session_id`, `summary`; необязательные `state`, `statuses:[{task_id,status}]`; запись итога в CRM |

Поля — snake_case. Источник создания: `claude`, `gpt` или `manual`. Проверяющий отличается от исполнителя. Подзадачи — один уровень, в одной компании. Ссылки — HTTPS без встроенных учётных данных; типы `link`, `image`, `video`. Даты срока — существующая дата `YYYY-MM-DD`; пустая строка снимает срок. Даты подтверждения — ISO UTC. План дня включает незавершённые задачи со сроком не позднее текущей даты в Asia/Bangkok.

`task_get` по умолчанию возвращает первые 20 комментариев и 20 подзадач. Для продолжения передавайте соответствующий offset; `comments_pagination` и `subtasks_pagination` содержат `total`, `limit`, `offset`. Ответ CRM ограничен 32 MiB с проверкой размера во время чтения; превышение возвращает ошибку без автоматического повтора операции.

Ошибка инструмента возвращается как MCP `isError: true` с `structuredContent.error.status` и русским сообщением. Например, чужая компания — 404. Ошибка входной схемы обрабатывается SDK до CRM. Сетевой таймаут после записи означает неизвестный результат: сначала прочитать фактическую запись; создание можно сверить по `client_ref`, не повторять комментарий вслепую.

Пример запроса после безопасной установки переменной окружения `$env:TASKS_MCP_ENDPOINT` в текущем сеансе Owner (значение не печатать):

```powershell
$body = '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
Invoke-RestMethod -Uri $env:TASKS_MCP_ENDPOINT -Method Post -ContentType 'application/json' -Headers @{Accept='application/json, text/event-stream'} -Body $body
```

`tools/call` использует стандартный JSON-RPC формат:

```json
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"task_create","arguments":{"client_ref":"owner-request-unique-ref","title":"Проверить задачу","project":"synapse-business","executor":"Codex","reviewer":"Owner","source":"manual"}}}
```

## Документы постановщика

`docs/handoff/MAP.json`, документы канона и `docs/seed/` содержат приватные материалы. Эти каталоги исключены корневым `.gitignore`: их нельзя коммитить, включая принудительное добавление. Постановщик передаст утверждённые карту, документы и seed при выпуске. В репозитории и тестах используется только тестовая карта; сервис не создаёт собственную конституцию или документы вместо канона. Формат тестового примера:

```json
{
  "always": ["CONSTITUTION.md", "DIRECTION.md"],
  "rules": [
    {"match": ["сайт", "вёрстка", "palitra"], "read": ["PREFLIGHT_METODIKA.md"], "why": "Правила работы с сайтом"}
  ]
}
```

Это только описание формата, не утверждённая карта. Подбор — простое совпадение подстрок без учёта регистра. `always` добавляется к каждому запросу. Перед регистрацией сессии проверяется наличие всех выбранных документов. Отсутствующая карта даёт «Карта не установлена». Повреждённая карта и недоступный выбранный документ не считаются отсутствующей картой; внутренние ошибки не раскрывают пути или секреты. Ни один такой отказ не создаёт сессию. `doc_read` ограничен файлами карты, размером 512 KiB, не допускает абсолютные пути, `..`, alternate streams и символические ссылки.

## Начальный импорт

Файл `docs/seed/pult-20261103.json` должен предоставить постановщик; задачи и семь агентов из прототипа не восстанавливаются по догадкам. Входной формат: `{ "agents": [...], "tasks": [...] }`. Агент использует аргументы `agent_report`; задача — аргументы `task_create` и необязательные `status`, `idea`, `links`, `parent_ref`. `parent_ref` ссылается на `client_ref` родителя в том же файле. Поле `idea: true` принудительно задаёт `inbox`.

Импорт выполняется вручную при отдельно разрешённом выпуске. Пример из `/opt/synapse`, когда CRM уже работает, а приватный seed передан в `/opt/synapse/docs/seed/`:

```sh
docker compose run --rm --no-deps --volume /opt/synapse/docs/seed:/run/tasks-seed:ro tasks-mcp node seed.js /run/tasks-seed/pult-20261103.json
```

Одноразовый контейнер использует существующую внутреннюю сеть и настройки сервиса; CRM наружу не публикуется, зависимости не запускаются повторно. Это инструкция будущего выпуска, в работе над PR команда не выполняется.

Скрипт проверяет весь JSON до первой записи, создаёт родителей раньше детей, повторно использует `client_ref`. Начальные статус и ссылки записываются атомарно при создании каждой задачи. Повтор импорта не сбрасывает последующие статусы задач и состояния существующих агентов. При частичном отказе сверить фактические записи; результат сетевой записи может быть неизвестен. Импорт не выполняется автоматически при старте и не запускает агентов.

## Подключение и приёмка

Слияние и серверный выпуск разрешаются только после повторной приёмки Claude и отдельного разрешения Влада. Текущая задача заканчивается обновлением PR и проверками; сервер не изменяется.

При будущем разрешённом выпуске:

1. Постановщик передаёт утверждённые MAP и seed. Карту и каждый документ из `always` и `rules[].read` копируют из `C:\Users\Vlad\Documents\Codex\AI_HANDOFF` в `/opt/synapse/docs/handoff/` **мимо Git**, сохраняя относительные пути из карты. Seed передают отдельно в `/opt/synapse/docs/seed/`. Эти материалы не добавляют в публичный репозиторий и образ контейнера.
2. Сверяют единственного писателя, резервную копию CRM с WAL, конфигурацию Owner/allowlist/секретов, сборку и миграцию. Каталог документов остаётся read-only для контейнера; проверяют чтение от имени `node`, не расширяя доступ к клиентским данным. Отсутствие документов не мешает поднять сервисы, но до их передачи рабочая сессия не начинается.
3. Проверяют карту и документы, затем вручную выполняют импорт seed приведённой выше командой. По `client_ref` сверяют фактические записи, выполняют сквозной сценарий и проверяют старые записи и сеансы. Автоматического импорта при старте нет.
4. Проверяют реальные DNS/TLS и подключают секретный адрес в настройках Owner в Claude и ChatGPT, если их интерфейсы допускают URL без OAuth. Факт подключения подтверждают отдельно. OAuth 2.1 остаётся отдельной задачей после выпуска.

Сами документы из AI_HANDOFF, карта и seed в этом PR не требуются: их передача согласована на момент выпуска. Наличие API и локальных тестов не подтверждает коннекторы или боевую приёмку.

PR-1 расширяет существующий кабинет. PR-2 — встраивание в личное приложение после слияния его ветки. Состояния «локально готово», «слито», «на боевом», «проверено» фиксируются отдельно.

Совместимость прежнего handshake проверяется также по [спецификации 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).
