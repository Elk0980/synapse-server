# Установка приватной карты документов

Инструкция описывает механизм; утверждённых правил, карты и клиентских документов здесь нет.
Установку выполняет отдельный агент выпуска после приёмки PR; этот PR ничего не устанавливает.

## Контракт загрузки

`TASKS_MCP_DOCS_DIR` — приватный каталог внутри MCP-контейнера (по умолчанию
`/app/docs/handoff`). Штатный bind mount на хосте — `/opt/synapse/docs/handoff`,
только чтение для контейнера. Каталог и файлы должны читаться пользователем `node`.
Не добавлять материалы в образ, Git, PR, CI-артефакты или публичные логи.
`docs/handoff/` и `docs/seed/` уже исключены из Git.

Поддерживаются старый `always: ["RULES.md"]` и новый
`always: [{"doc":"RULES.md","why":"SAMPLE обязательный документ"}]`.
`rules` содержит `match`, `read`, `why`; необязательный `fallback` содержит
`read`, `why` и выбирается, когда ни одно правило не совпало.
`version` — версия карты, `rules_version` — отдельная версия правил.
Без `rules_version` возвращается `version`, без обеих — null; это не доказательство
версии содержимого. При выпуске указывать обе версии.

Каждый `session_start` читает свежую карту и проверяет все выбранные документы
до обращения к CRM. Ответ содержит `documents` с причинами, `rules` с полными
текстами из always, `rules_documents` с путями, обе версии и `rules_revision`
(SHA-256 карты и обязательных текстов). Встроенные тексты tools.js больше
не выдаются вместо приватного канона. Список инструментов не меняется.
`doc_read` разрешает только пути always/rules/fallback. Ограничения путей,
символических ссылок, UTF-8 и размера 512 KiB на файл сохраняются.

`rules_changed` сравнивает с предыдущим успешным входом имени и типа агента
в данном процессе: true/false, либо null при первом входе, перезапуске или
вытеснении из ограниченного кэша 1000 агентов. Кэш содержит идентификаторы и хеши,
без текстов. При изменении приходит просьба перечитать. Полный канон возвращается
всегда, включая возобновлённые старые сессии. Это уведомление, не блокировка записей
и не доказательство прочтения. Для нескольких процессов сравнение локально каждому.

## Агенту выпуска

1. Получить утверждённые MAP и актуальный RULES у постановщика через №24.
   Основа — комментарии 5/6, дополнения — 13/98/115/151/152. Комментарий 152
   указывает на окончательный RULES v1.2 в приватной базе Claude. Не собирать
   предполагаемый окончательный текст автоматически и не выдавать v1 за v1.2.
   Сверить точное имя документа с always; имя файла само по себе не доказывает
   версию. Передать все файлы always, rules[].read и fallback.read с сохранением путей.
2. Проверить владельца ресурса, общий release lock, фактический mount и рабочий
   managed-release. Сохранить приватный бэкап каталога и план отката. Не включать
   legacy-sync, не менять ключи, права людей, CRM-базу или другие сервисы.
3. В приватном staging проверить комплект загрузчиком documents.js принятого SHA:
   readMap, sessionDocuments для каждого match и запроса без совпадений,
   readDocument для каждого разрешённого пути. Версию и текст 1.2 сверить
   с постановщиком. В отчёте только результаты/хеши, не тексты.
4. Установить документы первыми, MAP.json последним через атомарный rename
   временного файла на том же filesystem. При обновлении использовать новые
   версионные имена документов, затем переключать карту; старые файлы сохранять
   для отката. Сам bind-каталог не заменять: контейнер может остаться на старом inode.
5. Код documents.js/server.js выпускать адресно действующим managed-release,
   сохраняя изменения других PR, включая tools.js из PR477. Не копировать весь
   checkout поверх runtime. Документы подхватываются без перезапуска процесса.
6. Через реальные коннекторы Claude и Codex проверить session_start: полный
   RULES v1.2, версия, карта по запросу и doc_read. Повторить для прежнего агента
   с открытой сессией и нового агента. Убедиться в сохранности задач/комментариев
   и запрете чтения вне карты. Уведомление об обновлении проверять при настоящем
   разрешённом обновлении канона; не менять production-правила ради проверки.
   Синтетический сценарий обновления уже покрыт тестом.
7. При сбое адресно вернуть прежнюю карту/документы и код из приватного бэкапа.
   Базу не восстанавливать поверх новых записей. Итог и доказательства — в №24.
   До живой проверки не ставить connected/verified/accepted.

Без карты сохраняется 503 «Карта не установлена» без создания сессии.
Повреждённая карта или недоступный выбранный документ также не создают сессию;
публичная ошибка не раскрывает приватные пути/тексты. Прочие инструменты работают.
