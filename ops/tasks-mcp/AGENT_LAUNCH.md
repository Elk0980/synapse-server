# Запуск локальных агентов — задача #40

Среда: Synapse Business, Node 24, подписка Codex владельца. Код готовится в ветке `codex/agent-launch-20261103`, без слияния и выпуска. Страница доски (#26), auth/push (#35), архив (#38) не входят в изменение. Кнопка на доске — следующий отдельный шаг. Отправленный в очередь запуск не означает работающий процесс или принятый результат.

## Путь выполнения

1. Owner/оркестратор вызывает `agent_launch(task_id, code_only=true, allowed_paths=["ops/module/"], executor_profile="codex-code")`. `code_only:true` обязательно: отсутствие производственных слов не разрешает запуск. `allowed_paths` содержит 1–100 точных путей файлов или префиксов каталогов с завершающим `/`, без корня, wildcard и traversal. Разрешение и область файлов неизменяемо сохраняются в run. Старые запуски автоматически не получают разрешение. Разрешён только явный список компаний подключения. Имя Claude не заменяет авторизацию. Необязательный `client_ref` защищает от дубля при неизвестном ответе.
2. Запуск сохраняется в существующей `task_dispatch`, метаданные — в добавочных `task_dispatch_agent_*`. Переход из обычного диспетчера разрешён только из `awaiting_executor`. Состояния `review`, `needs_input`, `blocked`, `queued`, `running` и закрытые состояния отклоняются с сохранением записи, результата, вопроса и истории. Старые задания, комментарии, файлы, проверяющие и подтверждения не переписываются. Серверный текстовый исполнитель не забирает кодовый запуск.
3. Локальный воркер сам опрашивает MCP, атомарно получает аренду и создаёт отдельный worktree/ветку `codex/agent-task-<task_id>-<run prefix>` от `origin/main`. Одновременно сервер выдаёт не больше трёх процессов, включая неизвестные после обрыва связи. Ожидающие в очереди запуски не занимают процессный слот.
4. `codex exec --json` получает промпт через stdin. У ребёнка отдельные пустые HOME/USERPROFILE/APPDATA/LOCALAPPDATA и временный каталог. В отдельном `CODEX_HOME` вне worktree находятся авторизация подписки, конфигурация и схема результата; shell-доступ к исходному HOME, каталогу Codex, состоянию со всеми копиями auth, SSH/GitHub credential paths и исходному checkout со всеми ignored `.env` запрещается профилем ОС. Авторизацию загружает доверенный хост CLI вне исполняемых команд. До аренды и копирования auth воркер должен подтвердить работу запретов, закрытой сети и выбранного shell на искусственных контрольных файлах. Общий Owner endpoint остаётся у воркера. Дочернему MCP доступны своя задача, комментарии, свой отчёт и сессия, документы выбранной карты; он не получает запуск/остановку других агентов или полный каталог задач. Ровно семь инструментов этого ограниченного MCP заранее разрешены в private config; общие approvals и конфигурация пользователя не меняются. API-провайдеры и ключи не наследуются.

   Локальные `AGENTS.md` и `AGENT-ECONOMY.md` читаются из исходного `TASKS_AGENT_REPO` по фиксированному списку, без символических ссылок и выхода за каталог; лимит 64 KiB на файл и 96 KiB суммарно. Их текст передаётся в промпт вместе с публичной памяткой воркера. Это сохраняет правила, даже когда они не отслеживаются Git и отсутствуют в новом worktree. Файлы не копируются в публичную ветку. Если обязательные инструкции недоступны и локально, и в карте, агент сообщает блокер.
5. Агент читает правила/задачу, отмечает работу и пишет существенные шаги в комментариях. При отсутствии карты получает точное безопасное сообщение «Карта не установлена» и продолжает только разрешённую локальную работу. Вопрос оформляет `ВОПРОС → Claude` в своей задаче.
6. Codex работает с профилем записи в свой worktree, запретом credential paths и shell-сети, без запросов расширения прав. Фиксированный доверенный publisher проверяет изменённые, staged и исторические пути по сохранённому `allowed_paths`, тип файлов и типичные секреты, публикует только свою feature-ветку и создаёт черновой PR в `main`. Готовый PR не переиспользуется: требуется отдельное review Claude, только после него человек/оркестратор может снять draft. Слияния и развёртывания publisher не выполняет. Если публикация не подтверждена, локальный результат сохраняется для проверки, повтор всего хода не запускается.
7. Только `turn.completed` с корректным структурированным итогом `outcome:"ready"` допускает publisher и состояние `waiting`. Exit0 с блокером, `outcome:"blocked"` или невалидным итогом даёт `failed`, сохраняет session для доработки и не публикует изменения. Задача сама не становится принятой или `done`. `agent_message` продолжает тот же `run_id`, точный `session_id` и worktree через `codex exec resume`; `--last` не используется. `agent_status` возвращает состояние и безопасные события жизненного цикла вместо сырых stdout/stderr.

## Остановка и неизвестный результат

`agent_stop` для очереди сразу останавливает запуск; для работающего процесса устанавливает `stop_requested`. Слот освобождается только после подтверждения завершения. Потеря heartbeat останавливает локальное дерево. Просроченная серверная аренда становится `unknown`, не возвращается в автоматическую очередь и продолжает занимать слот. После перезапуска локальный журнал не допускает повторного запуска неизвестного процесса. Не удаляйте state/lock ради обхода неизвестного результата: сначала подтвердите состояние процесса и задания.

На Windows воркер использует отдельный supervisor с Job Object и explicit MXC. Живая проверка ревью82 обнаружила: `unelevated` при `network_access=false` всё равно позволяет raw TCP и чтение credential canaries. Этот режим не допускается к исполнению кода. В уже установленном app CLI 0.166.0-alpha.5.1 MXC подтвердил запрет чтения контрольных секретных путей, запрет внешней записи и raw TCP при рабочей записи в workspace. На POSIX используется отдельная группа процессов; наличие реальных read-deny/network гарантий также должно быть проверено до запуска. Ошибки не переключают воркер на более слабый режим и не запускают настройку admin/ACL/firewall. Доступ к боевому серверу и его `.env` воркеру не нужен. Секретный MCP URL не передаётся в аргументах процесса и не включается в журнал задачи. Ограничения режимов описаны в [официальной документации Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox).

Runtime-папки Node, Codex и фактически выбранного PowerShell разрешены только для чтения, с проверкой пересечения с credential paths. Проверка до старта включает сам shell, а не только Node: `Set-Content`/`Get-Content` в своём workspace. В MXC PowerShell может работать в ConstrainedLanguage; для обычной записи/чтения использовать стандартные cmdlets или доступный Node, без запроса расширения прав. Ошибка .NET type/method в таком shell не означает отсутствие разрешённого способа выполнить локальную работу.

Исполняемые project-слои `.codex/config.toml` запрещены: actual CLI способен ими переопределить private-профиль или добавить MCP/hooks. Воркер проверяет lexical и canonical цепочку рабочей папки до копирования auth и повторно непосредственно перед spawn/resume; найденная конфигурация сохраняется, запуск отклоняется. Глобальная конфигурация исходного HOME не считается используемым project-слоем и не изменяется. Модель не может создать `.codex`/изменить `.git` благодаря защите workspace. Ненужные host-инструменты и расширения (`view_image`, web search, apps, plugins, hooks) выключены. Подписка и ограниченный MCP используют доверенный хост CLI; проверка закрытой сети относится к исполняемым командам и их потомкам.

## Локальная настройка после отдельного разрешения подключения

Нужны Node 24, Git, авторизованный Codex CLI (`codex login status` должен показывать ChatGPT), GitHub CLI для родительского publisher и локальная копия публичного репозитория. Для Windows проверен установленный app CLI 0.166.0-alpha.5.1 с поддержкой MXC; npm CLI 0.149.1 не поддерживает MXC. Воркер не выполняет вход, покупку подписки, установку CLI или настройку API самостоятельно.

Переменные окружения родительского воркера:

| Переменная | Значение |
|---|---|
| `TASKS_MCP_ENDPOINT` | Существующий секретный HTTPS endpoint Owner, передать вне Git/комментариев/логов |
| `TASKS_AGENT_REPO` | Абсолютный путь к локальному `synapse-server` |
| `TASKS_AGENT_WORKTREE_DIR` | Отдельный абсолютный каталог рабочих копий вне репозитория |
| `TASKS_AGENT_STATE_DIR` | Отдельный приватный каталог состояния вне Git и worktree |
| `TASKS_AGENT_CODEX_BIN` | Необязательно: путь к прямому executable или JS entrypoint Codex; `.cmd/.bat/.ps1` не принимаются |
| `TASKS_AGENT_WINDOWS_SANDBOX` | Только поддерживаемая реализация с доказанным read-deny; проверенный вариант `mxc`, без fallback на `unelevated` |
| `CODEX_HOME` | Необязательно: существующий каталог авторизации подписки, только источник для приватного run-каталога |

Worktree и state не должны пересекаться. State содержит локальные lease и копию авторизации подписки: права только владельцу, не синхронизировать в публичное хранилище. На Windows наследуемые ACL каталога также должны быть приватными; режимы POSIX не заменяют Windows ACL. Воркер не читает серверный `.env`.

После безопасной установки переменных запуск из checkout:

```powershell
node ops/content/agent-launch-local-worker.js
```

Остановка — Ctrl+C/SIGTERM; управляющий `agent_stop` относится к отдельному запуску. Серверные обновления требуют отдельного разрешения: новые MCP-инструменты появятся только после такого выпуска.

## Без простоев: «в сети», передача запасному, ревью и слияние (№194, specs/194-agent-queue-no-stall)

- **Сигнал «в сети».** Обработчик раз в минуту вызывает `agent_worker_update` с `event:"presence"` (без `run_id`/`lease_token`), опрос очереди тоже считается сигналом. `agent_workers_status` показывает «в сети» при сигнале не старше 3 минут, очередь и передачи за сутки. Доска: «Задачи → Агенты» и карточка задачи Codex.
- **Передача запасному.** Запуск, который 10 минут никто не забрал, сервер раз в минуту снимает из очереди (`stopped`), пишет в задачу «Не стартовал за N мин: …», ставит исполнителем «Claude — запасной исполнитель» и следующий шаг. Одна строка в утренней сводке. Процесса у такого запуска нет, поэтому снятие безопасно; позже можно снова вызвать `agent_launch`.
- **Правило оркестратора.** Перед `agent_launch` для Codex вызвать `agent_workers_status`; если `online:false` — сразу отдать задачу Claude-агенту, а не ставить в очередь.
- **Профиль `codex-review-merge`.** `agent_launch({task_id, executor_profile:"codex-review-merge", pr_number:N})` — без `code_only` и `allowed_paths`. Только открытый PR в `main` из ветки `claude/…`. Codex читает копию ровно на head и пишет замечания `РЕВЬЮ PR #N: …`; итог `approve|changes|blocked`. При `approve` доверенный обработчик проверяет, что head не сдвинулся и все проверки CI pass/skipping (ожидание до 15 минут), пишет «КОД ПРИНЯТ — PR #N, head …» и выполняет `gh pr merge --merge --match-head-commit`. Черновой PR сначала переводится в готовый. Метки (в том числе «сайты: инфраструктура») не ставятся, `--admin` не используется, deploy нет. Модель сама «КОД ПРИНЯТ» написать не может. Продолжение ревью не поддерживается — новый запуск на новый head.

### Автозапуск при входе в Windows

1. Создать приватный файл `%LOCALAPPDATA%\Synapse\agent-worker.json` с теми же переменными, с которыми обработчик уже проходил проверку изоляции вручную (адрес MCP в чат и Git не вставлять):

```json
{
  "TASKS_MCP_ENDPOINT": "SECRET_VALUE=REDACTED",
  "TASKS_AGENT_REPO": "<тот же путь, что при ручном запуске>",
  "TASKS_AGENT_WORKTREE_DIR": "<тот же путь, что при ручном запуске>",
  "TASKS_AGENT_STATE_DIR": "<тот же путь, что при ручном запуске>",
  "TASKS_AGENT_WINDOWS_SANDBOX": "mxc"
}
```

   Допустимы также `TASKS_AGENT_CODEX_BIN`, `CODEX_HOME`, `GH_CONFIG_DIR`, `NODE_EXE`; другие ключи запускатель отклоняет. Доступ к файлу — только у себя: `icacls "%LOCALAPPDATA%\Synapse\agent-worker.json" /inheritance:r /grant:r "%USERNAME%:F"`.
2. Установить задачу планировщика (без прав администратора):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ops\content\agent-launch-worker-autostart.ps1
```

3. Готово, когда на доске «Задачи → Агенты» видно «Обработчик Codex: в сети» (1–2 минуты). Проверка задачи: `-Status`; удаление: `-Uninstall`. Журнал запускателя — `%LOCALAPPDATA%\Synapse\logs\agent-worker.log` (только коды состояния). После сбоя обработчик перезапускается с паузой 30 с → 5 мин; второй экземпляр не запускается. Неизвестный после перезапуска запуск по-прежнему требует ручной сверки — сигнал «в сети» при этом идёт, а очередь стоит; это видно по счётчику очереди.

## Границы проверки

Запуск прежде всего требует явного `code_only:true` и сохранённого списка путей. Дополнительный RU/EN gate проверяет задачу, комментарии и продолжение на производственные команды, включая «залей на прод», «выкати на сервер», `git push origin main`, merge/deploy и варианты кириллицы. Стандартные отрицательные ограничения вроде «PR без merge/deploy» допускаются; неоднозначные формулировки могут быть отклонены. Словарь остаётся эвристикой и не заменяет явное разрешение, изоляцию ОС или review. Реальные ограничения дополняются запретом чтения указанных credential/state paths, закрытой сетью, ограниченным MCP и фиксированным publisher. Профиль с конкретными deny-read путями не означает запрет чтения абсолютно всех остальных файлов владельца. Проверка типичных секретов не гарантирует распознавание любого клиентского текста; проверяющий читает diff перед принятием PR.

Локальные тесты используют только синтетические задачи, временные базы и репозитории. Они покрывают старые записи/сеансы, права/компании, лимит 3, аренду без повторов, stop/resume, публикацию и ошибки транспорта. Реальная приёмка с кнопки доски за ≤2 минуты, серверный выпуск и постоянная работа на компьютере требуют отдельного разрешённого этапа; локальные тесты не подтверждают их выполнение.

Проверка:

```powershell
cd ops/tasks-mcp
npm ci --ignore-scripts
npm test
```
