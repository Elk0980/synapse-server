# Palitra: одинаковые категории в каталоге и редакторе

Вместо фильтра только по внутренним разделам прайса редактор показывает «Категория на сайте» с каноническими названиями и количеством товаров. Например, «Мальчишник (2)» находит прежние товары из «Других поводов», а «День рождения мужчины (11)» учитывает товары всех разделов. Поиск работает вместе с категорией, категория сохраняется после возврата из формы. Есть отдельный пункт для товаров без категорий.

В карточке товара и списке используется термин «Категории на сайте». Физический раздел переименован в интерфейсе в «Раздел хранения» и вынесен в дополнительные настройки. Новый товар получает категорию выбранного фильтра. Данные, цены, фотографии, старые ID/URL и принадлежность существующих товаров не меняются. Использован существующий параметр publicKey модели поиска.

## Проверка

Локально: шесть DOM-проверок на неизменённом текущем прайсе, включая старый HTML, все категории/счётчики, реальные два товара, комбинированный поиск, возврат из формы, отсутствие PUT/изменений документа. Фикстура прайса остаётся приватным артефактом. Шесть файловых проверок install.py доступны через `python test_install.py`: backup/readback, отказ повторного apply, нового значения целевого файла, изменения окружения/прайса, лишнего payload, повреждённого backup и истёкшего действия. Синтаксис JS проверен node --check. DOM-проверки не заменяют живую мобильную/встроенную приёмку.

## Область установки

Ровно три публичных статических файла в payload; изменения к свежему production-снимку показаны в changes.patch. manifest.json закрепляет исходные/новые SHA и SHA установщика. Перед установкой: штатная native-консоль нужного сервера, свободная и собственная ancestor flock, неизменённые текущие образы, выключенный legacy sync и действующая managed policy. Stage загружает только публичный код из полного commit SHA. Prepare создаёт свежую BASE и точные защищённые backup. Apply однократный, с CAS до замены каждого файла, метаданными и atomic rename. Inspect независимо перечитывает файлы и проверяет сохранность остальной статики/окружения/прайса. Контейнеры и базы не меняются и не перезапускаются.

При несовпадении остановиться и прочитать реальное состояние, не повторять apply. Для возврата нужны собственная lease, свежая проверка окружения, exact backup и CAS совпадения текущего файла с этим кандидатом; возвращать только эти три файла. Старые полные HTML, Compose и установщики не применять.

Spec-lite: ограниченное исправление интерфейса поиска и подписей с существующей моделью publicCategories/publicKey; без новых API, прав, миграций или изменения бизнес-данных. Поручение владельца27.10.2026: названия должны совпадать с сайтом и сразу показывать, где находятся товары.
