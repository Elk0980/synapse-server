# Palitra: тестовый просмотр в Telegram

Изолированная демонстрация интерфейса владельца, администратора и покупателя. Все клиенты и заказы вымышлены. Реальные Telegram/Instagram, CRM, почта и платежи выключены. Переключение роли доступно только в этом демо.

Каждая браузерная сессия получает отдельную SQLite-базу в памяти. Перезапуск процесса сбрасывает примеры; приложение не предназначено для хранения настоящих обращений. Telegram SDK используется только для оформления окна, данные авторизации Telegram не считываются.

## Запуск

Нужен Node.js 24 со встроенным `node:sqlite`. Сборка и внешние зависимости не требуются. Запускаемый файл — `production-host.cjs`; служебные npm-команды исходного пакета в этот runtime-пакет не входят.

Перед запуском задать:

- `PALITRA_PREVIEW_PORT`: свободный внутренний порт, например 8799; порт локального просмотра 8789 зарезервирован.
- `PREVIEW_ORIGINS`: точный HTTPS origin без завершающей косой черты.
- `PALITRA_DRAFT_ORIGIN`: точный HTTPS origin тестового черновика. Если не задан, связь с формами выключена.

Слушатель работает только на `127.0.0.1`; внешний доступ предоставляет HTTPS reverse proxy в том же сетевом пространстве. Изменяющие API-запросы требуют точного Origin. Код можно монтировать только для чтения, запускать пользователем `node`; токены и рабочие базы подключать нельзя.

## Проверка и откат

Проверить `/api/health`, отсутствие активных транспортов, открытие кнопки в Telegram, тестовую запись и сохранение после обновления, изоляцию двух сессий. Отсутствующий или чужой Origin должен давать 403. Пути вне статического списка — 404.

Для отката остановить только отдельный процесс демо и убрать только его HTTPS-маршрут из сохранённой версии конфигурации. Основной сайт и рабочие сервисы не являются частью пакета. При пересоздании контейнера reverse proxy пересоздать и демо, если оно разделяет его сетевое пространство.

## Парный тест с черновиком

Кнопка «Проверить с черновиком» создаёт чистый тест без примеров. «Открыть черновик» связывает один браузер покупателя с этой тестовой командой. Форма подбора появляется в «Обращениях», корзина — в «Заказах». Покупатель видит этапы и согласование фото на странице «Мои тестовые заказы». Для обновления нажать «Обновить»; уведомления не отправляются.

Это временная база в памяти: максимум 6 часов, сброс после часа простоя или перезапуска. Реальных клиентов здесь хранить нельзя. Прайс — публичный снимок для демонстрации, не подключение к рабочему прайсу.

На черновике выделяется только `/_palitra_test/*`, без изменения обычного `/api/orders`. Мост `public/draft-bridge.js` подключается перед общим storefront, а охрана формы допускает отправку только при подтверждённом активном тесте. Обычный режим черновика остаётся закрытым для заявок. Полный свежий BASE storefront необходимо сохранить до изменения.

`deploy-caddy-pair.py` — помощник для уже согласованной консоли: `stage` сохраняет свежую BASE и готовит два точечных маршрута (один draft host/prefix и существующий preview). Перед `apply` оператор отдельно проверяет конфигурацию штатным Caddy. `apply` и `revert` требуют точного SHA текущего файла, отказываются при чужой версии и сохраняют inode bind-mounted файла. Не использовать без сверки владельца общего ресурса.

Проверено: 24 проверки обработчика, 17 проверок двухсторонней связи/штатной формы/изоляции/повторов и 3 проверки границ Caddy-патча. В Chrome лично пройдены нативная форма, каталог, корзина и обе стороны одного заказа. Физический Safari и мобильный Telegram требуют отдельного просмотра.
