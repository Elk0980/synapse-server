# Palitra: тестовый просмотр в Telegram

Изолированная демонстрация интерфейса владельца, администратора и покупателя. Все клиенты и заказы вымышлены. Реальные Telegram/Instagram, CRM, почта и платежи выключены. Переключение роли доступно только в этом демо.

Каждая браузерная сессия получает отдельную SQLite-базу в памяти. Перезапуск процесса сбрасывает примеры; приложение не предназначено для хранения настоящих обращений. Telegram SDK используется только для оформления окна, данные авторизации Telegram не считываются.

## Запуск

Нужен Node.js 24 со встроенным `node:sqlite`. Сборка и внешние зависимости не требуются. Запускаемый файл — `production-host.cjs`; служебные npm-команды исходного пакета в этот runtime-пакет не входят.

Перед запуском задать:

- `PALITRA_PREVIEW_PORT`: свободный внутренний порт, например 8799; порт локального просмотра 8789 зарезервирован.
- `PREVIEW_ORIGINS`: точный HTTPS origin без завершающей косой черты.

Слушатель работает только на `127.0.0.1`; внешний доступ предоставляет HTTPS reverse proxy в том же сетевом пространстве. Изменяющие API-запросы требуют точного Origin. Код можно монтировать только для чтения, запускать пользователем `node`; токены и рабочие базы подключать нельзя.

## Проверка и откат

Проверить `/api/health`, отсутствие активных транспортов, открытие кнопки в Telegram, тестовую запись и сохранение после обновления, изоляцию двух сессий. Отсутствующий или чужой Origin должен давать 403. Пути вне статического списка — 404.

Для отката остановить только отдельный процесс демо и убрать только его HTTPS-маршрут из сохранённой версии конфигурации. Основной сайт и рабочие сервисы не являются частью пакета. При пересоздании контейнера reverse proxy пересоздать и демо, если оно разделяет его сетевое пространство.

Проверка исходной версии: 21 проверка изолированного обработчика пройдена; основные исходники UI также прошли 205 проверок. Физический Safari и мобильный Telegram требуют отдельного просмотра.
