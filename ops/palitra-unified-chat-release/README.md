# Palitra: единый чат сайта и Telegram

Пакет проверенного локального кода. **На сервере новый чат и загрузка файлов ещё не установлены.** Исправление добавления товара при переходе к оформлению уже опубликовано отдельно; Main/draft — версия 257, общий прайс — 57.

## Результат для пользователя

- После принятой заявки покупатель открывает свою переписку на сайте. Telegram можно подключить к этой же истории; клиент сам нажимает «Начать» в боте.
- Менеджер видит заявки, переписку, товары и редактор сайта в существующем рабочем месте Synapse. От заявки открывается только действительно связанная переписка.
- Покупатель и менеджер отправляют текст и один файл до 20 МиБ. Подготовка файла блокирует преждевременную отправку подписи без вложения. Черновик сохраняется при обновлении и ошибках.
- Telegram использует прежний единственный обработчик и очередь. Подтверждённые части сообщения не повторяются; неизвестный исход отправки не выдаётся за успех.

## Exact-byte состав

`source-manifest.json` задаёт ровно 16 файлов: content 11, существующий worker 1, кабинет 3, управляемый `assets/order.js` 1. `approved_finished:true` означает личную локальную приёмку кода Root; публикацию и реальные доставки это не подтверждает. В payload нет тестов, журналов, конфигурации секретов или клиентских данных. Атрибуты Git сохраняют точные байты.

`build/assemble.py` создаёт только локальный выпуск с двумя Dockerfile: COPY 11 файлов в content и COPY одного worker в отдельный образ. Нужны независимые Root-подтверждения свежих content, worker и static BASE; полный worker image SHA передаётся отдельно через `--expected-worker-image`. Шаблоны BASE имеют approval=false и не пригодны для установки. Сборщик не запускает Docker, не пишет БД и не меняет сервер.

Прежний static installer используется по фиксированному SHA. У существующих worker, static и managed файлов допускается только ненулевой фактический BASE. Прайс, фотографии, авторизация и прежние заказы не являются payload-целями. При изменении native BASE выпуск останавливается до нового ревью.

## Локальная проверка

Node.js 24+, установленный Playwright и Chrome. При необходимости задать `PALITRA_PLAYWRIGHT` путём к установленному модулю и `PALITRA_CHROME` путём к браузеру:

```text
node ops/palitra-unified-chat-release/test/run-local-tests.cjs
python -B ops/palitra-unified-chat-release/build/test_assemble.py
```

Первый стенд проверяет точные payload-байты и запускает 24 сценария загрузки, настоящего worker с локальной подменой Telegram и интерфейса. Все запросы перехватываются, профиль пользователя не используется; собственные временные файлы и браузерные контексты закрываются. Второй стенд проверяет 13 методов сборки и отказов. Дополнительно Root принял локальные проверки общей истории, повторов, редактирования, черновиков, фокуса и воспроизведения медиа. Пересекающиеся повторные прогоны не складываются в число уникальных проверок.

## Порядок установки и отката

1. Подтвердить исключительное окно общего сервера; заново сверить версии, BASE, оба образа, единственный worker и сохранность его квитанций/файлов.
2. Установить backend при закрытых `PALITRA_CUSTOMER_CHAT_ENABLED` и `PALITRA_WEB_UPLOADS_ENABLED`; проверить добавочные таблицы и защищённые маршруты. Существующий `PALITRA_CHECKOUT_ENABLED=true` сохранить; CRM и clientBotOrders не включать.
3. Обновить единственный совместимый worker с сохранением журналов частей и ACK; подтвердить его работоспособность.
4. Последними установить кабинет и managed order штатным owner/CAS способом, включить подтверждённые возможности чата; проверить повторное чтение и Main/draft.
5. Проверить реальный путь покупатель → заявка → чат → ответ менеджера и обе стороны файлов. Реальные служебные заявки/сообщения требуют отдельного согласованного контрольного сценария. Физический Safari и Telegram WebView проверяются отдельно.

Откат сначала закрывает новые отправки. История, новые заказы, файлы, квитанции и неизвестные исходы сохраняются; полное восстановление старой БД поверх новых данных запрещено. Старому несовместимому worker нельзя выдавать файловые задания.
