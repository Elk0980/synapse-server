# Навыки Agent Skills в серверном Хью

Навык — это markdown-инструкция «как выполнять работу такого типа», написанная в формате
Agent Skills (agentskills.io): файл `SKILL.md` с короткой шапкой `name`/`description`
и, при необходимости, несколько справочников рядом.

Сервер подбирает подходящий навык по типу задания и добавляет его текст в системную часть
запроса **до обращения к модели**. Поэтому одни и те же инструкции получает и основной
рантайм, и любой резервный провайдер: оба читают один собранный запрос.

**Это подача текста через обычный API, а не «родные навыки» какой-либо модели.** Никаких
особых возможностей конкретного провайдера здесь не используется и не подразумевается.

## Состояние включения

| Что | Состояние |
| --- | --- |
| Загрузчик `ops/content/agent-skills.js` | реализован, покрыт тестами |
| Подключение к сборке запроса `ops/content/project-chat.js` | сделано, проверено интеграционным тестом |
| Каталог в образе (`COPY skills ./skills`) | добавлен в `ops/content/Dockerfile` |
| Навыки по умолчанию | **включены**; выключаются `HUGH_SKILLS=off` |
| Встроенные навыки | один: `synapse-content-system` версии 1.0.0 |
| Развёрнуто на сервере | **нет** — этого кода на сервере пока нет |

Владелец видит состояние в разделе Хью: идентификаторы, версии и замечания.
Содержание навыка наружу не отдаётся.

## Что навык делает и чего не делает

Навык **добавляет текст инструкции** в запрос. Он:

- **не выдаёт доступов и не меняет права**;
- **не подтверждает согласование** и не разрешает публикацию;
- **не меняет бюджет** и не влияет на учёт расходов;
- **ничего не исполняет**: скрипты рядом с навыком не запускаются, ссылки не загружаются,
  в сеть загрузчик не ходит вовсе — он умеет только читать файлы;
- **не является сообщением участника**: текст навыка подаётся как порядок работы,
  и базовые правила Хью остаются выше него.

Проверки прав, согласований и расходов живут в отдельных модулях и про навыки ничего не знают.

## Границы чтения

- Читается только то, что перечислено в `ops/content/skills/catalog.json`. Каталог
  не сканирует папки, поэтому подброшенная директория навыком не становится.
- Только файлы `.md` и только внутри корня навыков.
- Путь проверяется до обращения к диску: абсолютные пути, `..`, `.`, пустые сегменты,
  разделители Windows и нулевые байты отвергаются.
- Итоговый путь сверяется с реальным (`realpath`). Это отсекает символическую ссылку
  и на сам файл, и в любом промежуточном каталоге.
- Предел на файл — 32 КБ, предел на блок в запросе — `HUGH_SKILLS_MAX_BYTES` (по умолчанию
  6000 байт). Превышение обрезается с честной пометкой, а не молча.
- Справочник подключается только когда задание действительно про него: лишний текст
  в каждый запрос не уходит.

## Выбор навыка

Выбор детерминированный, без обращения к модели: слова задания сравниваются со списком
триггеров записи каталога. Совпадение считается по словам, а не по подстроке — «пост»
не срабатывает на «поставке». Триггер, оканчивающийся на `*`, сопоставляется по началу слова.

Нужно не менее `threshold` разных совпадений (по умолчанию два). Одного слова мало:
обычный разговор системную часть запроса не раздувает.

## Настройки окружения

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `HUGH_SKILLS` | пусто | Пусто — навыки подключены. `off` — выключены целиком. |
| `HUGH_SKILLS_MAX_BYTES` | 6000 | Предел размера блока инструкций в запросе, байты. Неверное значение возвращает к умолчанию и попадает в замечания. |

Обе переменные проброшены в сервис `content` в `docker-compose.yml`.

## Как добавить новый доверенный навык

1. Создать каталог `ops/content/skills/<идентификатор>/` и в нём `SKILL.md` с шапкой:

   ```
   ---
   name: Короткое название
   description: "Когда применять и когда не применять."
   ---
   ```

2. Написать **общие инструкции**. Личные имена, коммерческие условия, данные клиентов,
   исходники курсов и материалы конкретных компаний в навык не попадают: репозиторий
   публичный, а навык уходит в запрос по всем проектам.
3. Справочники положить в `<идентификатор>/references/*.md` — по одному на тему,
   а не целиком чужой материал.
4. Добавить запись в `ops/content/skills/catalog.json`:

   ```json
   {
     "id": "идентификатор",
     "version": "1.0.0",
     "dir": "идентификатор",
     "entry": "SKILL.md",
     "threshold": 2,
     "triggers": ["слово", "основа*"],
     "references": [{ "file": "references/тема.md", "triggers": ["слово"] }]
   }
   ```

   Версия задаётся явно и поднимается при каждом изменении текста: по ней в журнале
   видно, какая редакция инструкции применялась.
5. Поднять `version` самого каталога.
6. Прогнать `node --test ops/content/agent-skills.test.js ops/content/agent-skills-runtime.test.js`.
   Тест каталога проверяет, что все перечисленные файлы существуют, идентификатор и версия
   заданы по форме, а `COPY skills` остался в `Dockerfile`.

**Сторонние навыки массово не ставятся.** Каждый навык добавляется отдельным решением
и проходит то же ревью, что и код. Общие приёмы работы с документами и PDF в системе
уже есть — дублировать их навыком не нужно.

## Журнал

В журнал попадают только идентификатор и версия подключённого навыка. Содержание инструкции
не логируется и в состоянии раздела Хью не показывается.

## Чего в этой работе нет

- Серверных досок заданий для агентов и автоматического исполнения сторонних скриптов —
  это вне области; загрузчик умеет только читать markdown.
- Загрузки навыков из сети и установки навыков во время работы.
- Изменения прав, согласований и бюджета.

## Проверка

```
node --test ops/content/agent-skills.test.js ops/content/agent-skills-runtime.test.js
```

Покрыто: выбор навыка по контентному заданию и отказ на нецелевых задачах, порог в два
совпадения и отсутствие срабатывания «пост» на «поставке», подключение справочника только
по теме, отказ на выходе за корень, абсолютном пути, не-markdown и символической ссылке
наружу, предел размера с честной пометкой, выключатель и отсутствующий каталог, журнал
без содержания, отсутствие личных имён и коммерческих условий во встроенном навыке,
наличие каталога в образе, попадание инструкций в реальный запрос, отдельный контекст
каждой компании и сохранность маршрута ответа при сломанном загрузчике.
