# Публикация, обращение и учёт оплат

Журнал относится к существующей заявке и её компании. Это запись фактов администратором,
а не проведение платежей или автоматическая банковская сверка.

- `GET /studio-journey/:leadId/commerce?companyCode=...` — история, текущая привязка публикации, оплаты и итоги отдельно по валютам.
- `POST .../commerce/publication` — `revision`, `requestId`, `postId`, `evidence`. Допустима только публикация той же компании со статусом published или квитанцией. `postId: null` снимает ошибочную привязку с обязательным основанием; история сохраняется.
- `POST .../commerce/payments` — `revision`, `requestId`, `type` (received/refund), `amount`, `currency`, `reference`, `evidence`, `occurredAt` (UTC), для возврата `refundOf` (ID исходного события оплаты).

Права прежние: crm.view/crm.edit, доверенная личность, область компании; HTTP-прокси
проверяет сессию и CSRF. После чтения тела право проверяется повторно. Новых прав нет.

Суммы хранятся целым числом сотых единиц валюты. Частичные возвраты не могут превышать
исходную оплату и относятся к той же заявке и валюте. Номер платежа уникален внутри
компании, в том числе между заявками. Повтор requestId с теми же данными безопасен;
подмена суммы/заявки возвращает конфликт. Изменение версии требует обновления карточки.
Платёж и его уникальная ссылка сохраняются атомарно.

Старые sale_amount и отметки покупки абонемента не прибавляются к журналу. Иначе одна
оплата могла бы учитываться дважды. Незаполненный журнал означает отсутствие записей,
а не доказательство отсутствия фактических оплат. Привязка публикации — явная отметка
с основанием, не автоматически доказанная причинность по произвольной UTM-метке.

В карточке визита раздел «Источник обращения и оплаты» загружает журнал по запросу.
Редактор может выбрать подтверждённую публикацию, записать оплату или частичный возврат;
наблюдатель видит историю. Повтор отправки тех же данных после ошибки сохраняет requestId.
Историю можно перечитать без записи. Поздний ответ после смены компании отбрасывается.

Сводка пути клиента содержит таблицу по публикациям для той же когорты обращений и
фильтра источника. Запись/визит считаются один раз на обращение, оплаты за всё время
этих обращений берутся только из журнала. «Оплачивали» включает последующие возвраты;
чистая сумма показана отдельно для каждой валюты. Непривязанные обращения видны
отдельной строкой. Период сводки — время появления обращений, не бухгалтерский период.

Автоматический сбор переходов, импорт банковских/кассовых квитанций и привязка отдельных
заказов не реализованы этим этапом. Рабочие платежи тестами не создаются. Ошибочную
денежную запись пока нельзя аннулировать в интерфейсе; возврат используют только для
действительно состоявшегося возврата, не как замену исправления ошибки.
