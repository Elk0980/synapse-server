# Координация существующих задач

Владелец открывает «Задачи → Координация проектов». По умолчанию показана выбранная компания;
«Все проекты» включает общий обзор. Карточки используют ID существующих задач CRM.
Новая задача создаётся в обычном списке, отдельного дублирующего реестра нет.

Карточка содержит модуль, постоянный ID и отображаемое название ответственного чата,
исполнителя, проверенную модель и дату проверки, область работ, критерий готовности,
результат, блокер и следующий шаг. Компания и обычный статус берутся из исходной задачи.

«Код готов», «Подключено», «Проверено» и «Принято» независимы. Подтверждение либо
исключение этапа требует основания и даты. Готовый код сам по себе не отмечает запуск
или приёмку. Сохранение использует revision; конфликт возвращает 409 без потери
предыдущего результата. История версий неизменяема и хранит автора проверки.

## Границы

Доступ только владельцу: проверка и в прокси кабинета, и в CRM. Обычные маршруты
задач не возвращают внутреннюю координацию клиентам. Новых прав и аккаунтов нет.

Это ручной учёт фактов. Он не подтверждает активность процесса, не запускает чаты,
не отправляет сообщения и пока не захватывает общие ресурсы. Подключение исполнителей,
аренда ресурсов и проверка устаревших запусков остаются отдельными этапами реализации.
Ссылку на результат и его проверку вносит владелец; наличие текста не является
автоматической проверкой внешнего артефакта.

## API

- GET `/coordination/tasks?companyCode=...&limit=100&offset=0` — обзор; компания необязательна для владельца.
- GET `/coordination/tasks/:id` — карточка существующей неудалённой задачи.
- PUT `/coordination/tasks/:id` — полная карточка `{revision,data}`.

Браузер использует существующий `/content/crm` и CSRF; внутренний API — существующий
ключ CRM и проверенную identity владельца. Прямое API без identity владельца отклоняется.
Удаление CRM-задачи скрывает карточку; история не удаляется.

независимость этапов и отсутствие скрытой автоматической приёмки.
