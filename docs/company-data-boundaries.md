# Компании, системные настройки и участники сделки

Решение владельца 16.09.2026: во всех разделах должно быть видно, к какой компании относятся сведения. Клиенты студии не являются автоматически участниками договора между Synapse и собственником студии.

## Области данных

| Раздел | Владелец данных |
| --- | --- |
| Главная, заявки, контакты, CRM-компании, реквизиты, задачи, чат, Хью | Выбранная рабочая компания; компания-клиент внутри CRM остаётся отдельной сущностью |
| Сделки, файлы, счета, сметы, участники, критерии и оформление воронки | Рабочая компания и конкретная сделка |
| Аналитика и рекламная статистика | Выбранная компания; старые расходы без компании не распределяются автоматически |
| Сайты и ссылки редакторов | Выбранная компания; фильтр сайтов переключает общий контекст |
| Актуальность, автопостинг, рассылки | Выбранная компания; незавершённые модули не изображают подключение |
| Финансовые операции | Выбранная компания; план отдельно от факта |
| Каталог модулей и пакетов | Synapse Бизнес; его предложения не предлагаются в сделках клиентской базы студий |
| Получатель уведомлений и очередь | Выбранная компания, `/company-email?companyCode=...` |
| SMTP и источники Хью | Явно общий раздел «Настройки системы», только владелец |
| Учётные записи / доступы | Управление всей системой, с указанием назначенных компаний |
| Личный аккаунт и настройки меню | Пользователь |
| Помощь с товарными знаками | Общая справочная инструкция, не карточка клиентского проекта |

Общий контекст показан над всеми разделами; системная область выделена другим цветом. Переключение компании закрывает открытые диалоги, убирает ID карточки из маршрута, перезагружает активный модуль. CRM-запросы получают выбранную компанию по умолчанию; устаревший ответ предыдущего проекта не возвращается в модуль. Сервер отдельно проверяет принадлежность сущностей и назначенные права.

## Почта

Существующая зашифрованная SMTP-конфигурация сохраняется. Таблица `company_email_recipients` хранит отдельные адреса; до первого изменения ALVI/Авокадо читаются прежние адреса из конфигурации. Пустой адрес — явное отключение, а не повод использовать адрес другой компании. Старый общий получатель относится только к Synapse. Новые компании требуют собственного адреса. Проверка настроек и получателей не отправляет писем.

## Представители и клиенты

`contact_companies` исторически одновременно использовалась для принадлежности клиентской базе и связи человека с организацией. Поэтому она не определяет участие в сделке.

`deal_participants` хранит явно назначенных людей, роль и сторону: клиент либо наша команда. Список и условие перехода «контакт» используют эту таблицу. Прежние клиентские связи не копируются в участников и не удаляются. В старых сделках нужно назначить представителя; система не угадывает его по имени. Создание сделки из конкретного контакта передаёт его ID и назначает участником. Новый представитель создаётся вместе с членством в одной транзакции. Удаление участника из сделки сохраняет карточку контакта в CRM.

Карточка CRM-компании в базе Synapse показывает только контакты, доступные в этой базе, а не всех клиентов студии. Представитель может участвовать в нескольких сделках явно.

## Воронки

Исходная схема остаётся шаблоном. Настройка сделки сохраняет название, порядок, цвета, инструкции и критерии в `deal_company_pipelines` / `deal_stage_rules` для рабочей компании. Она не переименовывает этапы соседней компании. Используемый сделкой этап удалить нельзя. Успешное заключение по-прежнему требует договора и чека либо зафиксированного исключения владельца.

## Проверка

Проверки API покрывают разграничение компаний, почту без SMTP-отправки, изоляцию воронок, участников и сохранность исходных контактов. DOM-проверки покрывают смену компании при незавершённом запросе, отдельные адреса и недоступность каталога Synapse в другой компании. Интерфейс проверяется на ПК и ширине 390 px на синтетических данных, затем читается опубликованная версия.
