# Медиа-наставник: технический чеклист пилота

Три **раздельных** проекта. Контекст не смешивается и брифы не копируются между ними:
у каждой компании свой бриф, свой план, своё согласование, свои черновики и свои материалы.
Скопировать чужой бриф «для скорости» нельзя — это разные компании с разными фактами.

| Проект | Код компании | Роль |
|---|---|---|
| АЛВИ | `alvi` | пилот |
| Авокадо | `avokado` | пилот |
| Палитра | `palitra-love` | подключение |

Документ технический. Целей, аудиторий, продуктов и прочих сведений конкретных компаний здесь
**нет и быть не должно** — они живут в ЛК каждой компании. Здесь только перечень проверок.

Обозначения: **ПОДТВЕРЖДЕНО КОДОМ** — есть автоматический тест; **НЕ ПРОВЕРЕНО** — требует
живой проверки в рабочей системе, автоматическим тестом не подтверждается.

## Как проверять

Раздел ЛК: «Продвижение» → «Бриф и план» (`#media-mentor`), состояние внедрения —
«Медиа-наставник» (`#media-mentor-rollout`). Для каждого шага компания выбирается
переключателем проекта; проверка одного проекта не засчитывается за другой.

## Чеклист по каждому проекту

Один и тот же список проходится отдельно для `alvi`, `avokado` и `palitra-love`.

### 1. Бриф: цель, аудитория, продукт

- [ ] Раздел открывается у пользователя компании с правом «Автопостинг: просмотр» — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] Цель, продукт и аудитория заполнены **своими** словами этой компании — **НЕ ПРОВЕРЕНО**
- [ ] Боли клиента перечислены — **НЕ ПРОВЕРЕНО**
- [ ] У каждого подтверждённого факта назван источник (без источника факт не сохраняется) — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] Исходники описаны словами: название, тип, заметка — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] Площадки компании отмечены — **НЕ ПРОВЕРЕНО**
- [ ] В брифе нет сведений другой компании — **НЕ ПРОВЕРЕНО** (отсутствие смешения в коде — **ПОДТВЕРЖДЕНО КОДОМ**)

### 2. План на 7–14 дней

- [ ] Окно плана от 7 до 14 дней подряд, дни по возрастанию даты — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] На дату не больше трёх материалов — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] Площадка каждого дня выбрана в брифе этой компании — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] Исходник дня существует в брифе этой компании — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] У каждого дня заполнена тема, тема не длиннее 200 символов (иначе перенос откажет) — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] План отражает реальные возможности компании по съёмке — **НЕ ПРОВЕРЕНО**

### 3. Утверждение плана

- [ ] Решение принимает владелец кабинета, имя решившего записано — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] Согласована **конкретная версия** плана вместе с версией брифа — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] Отклонение требует комментария — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] После правки брифа план возвращается на пересогласование — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] Владелец компании понимает: это решение по тексту плана, **не** разрешение публиковать — **НЕ ПРОВЕРЕНО**

### 4. Материал

- [ ] Перенос согласованной версии создал черновики автопостинга — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] У задания видно состояние «Материал: не добавлен / добавлен» — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] Файл загружается существующим приёмом материалов автопостинга своей компании — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] Описание исходника из брифа **не** подставлено как загруженный файл — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] Клиент реально прислал материалы по заданиям — **НЕ ПРОВЕРЕНО**
- [ ] Материал соответствует заданию дня — **НЕ ПРОВЕРЕНО** (автоматически не проверяется)

### 5. Карточка публикации

- [ ] Карточка создана в статусе «черновик», без времени и каналов — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] В карточке виден указатель на версию плана и брифа и на исходник — **ПОДТВЕРЖДЕНО КОДОМ**
- [ ] Текст поста написан человеком — **НЕ ПРОВЕРЕНО** (перенос текст не создаёт)
- [ ] Подписи под площадки заполнены — **НЕ ПРОВЕРЕНО**
- [ ] Карточка одобрена владельцем в разделе автопостинга — **НЕ ПРОВЕРЕНО** (это отдельное согласование, не согласование плана)

### 6. Onlypult и каналы

- [ ] Площадка подключена в «Автопостинг → Подключения» этой компании — **НЕ ПРОВЕРЕНО**
- [ ] Для Onlypult сохранён ключ вида `op_<64 hex>` и выбран профиль — **НЕ ПРОВЕРЕНО**
- [ ] Живая проверка канала прошла — **НЕ ПРОВЕРЕНО**
- [ ] Канал выбран в карточке вручную — **НЕ ПРОВЕРЕНО** (перенос каналы не выбирает — **ПОДТВЕРЖДЕНО КОДОМ**)

### 7. Результат

- [ ] Публикация состоялась и ссылка на пост проверена — **НЕ ПРОВЕРЕНО**
- [ ] Показатели площадки собраны — **НЕ ПРОВЕРЕНО**
- [ ] Результат сопоставлен с днём и ролью плана — **НЕ РЕАЛИЗОВАНО** (связи публикации с днём плана в коде нет)

## Что обязательно должно быть настроено до пилота

Существующие настройки, без которых путь обрывается. Ни одна из них не проверена автоматически —
это настройки живой системы.

1. Компания заведена в CRM и доступна в ЛК (`alvi`, `avokado`, `palitra-love` есть в справочнике
   компаний сервиса контента) — **НЕ ПРОВЕРЕНО** для каждой конкретной установки.
2. У сотрудника компании есть права `company-information.view` и `autoposting.view` для чтения,
   плюс `autoposting.edit` для правки брифа, плана и загрузки материалов. Право
   `autoposting.view` по правилам доступа требует `company-information.view` — **НЕ ПРОВЕРЕНО**.
3. Решение по плану принимает учётная запись с ролью владельца — **НЕ ПРОВЕРЕНО**.
4. Заполнены эталонные данные компании (раздел «Актуальность»): от них берётся часовой пояс
   черновика и версия данных — **НЕ ПРОВЕРЕНО**.
5. Настроен приём материалов: каталог `ASSETS_DIR` доступен сервису контента на запись —
   **НЕ ПРОВЕРЕНО**. Принимаются JPEG, PNG, WebP, MP4, WebM; подпись файла проверяется.
   Лимит фото 10 МБ фиксирован в коде, лимит видео по умолчанию 60 МБ и меняется переменной
   `MAX_PUBLISHING_VIDEO_BYTES`. Адрес выдачи материалов задан в коде константой, настройкой
   его не переопределить — при смене домена потребуется правка кода.
6. Для публикации — подключённый канал площадки в автопостинге (Telegram/VK напрямую либо
   Onlypult с ключом и профилем) — **НЕ ПРОВЕРЕНО**.

## Известные пробелы

Чего в коде нет; в пилоте это делается руками или не делается вовсе.

- **Генерация по брифу.** Все тексты вводит человек, обращений к моделям нет.
- **Приём материалов от клиента как отдельный процесс.** Файл загружает сотрудник в карточку;
  напоминаний клиенту, сроков и статусов «ожидается / прислан» по заданию нет.
- **Монтаж.** Постановки задачи, статусов и приёма готового файла нет.
- **Связь плана с карточкой при согласовании публикации.** Одобрение карточки — отдельный
  механизм автопостинга; решение по плану на карточки не переносится и не должно.
- **Выбор канала по площадке дня.** Перенос каналы не заполняет, канал выбирается вручную.
- **Сбор результата по плану.** Показатели площадок собираются отдельно и с днями плана
  не связаны.

Подробнее: [что готово и что осталось до пилота](media-mentor-pilot-roadmap.md).

## Границы пилота

Пилот **не даёт** права публиковать клиентам несогласованный контент. Порядок прежний:
текст пишет человек, карточку одобряет владелец в автопостинге, и только после этого
она может быть поставлена на отправку. Перенос плана и загрузка материала ничего
не публикуют и в очередь не ставят.

## Проверка утверждений «ПОДТВЕРЖДЕНО КОДОМ»

```
node --test ops/crm/media-mentor.test.js ops/crm/media-mentor-rollout.test.js \
            ops/crm/media-mentor-http.test.js ops/crm/media-mentor-transfer.test.js \
            ops/crm/media-mentor-pilot.test.js
node --test ops/content/media-mentor-proxy.test.js ops/content/media-mentor-rollout-proxy.test.js
NODE_PATH=<каталог с jsdom> node --test sites/synapse/cabinet/*.test.cjs
```

`ops/crm/media-mentor-pilot.test.js` — синтетический сценарий трёх проектов: бриф, план,
согласование, перенос, материал; проверяется, что ни один проект не видит метки, исходника,
файла и карточки другого, и что при этом ничего не публикуется. Данные в нём выдуманные
и техничные: настоящие сведения компаний в тесты не переносятся.
