# Актуальность и автопостинг

## Как пользоваться

1. Откройте **Актуальность** в ЛК и выберите компанию. Существующие основные сведения берутся из CRM.
2. Заполните контакты, адрес, часы работы, услуги, акции и материалы. Сохранение подтверждает эту версию. Пустое ранее заполненное поле означает намеренное удаление.
3. Кнопка **Проверить актуальность** читает открытые страницы по сохранённым ссылкам, начиная с 2ГИС. Показывает совпадения и расхождения доступных контактов. Не меняет данные владельца и внешние площадки.
4. В **Автопостинге** добавьте текст и фото, дату, время и площадку. Сохраните черновик и откройте предпросмотр.
5. **Поставить в план** разрешает отправку именно этого материала в выбранное время. Черновики не отправляются. Отмена останавливает ещё не начатые отправки.

Фотографии JPEG, PNG и WebP до 10 МБ загружаются с устройства. Их адреса предназначены для публикаций: файлы доступны по случайной длинной ссылке без входа в ЛК. Каталога всех файлов нет.
Календарь использует часовой пояс компании, а не компьютера. При изменении подтверждённых данных отложенные посты по старой версии переходят в «Нужна проверка».

## Подключение площадок

В «Подключении площадок» сохраните точное место публикации и ключ доступа, затем нажмите **Проверить доступ**. Проверка не отправляет сообщений.

| Площадка | Первая версия подключения |
| --- | --- |
| Telegram | Бот с правом публикации в конкретном канале. Текст до 4096 символов либо до 10 фотографий с подписью до 1024 символов. Личные чаты не поддерживаются. |
| ВКонтакте | Ключ пользователя с правом `wall`, который управляет указанным сообществом. Текст до 15000 символов и одна ссылка как вложение. Загрузка фото на стену VK в этой версии не реализована. |
| 2ГИС, Яндекс Карты, MAX | Реестр площадок и ссылки. Автоматическая публикация на них ещё не подключена. |

Ключи шифруются в SQLite с привязкой к компании и площадке; API не возвращает их в браузер. Изменение подключения требует новой проверки и останавливает задания, подготовленные для прежней версии канала. При замене ключа CRM надо заново ввести ключи площадок.

Очередь проверяется каждые 30 секунд работающим сервисом CRM и после запуска сервера. Успешная отправка сохраняет ссылку и номер поста. При неопределённом сетевом результате автоматической повторной отправки нет: сначала нужно проверить площадку, чтобы не создать дубликат. Частичный результат сохраняется отдельно по каждому каналу.

## Доступ

Владелец платформы видит вкладки. Для других аккаунтов назначаются только их компании и права:

- `company-information.view` / `.edit` — чтение / изменение данных и запуск проверки;
- `autoposting.view` / `.edit` — просмотр / подключение каналов и работа с планом.

Просмотр автопостинга включает чтение данных компании. Назначение прав выполняется через существующее управление аккаунтами; новая версия не выдаёт доступ всем пользователям автоматически.

## Границы текущего агента

Проверка извлекает телефоны, email и доступные структурированные адреса/часы работы из HTML. Она **не подтверждает все сведения компании**, не распознаёт баннеры и не выполняет JavaScript внешней страницы. Недоступная или неполная страница получает соответствующий статус. Сверка цен, состава услуг, изображений, автоматические исправления и расписание мониторинга остаются следующими этапами из [описания агента](company-information-agent.md).

Услуги и акции в эталоне пока не публикуются автоматически в существующие редакторы сайтов и прайса. Их сохранение создаёт версию и отмечает зависимые задания, но не заменяет опубликованный прайс без отдельной интеграции.

## Технические точки

- `GET/PUT /content/crm/company-information?companyCode=...`, `POST .../check`;
- `GET/PUT /content/crm/autoposting/settings?companyCode=...`, `POST .../settings/:id/check`;
- `GET/POST /content/crm/autoposting/posts?companyCode=...`, `PATCH .../posts/:id`, `POST .../posts/:id/schedule|cancel`;
- `POST /content/publishing-assets?companyCode=...` — двоичное тело фото, Content-Type и CSRF;
- изменение профиля/поста и подключения требует текущую `revision`; конфликт возвращает 409;
- существующие поля компании хранятся в `companies`, дополнительные поля — в `company_information`, неизменяемая история — в `company_information_versions`;
- наблюдения и очередь хранятся отдельно от эталона. Статус наблюдения привязан к проверенной версии.

API площадок: [Telegram Bot API](https://core.telegram.org/bots/api), [официальная схема VK wall](https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json).

Тесты отправки используют имитации площадок. Проверки доступа запускают настоящие локальные сервисы и отдельные временные базы. Настоящие посты при разработке не создавались.
