# Сквозная аналитика соцсетей (ТайСабай) — фундамент

Состояние: код и тесты локально (QA). Живой сбор возможен только там, где уже есть разрешённый доступ: Telegram (число подписчиков через бота из подключения) и ВКонтакте (участники и суточная статистика при ключе с правом `stats`). Instagram, TikTok, YouTube и Onlypult Analytics — `missing_access` с точным списком недостающего; чисел без доступа нет.

## Модель данных (CRM, SQLite)
- `social_accounts` — аккаунт площадки компании: `platform` (instagram|tiktok|youtube|vk|telegram), `account_ref` (@имя/ID/club…), `provider` (direct|onlypult|manual), `kind` (organic|paid|mixed|unknown), `timezone` (Asia/Bangkok), `collect_hour`, `revision`. Ключей здесь нет: доступ живёт в подключениях площадок (Автопостинг) или у провайдера.
- `social_snapshots` — снимок метрики за день (`period=day`) или на момент (`period=lifetime`): `metric` из единого словаря (`followers, follower_change, reach, impressions, views, profile_visits, likes, comments, shares, saves, clicks, link_clicks, watch_time_seconds, avg_watch_seconds, retention_percent, posts_published`), `unit`, `source_field` (исходное имя поля площадки), `value` (**null = UNKNOWN, не 0**), `kind`, `completeness`, `provider`, `collected_at`. Ключ уникальности — компания+площадка+аккаунт+день+период+метрика: повторный сбор обновляет, не дублирует.
- `social_posts` / `social_post_metrics` — публикации с `platform_post_id`, `url`, `content_id` (карточка контент-плана) и их метрики по дням.
- `social_collect_runs` — журнал сборов: статус `ok | partial | missing_access | unsupported | failed`, строки, ошибка, список недостающего, `closed` (1 — итог за завершённый день, 0 — обновление текущего).
- Знак значений: `follower_change` может быть отрицательным (отток), остальные метрики — только ≥ 0. Тип агрегации за период задан словарём `AGGREGATION`: `sum` (просмотры, реакции…), `avg` (`retention_percent`, `avg_watch_seconds` — **невзвешенное** среднее суточных значений, каждый день с равным весом; это не общее удержание за период и не средняя длительность по всем просмотрам), `latest` (`followers` — состояние, берётся последний lifetime-снимок).

## Адаптеры (`ops/crm/social-adapters.js`)
Единый контракт `describe()` / `collect()`. `direct`: Telegram `getChatMemberCount` (только подписчики; просмотры постов Bot API не даёт), ВКонтакте `groups.getById` + `stats.get` за реальные границы локального дня аккаунта в его `timezone` (`dayBounds`, с учётом перехода на летнее время; views, reach, likes, comments, shares, прирост/отток подписчиков); Instagram/TikTok/YouTube — `missing_access` (нужны собственные приложения, OAuth владельца и его решение о новых правах). `onlypult` — временный источник: MCP Analytics по OAuth 2.1 с профилями `an_…`, подключение не создано; ВКонтакте/Telegram/YouTube он не покрывает. `manual` — реальные числа из кабинета площадки с датой снятия и источником (не заглушка). Тексты «чего недостаёт» — общие шаблоны без клиентских идентификаторов; аккаунт подставляется из настроек компании (`{account}` → `account_ref`). Ответ провайдера, пришедший после смены аккаунта аналитики (`social_accounts.revision`/`account_ref`) **или** сохранённого подключения площадки (`autoposting_channels`: ревизия токена/цель — отпечаток `connectionRevision` без секрета сравнивается до и после вызова), отбрасывается со статусом `failed`, сбор повторится.

## Маршруты (через content proxy, компания обязательна)
`GET /social-stats?companyCode&from&to` (analytics.view) — сводка: по площадкам (свежесть, статус последнего сбора, недостающее, итоги за период с типом агрегации, последние lifetime-значения, дни, разметка органика/реклама — только по текущему `account_ref`; данные прежних аккаунтов площадки — отдельной группой `history`, в сводку и агрегат не входят), агрегат соцсетей (суммы просмотров/реакций; **уникальный охват = null** с пояснением), атрибуция CRM, журнал сборов. `GET/PUT /social-stats/accounts` (чтение analytics.view, запись — владелец), `POST /social-stats/collect {platform,date?}` (crm.edit), `POST /social-stats/import` (владелец; `capturedAt`, `sourceNote`, `rows[]`, `posts[]`). Все операции проверяют компанию на сервере; CSRF — в прокси.

## Расписание
Раз в 10 минут CRM проверяет включённые аккаунты (`provider ≠ manual`). Итог (`complete`, `closed=1`) собирается только за **завершённый предыдущий** локальный день аккаунта — один раз после `collect_hour`. **Текущий** день собирается как `partial` и обновляется не чаще раза в час (последний сбор перезаписывает значения, строки не дублируются), чтобы вечерняя активность не терялась; на следующий день он собирается заново как итог. Lifetime-снимки (подписчики) датируются **реальным моментом снятия** (сегодняшний локальный день), даже когда собирается итог за вчера — история подписчиков не переписывается задним числом. Запуск в журнале привязан к `account_ref` и ревизии аккаунта: после смены аккаунта или подключения прежний `missing_access` не блокирует новый сбор. Если по аккаунту нет доступа (`missing_access`/`unsupported`), текущий день повторно не запрашивается до следующего дня. Будущая дата не собирается. Ручной запуск — кнопка «Собрать сейчас».

## Атрибуция
Каждое обращение засчитывается **не более одного раза**. Посту — только по однозначной связи: (1) URL поста в `referrer`/`landing_page` — точное совпадение или продолжение через `?`, `#`, `/` (префиксного совпадения `post1` → `post10` нет); (2) метка `utm_content`/`utm_campaign` = `content_id`, если у контента один пост или площадка обращения (`utm_source`, иначе `source`) совпадает ровно с одной площадкой постов этого контента. Один `content_id` на пяти площадках без площадки в обращении — группа `byContent` («по контенту»): считается один раз, ни одному посту не приписывается. Продажи — по `stage='продажа'` и `sale_amount` тех же обращений. Остальное — неизвестная атрибуция, корреляция не объявляется продажей. Отдельно — обращения/продажи по источникам за период.

## Что нужно для живого сбора (не сделано, требует решения владельца)
- Telegram: бот из подключения — администратор канала; `account_ref` = @канал; просмотры постов недоступны без MTProto/канальной статистики.
- ВКонтакте: ключ с правом `stats` в подключении ВКонтакте; `account_ref` = идентификатор сообщества (club…).
- Instagram: Meta-приложение Synapse + App Review (`instagram_basic`, `instagram_manage_insights`) + токен профессионального аккаунта.
- TikTok: приложение TikTok for Developers, аудит, `user.info.stats`, `video.list`, OAuth аккаунта.
- YouTube: проект Google Cloud с YouTube Analytics/Data API, OAuth канала (`yt-analytics.readonly`, `youtube.readonly`).
- Onlypult Analytics: аналитические профили `an_…`, MCP по OAuth 2.1, подтверждённый e-mail; VK/TG/YT им не покрываются.
