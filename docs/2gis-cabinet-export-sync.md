## Общая модель

Спрос площадки → показ компании → анонимная сессия → целевое действие → обращение → запись → состоявшийся визит → оплата → повторная покупка.

Каждый показатель имеет собственную единицу, источник, период, часовой пояс, компанию, филиал и степень доказанности. Нельзя превращать поиски рубрики в клиентов, просмотр телефона — в звонок, открытие чата — в диалог, построение маршрута — в визит.

### Статусы сопоставления

1. **Анонимный интерес**: сессия/событие площадки, без карточки человека.
2. **Потенциальное обращение**: сигнал намерения; может иметь несколько действий. Это не подтверждённая заявка и не уникальный клиент.
3. **Предполагаемая связь**: кандидат на совпадение с обращением/записью, с перечислением оснований и альтернатив.
4. **Подтверждённая связь**: проверяемый общий идентификатор либо явное подтверждение менеджера с основанием. Ручное подтверждение отделять от технического доказательства.
5. **Связь отклонена**: хранить отклонение, чтобы не предлагать повторно без новых данных.

Связи не сливают исходные события безвозвратно. Сохранять источник, автора решения, время, метод, основание и историю отмены. Несколько событий могут относиться к одной записи; нельзя суммировать их как несколько клиентов. Изоляция companyCode обязательна и на сервере, и в интерфейсе.

UTM подтверждает маркированный источник перехода, но сама по себе не доказывает, какая именно анонимная сессия 2ГИС привела к нему. Поисковый запрос ленты нельзя автоматически переносить на запись клиента только по близкому времени. Брендовый поиск может быть последним касанием после рекламы на другой площадке, а не первым источником знакомства.
