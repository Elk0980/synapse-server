# Чат ЛК: как включить ответы Хью и Лео

Решение для задачи доски №229 (specs/229-chat-ai-works). Документ публичный: ключей, адресов
чатов и данных клиентов здесь нет и быть не должно.

## Почему сейчас «Ответ пока недоступен»

Ответы в «Чатах» кабинета (общий чат компании, лог с Хью, личные чаты) пишет
`ops/content/team-chat-answers.js`. Путь один:

```
кабинет → content (team-chat-answers) → POST http://hugh-runtime:8080/reply → codex app-server → подписка ChatGPT
```

Ответ появляется только если сработали все три звена:

| Звено | Что нужно | Где берётся | Если нет |
|---|---|---|---|
| Внутренний ключ | `CHAT_API_KEY` в `.env` сервера (рядом с `docker-compose.yml`) | compose передаёт его в `content`, `chat` и `hugh-runtime` | content даже не обращается к рантайму, `hugh-runtime` не стартует |
| Сервис `hugh-runtime` | собран и запущен (`docker compose build/up hugh-runtime`) | `ops/hugh-runtime`, Codex CLI 0.154.0 закреплён в образе | `/reply` не отвечает |
| Вход в подписку | владелец выполнил вход по коду устройства | `CODEX_HOME=/data/codex` в томе `hugh_runtime_data` | `/reply` → 503 `LOGIN_REQUIRED` |

Модель — та, что разрешена подписке ChatGPT владельца: каталог собирается при сборке образа,
`HUGH_MODEL` только сверяет слаг. **Ключ OpenAI API не нужен**: это вход ChatGPT-аккаунтом.
Резервные провайдеры (`HUGH_FALLBACK_*`, ключи провайдеров в ЛК) обслуживают «Чат проекта»
(`project-chat.js`), а не «Чаты» кабинета. Локальный обработчик Хью на компьютере владельца
(`HUGH_LOCAL_WORKER_*`) «Чаты» тоже не обслуживает — им нужен именно серверный `hugh-runtime`.

Любой сбой любого звена раньше показывался как «Ответ пока недоступен. Вопрос сохранён для
проверки.» Теперь участник видит «Хью (или Лео) передал вопрос команде — ответим здесь», а
вопрос попадает в очередь проверки владельца (кроме личных чатов — там очередь владельцу не видна,
и ответ говорит, что вопрос остался собеседнику).

## Что сделать Владу — один раз

1. **Ключ `CHAT_API_KEY`.** Зайти на сервер и открыть `.env` проекта. Если строка `CHAT_API_KEY=`
   уже есть и не пустая — ничего не менять (её же использует сервис `chat`). Если пустая или
   нет — сгенерировать на самом сервере, например `openssl rand -hex 32`, и вписать
   `CHAT_API_KEY=<значение>`. Значение не пересылать ни в чат, ни в репозиторий, ни агентам.
2. Сказать координатору «ключ на месте» — без значения. Координатор выпускает сервисы (ниже).
3. **Вход в подписку.** Кабинет → «Чат проекта» → «Настройки чата» → блок «Ответы Хью через
   Codex» → «Подключить подписку». Откроется ссылка и код: открыть ссылку, войти своим
   аккаунтом ChatGPT с подпиской, ввести код. Кнопка видна только владельцу.
4. Там же нажать «Проверить» — должно быть «подключено» (`state: connected`).
5. Проверка в «Чатах»: написать в общий чат компании «Хью, что у меня в работе?» и
   «Лео, что снимаем на неделе?». Ответы подписаны «Хью · ИИ» и «Лео · ИИ».

Если на шаге 3 вход не начинается, причина видна в журнале `hugh-runtime`
(`login_start_failed category=…`, см. `ops/hugh-runtime/README.md`, раздел «Почему вход не начался»).

## Что выпускает координатор на сервер

После слияния PR specs/229 и после шага 1:

1. `git pull` на сервере (ветка main).
2. `docker compose build hugh-runtime content crm` — образ рантайма при сборке сам проверяет
   версию Codex и изоляцию инструментов; провал сборки = не выпускать.
3. `docker compose up -d hugh-runtime crm content` (если `CHAT_API_KEY` менялся — также `chat`,
   потому что ключ общий у chat, content и hugh-runtime).
4. Проверить: `docker compose ps hugh-runtime` — работает; `/status` из кабинета (шаг 4 выше)
   показывает `login_required` до входа и `connected` после.
5. После входа владельца — один проверочный вопрос в «Чатах» на служебном тексте.

Ключ в compose не передаётся литералом: только `${CHAT_API_KEY}` из `.env`.

## Что изменено кодом (specs/229)

- Фильтр не отклоняет телефон, email и ссылки, совпадающие с контактами **этой** компании из
  её профиля в CRM (телефон, email, сайт, ссылки `socials`). Чужие контакты, ключи, токены,
  «пароль:» и т. п. режутся как раньше; запрос ссылки (`?token=…`) проверяется отдельно.
- «Лео, …» отвечает Медиа-наставник: инструкция от его имени (`hugh-personas.instruction('leo')`),
  в фактах — бриф, контент-план, материалы и задачи. Бриф виден тем, кому открыт контент-план.
- Запасной ответ — «передал вопрос команде», без слова «ошибка».
- Ожидание одного хода рантайма поднято с 8 до 20 секунд в пределах прежних 24 секунд на вопрос:
  ход Codex на подписке часто дольше 8 секунд.
