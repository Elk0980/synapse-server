# Разработка Synapse по Spec Kit

Версия процесса: 1.0.0. Решение владельца: 30.09.2026.

## Обязательно для всех ИИ-разработчиков

Codex, Claude, Qwen, DeepSeek и любой новый исполнитель используют один процесс независимо от провайдера. Перед изменениями прочитать AGENTS.md, этот документ и `.specify/memory/constitution.md`. Инструкции пользователя и ограничения доступа сохраняют приоритет. Спецификация не разрешает публикацию, новые права, оплату или отправку сообщений.

Новая функция, изменение API, прав, данных или межмодульного поведения:
1. Создать либо актуализировать `specs/<номер-название>/spec.md`: цель, сценарии, FR-требования, проверяемая приёмка, ограничения.
2. Составить `plan.md` с существующими модулями, контрактами, миграциями и проверками. Назначить одного владельца и разрешённые файлы/ресурсы; документ не является серверной блокировкой.
3. Создать `tasks.md`, выполнять ограниченные задачи, фиксировать реальные проверки в `evidence.md`.
4. Проверить соответствие результата требованиям через Spec Kit converge. Не считать галочки доказательствами.
5. В описании PR указать отдельной строкой `Spec: specs/<номер-название>`.

Малая правка без изменения контрактов/прав/данных может использовать сокращённый процесс: цель, границы, проверка в описании PR и отдельная строка `Spec-lite: <конкретное обоснование>`. Разрешение сокращённого пути проверяет ревьюер; автоматическая проверка не умеет оценивать смысл обоснования.

## Исполнители и передача

- Codex: `.agents/skills/speckit-*`, команды `$speckit-specify`, `$speckit-plan`, `$speckit-tasks`, `$speckit-implement`, `$speckit-converge`.
- Claude Code: `.claude/skills/speckit-*`; вход `CLAUDE.md`.
- Qwen Code: `.qwen/commands/speckit.*.md`; вход `QWEN.md`. Название клиента не подтверждает модель.
- DeepSeek и веб-чаты: координатор передаёт результат `python tools/spec-kit/gate.py packet specs/<номер-название>`. Пакет содержит правила, требования, план, задачи и их контрольные суммы. Исполнитель должен назвать версию процесса, задачу, разрешённую область и фактическую модель; координатор проверяет результат. Генерация пакета не означает его доставку или прочтение.
- Активные старые чаты не получают новые инструкции автоматически. Перед следующим заданием загрузить текущий пакет. Не запускать второго автора и не рассылать статусы соседним чатам.
- Клиентские диалоги Хью не получают разработческие команды. Если модель выполняет именно разработку, координатор обязан передать этот процесс независимо от транспортного клиента.

## Проверки и границы гарантии

`python tools/spec-kit/gate.py check` проверяет входы моделей, официальный комплект по контрольным суммам и конституцию. GitHub workflow `spec-kit` выполняет проверку на каждом PR и проверяет ссылку на спецификацию либо обоснование малого изменения. CI проверяет наличие артефактов, не истинность отчёта и не внутреннее мышление модели. Обязательность CI для слияния зависит от настроек защиты ветки; этот PR их не меняет.

Готовность отчёта разделять: реализовано / проверено локально / подключено / проверено в рабочей системе / принято. Не объявлять все модели подключёнными по одному наличию файлов. Непроверенную или недоступную модель обозначать прямо.

## Установка и обновление

Официальные файлы скопированы CLI из GitHub Spec Kit; точная версия в `.specify/upstream.json`, лицензия рядом. Python-скрипты работают на Windows и Linux. Для уже полученного репозитория CLI не требуется для чтения правил, пакета и проверок; для генерации использовать установленный specify-cli той же версии либо навыки агента.

Обновление — отдельная ветка: проверить upstream, установить интеграции codex/claude/qwen, сохранить нашу конституцию и правила, пересмотреть diff и пройти gate. Не запускать принудительную инициализацию поверх незакоммиченных изменений. Другие checkout получают изменения обычным обновлением ветки; не перезаписывать занятые worktree.
