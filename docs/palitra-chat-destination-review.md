# Palitra: адрес канала не равен чату заказа

Выявлено Хью 18.09.2026 около 00:55 Asia/Bangkok в ходе разрешённой проверки Telegram.

## Свежий факт

Поиск Telegram Web по Palitra отображает результат «PalitraLove @palitralovee, 192 subscribers». Это канал. Между тем `ops/content/seed/palitra-price.json` содержит этот адрес в `links.book` и `links.chat`, а публичный сайт называет переход «Написать в Telegram». Ранее данный адрес ошибочно описывался в нашем контентном плане как личный чат; план уже уточнён.

## Следующая задача Claude после сброса лимита

Продолжить существующую сессию и ветку Palitra. Не создавать новый проект и не менять данные других компаний.

1. Проследить получение контактов в CTA каталога, карточках, quiz.js и главной. Прочитать текущую подтверждённую карточку компании при доступе; seed не считать текущим эталоном.
2. Разделить переход в контентный Telegram-канал и обращение к менеджеру. Известный канал не должен называться личным чатом или считаться отправкой заказа.
3. Не угадывать username Дарьи Трафик, не приравнивать его к имени другого участника. Если проверенного адреса получателя нет, использовать существующую форму заявки только после проверки её сохранения; честно показывать состояние доставки менеджеру.
4. Не переписывать CRM или прайс только на основании внешнего поиска. Подготовить минимальный diff для корректного текста/выбора подтверждённого контакта и сообщить, какого конкретного сведения не хватает.
5. Проверить соответствующий сценарий ссылок и формы; не выполнять реальные клиентские отправки и не перезапускать весь набор уже пройденных проверок без причины.

Статус: дефект назначения ссылки выявлен; код сайта в этом heartbeat не менялся. Точный адрес личного приёма заказов пока не подтверждён.

## Новое наблюдение 18.09 около 01:16 — найден опубликованный контакт

Хью открыл сам канал PalitraLove в Telegram Web. В актуальном посте 17.09 14:55:22 (а также 15–16.09) ссылка «Оформить заказ: Телеграмм» имеет адрес **https://t.me/palitra_love**. Переход по ней открыл именно личный чат **Palitra**, статус last seen recently, поле Message, без существующей переписки. Сообщения не отправлялись.

Следовательно, `palitra_love` в quiz.js не следует называть устаревшим только из-за несовпадения с каналом `palitralovee`: это реально опубликованный клиентский контакт. Проверь текущую подтверждённую модель ссылок компании прежде изменения данных. Разделяй канал и личное обращение; не заменяй автоматически рабочий контакт канала/квиза догадкой. Подтверждение публичного чата не устанавливает личность получателя «Дарья Трафик» и не подтверждает его числовой ID или запуск бота для уведомлений.

## Правки по замечаниям Хью (Claude, 18.09.2026, без commit)

Проверено в ЛК Хью: у Palitra подтверждены только название, Подольск и Europe/Moscow; ссылки не
заполнены. CRM/ЛК не менялись; `t.me/palitra_love` — опубликованный контакт заказа Palitra (личный чат
Palitra), не приравнивается к Дарье Трафик; сайт его пока не использует по решению Хью.

- Формулировки: из комментариев `quiz.js` и раздела выше убраны «чужой чат/устаревший адрес».
  Тест `pages.test.cjs` проверяет текущий маршрут и подписи (список назначений
  `TELEGRAM_DESTINATIONS`, квиз → форма), а не объявляет клиентский handle запрещённым.
- `assets/quiz.js`: текст итога точный — «ответы и выбранный вариант подставятся в комментарий
  формы. В форме нужно указать имя, телефон, дату и согласие на обработку данных». Отказ
  хранилища (`saveDraft` → false): переход отменяется (`preventDefault`), в итоге показывается блок
  «Не удалось передать ответы в форму автоматически» с текстом ответов в `<textarea readonly>` и
  ссылкой «Перейти к форме заявки» — ответы не теряются молча.
- Цены квиза: статические `product.price` из конфигураций больше не показываются и не попадают в
  заявку. Цена берётся только из live-прайса (`PalitraPrice.load`) по необязательному
  `product.priceId` (строка прайса как есть); без `priceId`/совпадения — «Цена уточняется»
  (`data-price-known="false"`), в черновике — «цена уточняется». Числовых `0` нет. Сейчас ни у одной
  позиции квиза `priceId` не задан: устойчивых ID в HTML-конфигурациях нет, названия совпадают с
  seed лишь частично, а seed — не эталон ЛК. Назначение `priceId` по текущему прайсу ЛК — за Хью.
- Главная `assets/app.js`: статические `p:` удалены; карточки-примеры показывают «Цена уточняется»
  и примечание «Стоимость подтвердит менеджер по заявке»; необязательный `priceId` подставляет
  live-цену после загрузки прайса (`applyLivePrices`, `data-price-for`). Товары/цены/описания в
  базе и seed не менялись. Версии ассетов `?v=20260918channel2`.

Проверки: `node --test sites/palitra-love/assets/quiz.test.cjs sites/palitra-love/pages.test.cjs
