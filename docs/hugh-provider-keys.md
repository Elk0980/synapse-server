# Защищённый ввод ключей провайдеров Хью

Владелец вводит ключ API в существующем ЛК → **Настройки системы** → «Провайдеры ответов Хью».
Раздел owner-only, запись требует CSRF-токена.

**Это ещё не развёрнуто.** Код лежит в ветке `codex/media-mentor-foundation-20260919`,
коммитов, push и деплоя не было. Пока изменения не выкачены, вставить ключ в ЛК нельзя.

## Как устроена защита

- **Ключ write-only.** Он уходит на сервер и **не возвращается ни одним ответом**: ни в `GET`,
  ни в ответе сохранения. В разметке, журналах, Git и браузерном хранилище его нет. Поле формы
  очищается сразу после отправки. Наружу видно только «ключ задан» и когда задан.
- **Шифрование** повторяет уже работающую схему автопостинга: AES-256-GCM, случайные salt и IV
  на каждую запись, ключ выводится HKDF-SHA256 из внешнего мастер-ключа, AAD привязывает запись
  к пространству имён и имени провайдера. Другой мастер-ключ расшифровать не сможет.
- **Fail-closed.** Без `HUGH_PROVIDER_MASTER_KEY` (минимум 32 символа) хранилище закрыто:
  сохранить ключ нельзя, сохранённые ключи не читаются, в рантайм ничего не уходит,
  а причина названа прямо. Безопасность без мастер-ключа не имитируется.
- **Произвольный адрес запрещён.** Хост обязан входить в список официальных адресов провайдера;
  только `https`, без логина и пароля в адресе, без нестандартного порта, без IP-литерала,
  без параметров запроса. Это отсекает SSRF. Список хостов при необходимости расширяет
  оператор сервера переменной `HUGH_PROVIDER_ALLOWED_HOSTS` — но не пользователь ЛК.
- **Переадресация запрещена.** Запрос уходит с `redirect: 'error'`, а ответ с признаком
  переадресации или кодом 3xx считается отказом. Иначе разрешённый адрес мог бы увести
  запрос с ключом на чужой хост. Адрес перепроверяется по списку **прямо перед сетью**,
  а не только при сохранении, — и в проверке, и в рабочем рантайме ответов.
- **Сохранение ничего не включает и не тратит денег.** Провайдер по умолчанию выключен.
  **Включить можно только после успешной проверки этой же версии соединения.** Смена адреса,
  модели или ключа обесценивает проверку; переключение «включено», цен, лимита и таймаута —
  не обесценивает. «Сохранено» и «проверено» — разные состояния.
- **Проверка соединения — отдельное явное действие** владельца, и это **платное обращение**:
  оно проходит через тот же учёт бюджета, что и обычные ответы. Неизвестная цена при денежной
  границе и исчерпанный бюджет останавливают проверку **до обращения в сеть**.
- **Успехом считается структура ответа,** а не факт `HTTP 200`: нужен непустой `choices`
  с объектом `message`, у которого есть роль и поле `content` допустимого типа. Пустой JSON
  подтверждением не считается. Пустой текст при `max_tokens: 1` допустим и проверке не мешает.
- **Результат привязан к версии настройки на момент запроса.** Если во время проверки настройку
  изменили, результат к новой настройке не относится, помечается устаревшим и включить её не даёт.
- **Ключ не возвращается даже если провайдер вернул его** в поле `model` или в тексте ошибки:
  такие значения вычищаются перед сохранением сообщения проверки.

## Что настраивается

Адрес API из официальных, **фактический идентификатор модели** (вводится человеком, не выводится
из названия провайдера), ключ, таймаут, потолок ответа, цена запроса и ответа за 1000 токенов,
лимит расходов, признак «использовать для ответов».

Цены и лимит — те же величины, которые понимает бюджетный стоп: без объявленной цены денежная
граница по этому провайдеру не работает.

## Подключение к рантайму

В рантайм ответов (`ops/content/hugh-fallback.js`) попадает провайдер, у которого одновременно:
сохранён ключ, **включён** признак использования и есть **успешная проверка текущей версии
соединения**. Одного «включено» недостаточно. Адрес перепроверяется по списку и здесь.
Одноимённый провайдер из ЛК заменяет заданный в окружении; отдельного мёртвого экрана нет.

Реализован ровно один контракт — OpenAI-совместимый `POST {адрес}/chat/completions`, тот же,
что уже работал. Других адаптеров нет и они не выдумывались.

**Anthropic через этот контракт не подключается.** Его API устроен иначе, адаптер не написан,
поэтому кандидат помечен недоступным: ключ для него не принимается и проверка не выполняется.
В интерфейсе он показан с причиной и без формы. Резерв, предназначавшийся Anthropic,
через ЛК сейчас использовать нельзя.

## Инструкция: куда Влад вставит ключ

1. Оператор задаёт на сервере `HUGH_PROVIDER_MASTER_KEY` (случайная строка ≥32 символов,
   в защищённом хранилище окружения, **не в репозитории**) и перезапускает сервис контента.
2. Изменения этой ветки должны быть проверены, слиты и развёрнуты.
3. Влад входит в ЛК владельцем → **Настройки системы** → «Провайдеры ответов Хью».
4. Раскрывает нужного провайдера, вставляет **адрес API из официальных** (подсказка с хостами
   рядом), **фактический идентификатор модели** и **ключ**, задаёт цены и лимит расходов.
5. Нажимает «Сохранить настройку». Галочку «использовать для ответов» оставляет **снятой**.
6. Нажимает «Проверить соединение» — это единственное действие, которое обращается к провайдеру.
7. Только после успешной проверки включает галочку и сохраняет ещё раз.

Кабинеты пополнения из поручения: Z.ai, Alibaba Model Studio, DeepSeek, Google AI Studio,
Mistral, а также OpenAI и Anthropic как резерв. Ссылки выведены рядом с каждым провайдером.

## Блокеры реальной поставки

1. **Изменения не развёрнуты** — ТОЧНО: коммитов, push и деплоя не было.
2. **`HUGH_PROVIDER_MASTER_KEY` на сервере** — НЕ ПРОВЕРЕНО: сервер не осматривался.
   Без него раздел работает только на чтение и честно сообщает, что закрыт.
3. **Балансы провайдеров не пополнены.** Конкретные суммы по каждому провайдеру задаёт
   владелец в личном чеклисте вне репозитория; здесь они не публикуются. Формат записи —
   «провайдер: сумма, валюта, дата» (например, «demo-provider: 10 USD, 19.09.2026»).
   Списаний не было, код платежей не выполняет.
4. **Совместимость провайдеров с нашим контрактом не подтверждена.** Мы реализуем только
   OpenAI-совместимый `/chat/completions`. Для каких из кандидатов он доступен по указанным
   адресам — покажет проверка соединения; заранее это не утверждается.
   **Anthropic — точно недоступен** через этот контракт: адаптер не написан.
5. **Официальность хостов в каталоге не подтверждена.** Список взят из ссылок поручения
   и общеизвестных адресов API. **Успешный ответ по адресу НЕ доказывает, что хост принадлежит
   провайдеру** — он доказывает только совместимость с контрактом. Принадлежность хоста
   проверяется по официальной документации провайдера, вне этой системы.
   До такой сверки список остаётся предположением, ограничивающим область, а не гарантией.
6. **Минимальные суммы пополнения, налоги, платёжная доступность и регион не проверены.**
7. **Живой проверки не было**: все тесты используют подменённую сеть. Ни одного обращения
   к настоящему провайдеру и ни одного платежа в этой работе не выполнялось.

## Проверка

```
node --test ops/content/hugh-providers.test.js ops/content/hugh-providers-route.test.js
NODE_PATH=<каталог с jsdom> node --test sites/synapse/cabinet/hugh-providers.test.cjs
```

Покрыто: закрытое хранилище без мастер-ключа и при коротком ключе, отсутствие ключа в ответах
и шифрование в базе, нечитаемость чужим мастер-ключом, отказ произвольному адресу (http,
IP-литерал, чужой домен, поддомен-подделка, логин с паролем, нестандартный порт, параметры,
хост другого провайдера), выключенное состояние по умолчанию, запрет включения без ключа
и без свежей проверки, сохранение проверки при переключении «включено», её обесценивание
при смене адреса, модели или ключа, конфликт версий, отказ клиенту и отсутствие сессии,
CSRF на записи и на проверке, очистка поля ключа в интерфейсе, пустой `localStorage`.

Отдельные регрессии на найденные при ревью случаи: проверка останавливается **до сети**
при неизвестной цене с денежной границей и при исчерпанном бюджете; `HTTP 200` с пустым
или неполным JSON не считается подтверждением, а пустой текст при `max_tokens: 1` — считается;
параллельное сохранение во время проверки не подтверждает чужую новую настройку; переадресация
отклоняется тремя способами (исключение, признак `redirected`, код 3xx) и запрос уходит
с `redirect: 'error'` и в проверке, и в рантайме; включённый провайдер без актуальной успешной
проверки в рантайм не попадает; ключ, возвращённый провайдером в `model`, в сообщение не попадает;
Anthropic не принимается ни на сохранение, ни на проверку.
