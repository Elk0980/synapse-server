# Общая очередь сервера

ЛК владельца → Задачи → Координация проектов → Очередь сервера. Используется существующая сессия владельца, CSRF и ключ внутреннего CRM. Клиентам раздел и API недоступны. Состояние и неизменяемая история находятся в постоянной CRM SQLite, не на ПК.

1. До записи проверить актуальную памятку сервиса, свою задачу, реального владельца/процессы/ожидающие операции. Внести основание свежей проверки свободы. Оно действует5мин.
2. Добавить заявку: постоянный ID чата, задача, исполнитель, точная область, нераньше и5–60мин. requestKey сохранять до подтверждения; одинаковые данные с тем же ключом не создают дубль.
3. Занять первую наступившую заявку. Только успешный ответ с leaseToken/fence подтверждает аренду. Токен не показывается в списке и не передаётся другим чатам. Перед новым действием читать свежую revision.
4. Продлевать свою аренду, пока работа идёт; после проверенного результата освободить её и записать исход. Ревизия/токен/поколение защищают от позднего ответа старого исполнителя.
5. Истечение не означает свободу: исход uncertain, следующая работа заблокирована. Проверить исполнителя и фактический результат. Затем тот же исполнитель завершает свою аренду либо владелец явно подтверждает исход completed/stopped/rolled_back/no_write с основанием.

GET /coordination/server-resource, POST /coordination/server-resource/requests, POST /coordination/server-resource/action. Actions: confirm_idle, claim, renew, release, cancel. Все изменения очереди атомарны; действие требует revision. GET nextCheckAt/serverTime определяет контроль5–15мин. Таймер после пробуждения перечитывает очередь и не запускает повторную публикацию.

Очередь учитывает общий ресурс synapse-production: консоль, CRM и серверное размещение. Это кооперативный учёт. Произвольная SSH-команда вне API технически не перехватывается; утверждать универсальную блокировку нельзя. Все подключённые исполнители должны выполнить preflight и регистрацию. Неподключённый чат не считается участником по одному сохранению документа. Локальные тесты/ветка не являются рабочей серверной очередью; production и участие проверяются отдельно.

Клиентские дизайны/тексты, настройки прав, ключи, бизнес-данные и автоматическая синхронизация этой функцией не изменяются. Само наличие очереди не разрешает публикацию или снятие неизвестного владельца.
