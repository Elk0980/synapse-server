# Подтверждение внешней публикации (external publication receipt)

Контент часто выходит не из личного кабинета: владелец публикует ролик через внешний сервис
или прямо в приложении площадки. До сих пор такая карточка оставалась «Черновиком», хотя запись
уже опубликована. Подтверждение внешней публикации — это отдельное **доказательство**, которое
владелец добавляет вручную. Оно ничего не отправляет и ничего не подменяет.

## Что такое receipt и чем он не является

| Что это | Чем не является |
| --- | --- |
| Запись владельца: площадка, публичная ссылка, время публикации, версия содержимого, кто и когда отметил | Не доставка: провайдер (Onlypult, VK API, Telegram Bot API) не вызывается |
| Доказательство факта выхода записи | Не согласование: `approval` и `review.state` не меняются |
| Основание запретить повторную отправку этой площадки | Не смена статуса карточки: карточка остаётся в своём состоянии (`draft`, `needs_review`, …) |
| Отдельная сущность, переживающая правку содержимого | Не `autoposting_deliveries`: нативные отправки и ручные доказательства не смешиваются |

Запланированная запись опубликованной не считается: дата публикации в будущем отклоняется
кодом `NOT_PUBLISHED_YET`.

## Модель данных

Таблица `autoposting_publication_receipts` (`ops/crm/autoposting.js`):

| Поле | Смысл |
| --- | --- |
| `company_id`, `post_id` | Компания и карточка контент-плана; изоляция арендаторов на уровне выборки |
| `platform` | `instagram`, `tiktok`, `youtube_shorts`, `vk`, `telegram` |
| `url` | Публичная ссылка на запись, нормализованная при проверке |
| `published_at` | Момент публикации в UTC |
| `content_revision` | Версия содержимого карточки, которая действительно вышла |
| `note` | Необязательное примечание владельца (до 500 символов) |
| `recorded_by`, `recorded_by_name`, `recorded_at` | Кто и когда отметил |

`UNIQUE(company_id, post_id, platform, url)` — ключ идемпотентности. Повтор того же
подтверждения возвращает прежнюю запись (HTTP 200) и не создаёт дубль; новое подтверждение
создаётся с HTTP 201.

Подтверждения **не удаляются** при правке карточки: `update()` очищает только `autoposting_deliveries`.
После правки содержимого у каждого подтверждения выставляется `stale: true` — ссылка относится
к прежней версии, а текущая версия на этой площадке не публиковалась.

## API

```
POST /autoposting/posts/{id}/receipts?companyCode={code}
{ "platform": "telegram",
  "url": "https://t.me/channel/512",
  "publishedAt": "2026-09-17T09:30:00.000Z",
  "contentRevision": 2,
  "note": "" }
```

Ответ — карточка целиком; подтверждения лежат в `externalReceipts[]`
(`platform`, `platformLabel`, `url`, `publishedAt`, `contentRevision`, `stale`, `note`,
`recordedByName`, `recordedAt`).

Коды отказа:

| Код | Когда |
| --- | --- |
| 403 `FORBIDDEN` | Не владелец компании (проверяется и в прокси `ops/content/server.js`, и в `ops/crm/server.js`) |
| 403 | Неверный CSRF-токен — общий механизм прокси кабинета |
| 404 `NOT_FOUND` | Карточка другой компании |
| 400 | Ссылка не прошла проверку, неизвестная площадка, некорректная дата |
| 400 `NOT_PUBLISHED_YET` | Дата публикации в будущем |
| 409 `CONTENT_REVISION_CONFLICT` | Содержимое карточки изменилось: подтверждается не та версия |
| 409 `EXTERNAL_PUBLICATION_RECORDED` | Попытка поставить в план площадку, уже отмеченную как опубликованную |

## Проверка ссылки

Ссылка принимается не «по хосту», а целиком по одному из разобранных форматов площадки.
Общая для сервера и кабинета функция (`receiptFormat` в `ops/crm/autoposting.js`,
`safeReceiptUrl` в `sites/synapse/cabinet/autoposting.js`) требует:

* схему `https` (никаких `http`, `javascript:`, `data:`);
* отсутствие логина, пароля и порта;
* отсутствие части после `#`;
* отсутствие управляющих символов, разметки, кавычек и обратных слэшей; длину до 500 символов;
* домен из списка своей площадки — похожие хосты вроде `t.me.attacker.example` отклоняются;
* путь и строку запроса, совпадающие с одним из поддерживаемых форматов **целиком**.

| Площадка | Поддерживаемые форматы |
| --- | --- |
| Telegram | `https://t.me/<канал>/<номер>`, `https://t.me/c/<id>/<номер>` |
| ВКонтакте | `https://vk.com/wall-12345_678` (`wall`/`video`/`clip`/`photo`), `https://vk.com/<сообщество>?w=wall-12345_678` |
| Instagram | `https://www.instagram.com/(p\|reel\|reels\|tv)/<id>`, в том числе с именем автора в пути |
| TikTok | `https://www.tiktok.com/@<автор>/(video\|photo)/<id>` |
| YouTube Shorts | `https://www.youtube.com/shorts/<id>`, `https://www.youtube.com/watch?v=<id>` |

Параметры запроса разрешены только там, где их требует сам формат (`w` у ВКонтакте,
`v` у `watch`), и их **значения проверяются регулярным выражением формата**. Любой лишний
параметр, повтор параметра и значение не по формату отклоняются, поэтому
`?t=TOKEN`, `?z=SECRET`, `?igsh=SESSION`, `?v=a&v=b` не проходят.

Короткие ссылки (`youtu.be`, `vm.tiktok.com`, `vt.tiktok.com`) **не поддерживаются**: по ним
нельзя убедиться, что это адрес записи, а не редирект. Лучше минимальный проверяемый формат,
чем непроверяемый shortlink.

Кабинет применяет ту же проверку дважды: до отправки формы (некорректная ссылка не уходит
на сервер) и перед отрисовкой (в разметку попадает только разобранный адрес). Вывод
экранируется, переход идёт с `rel="noopener noreferrer"` и `referrerpolicy="no-referrer"`.

## Запрет повторной отправки

Отмеченная площадка не отправляется ни вручную, ни из очереди. Проверка стоит на четырёх рубежах:

1. `schedule()` отказывает с `EXTERNAL_PUBLICATION_RECORDED`, если среди выбранных каналов
   есть площадка с подтверждением.
2. Воркер `processDue()` до захвата lease отменяет `pending`-доставки отмеченных площадок
   (`error_code = EXTERNAL_PUBLICATION_RECORDED`) и переводит карточку в `needs_review` —
   это закрывает случай, когда подтверждение добавили после постановки в план.
3. Та же проверка повторяется внутри цикла по каналам, перед вызовом транспорта.
4. Проверка встроена в callback `beforePublish` — барьер, который адаптер вызывает
   непосредственно перед передачей запроса площадке, после всех предварительных обращений.
   Подтверждение, добавленное, пока транспорт ждал preflight, останавливает передачу:
   доставка снимается в `cancelled`, карточка уходит в `needs_review`.

Сохранение подтверждения при этом не запускает `schedule`/`send` и не создаёт доставок.

### Чего запрет не гарантирует

`beforePublish` — последняя точка, где отправку ещё можно остановить. Как только запрос
передан площадке, подтверждение его **не отменяет**: отсутствие дубликата в этом случае
не гарантировано. Кабинет говорит об этом прямо в блоке подтверждений и не подменяет
результат уже начатой доставки — она остаётся видна со своим статусом и ссылкой.

Барьер `beforePublish` сегодня вызывает только адаптер Onlypult
(`ops/crm/autoposting-transport.js`). Прямые каналы Telegram и ВКонтакте выполняют
один запрос без ожидания preflight, поэтому для них работают рубежи 1–3.

## Интерфейс кабинета

* Блок «Публикации вне кабинета» рядом с согласованием: по каждой площадке отдельная строка
  «Опубликовано вне ЛК», ссылка, время в поясе карточки, версия содержимого и автор отметки.
* Если версия содержимого изменилась после публикации, показывается предупреждение:
  «Подтверждена публикация версии содержимого vN. Публикация текущей версии vM не подтверждена».
  Кабинет не утверждает, что новая версия не выходила: он этого не знает — он лишь говорит,
  что подтверждения на неё нет.
* Форму добавления видит только владелец; участники с `autoposting.view` видят список и ссылки.
* Форма до сохранения предупреждает: отметка навсегда заблокирует повторную отправку этой
  площадки для карточки и в текущем интерфейсе не отзывается.
* Карточка очереди контента показывает сводку «Опубликовано вне ЛК: …».
* Предпросмотр перечисляет отмеченные площадки как препятствие к постановке в план,
  кнопка «Поставить в план» остаётся отключённой.

## Ограничения

* Отметку нельзя снять или исправить через интерфейс: ошибочная ссылка навсегда блокирует
  повторную отправку этой площадки для этой карточки. Форма предупреждает об этом до сохранения;
  отзыв подтверждения — отдельная задача.
* Подтверждение не сверяет содержимое записи на площадке: это слово владельца, а не проверка.
  Поэтому «подтверждения нет» никогда не означает «публикации не было».
* Уже переданную площадке отправку отметка не отменяет — см. «Чего запрет не гарантирует».
* Короткие ссылки площадок не поддерживаются; нужен канонический адрес записи.
* Автоматическое обнаружение уже вышедших публикаций не выполняется.
