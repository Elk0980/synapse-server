# Data model

Process: Spec Kit 1.0.0. Согласованный контракт инкремента; точные SQL-миграции и результаты проверок см. в реализации и evidence.md.

## Direct connection — vk_direct_connections

Одна запись на пару `(company_code, purpose)`, где `purpose` — `analytics` или `design`. Хранилище включает `group_id,token_type,encrypted_token,enabled,revision,checked_revision,status,checked_at,error_code,updated_at`. Аналитика допускает только `user`; оформление — `user` или `group`. Секрет шифруется с аутентифицированной привязкой к компании, назначению и группе и не возвращается в DTO.

Публичное для авторизованного владельца представление: `companyCode,purpose,groupId,tokenType,revision,configured,tokenConfigured,enabled,connected,checkedRevision,status,checkedAt,errorCode,group,capabilities`. Это приватный API кабинета, не общедоступные данные. `connected` и capability-проверка не означают неограниченных прав на операции VK. `group` содержит `{id}` или `null`; `capabilities` разделяет `statistics,communityInfo,design,editingRightsVerified,messages,publishing`. У прямого подключения `messages` и `publishing` выключены; чтение не устанавливает `editingRightsVerified=true`.

Сохранение требует актуальной `revision`. Пропущенный/пустой секрет сохраняет прежний только при той же привязке. Изменение привязки не переносит незаметно старую авторизацию. Проверка относится к конкретной ревизии; старый результат проверки не разрешает работу новой конфигурации. Записи публикаций и секреты Onlypult не изменяются.

## Design preview — vk_design_previews

Неизменяемое намерение: компания, группа, ревизия подключения, `previewId`, `operation`, `before`, `after`, хеш полезной нагрузки/исходного файла и время. Для обложки исходные байты хранятся приватным BLOB; в ответ выдаются только сведения для предпросмотра. Они не превращаются в публичный asset URL.

DTO: `companyCode,groupId,revision,previewId,operation,before,after,sourceHash,warnings,createdAt`. Для обложки `after` содержит `mime,width,height,sourceHash,crop`; `before` содержит прежние `enabled,images`. Ссылки прежней обложки не гарантируют возможность восстановления оригинала.

## Design action — vk_design_actions

Запись создаётся до внешнего изменения. Устойчивый `requestId` и связь с `previewId` исключают повторную отправку того же намерения; повтор запроса возвращает известный результат. Запись привязана к компании, группе и ревизии. При несовпадении текущего состояния/ревизии нужна новая подготовка.

Состояния:

- `applying` — отправка зарегистрирована, окончательного результата ещё нет;
- `verified` — результат подтверждён повторным чтением;
- `applied_unverified` — VK принял изменение, но соответствие опубликованного состояния не подтверждено;
- `uncertain` — неизвестно, было ли изменение выполнено; автоматический повтор запрещён;
- `failed` — зафиксирован отказ/ошибка, без заявления об успешном изменении.

DTO дополнительно включает `requestId,status,code,completedAt`. Провайдерские секреты, URL загрузки с временными параметрами и сырые ответы ошибок в журнал/DTO не попадают. Журнал истории доступен только владельцу выбранной компании.

## Analytics / rollback

Сбор использует существующие метрики, интервалы, снимки и журнал social-stats, добавляя независимый прямой транспорт. Отсутствие измерений не превращается в ноль. Настройка аналитики не меняет `autoposting_channels`.

Откат описания создаёт новый preview на основании прошлой операции. Текущее описание должно совпасть с её ожидаемым результатом; иначе сначала разрешается конфликт. Применение отката получает новый requestId. Обложка не имеет гарантированного автоматического отката без сохранённого исходного файла.
