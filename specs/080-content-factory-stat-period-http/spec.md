# HTTP периода статистики Контент завода

Spec Kit1.0.0. Root: только ops/crm/social-stats-http.js, новый social-stats-project-period-http.test.js и эти документы. Серверный расчёт social-stats.js/spec079 — отдельный автор, UI — Claude.

Цель: обращения выбранного месяца проекта используют его часовой пояс, сохраняя прежний общий UTC контракт аналитики. GET не запускает сбор и ничего не сохраняет.

- FR-001 GET /social-stats принимает единственный необязательный crmPeriod=project или utc. Отсутствие параметра сохраняет вызов overview с прежними тремя аргументами. Пустое, неизвестное или повторённое значение возвращает400 VALIDATION_ERROR field crmPeriod до чтения сводки.
- FR-002 project передаётся как options.crmPeriod. Часовой пояс берёт сервис из своей компании; параметр timezone не переопределяет его. Даты from/to и дневные агрегаты площадок сохраняют существующую семантику.
- FR-003 Сохраняются analytics.view, область активной компании и no-store. Отказ storedtimezone отдаётся400 field timezone; ошибочные запросы не меняют БД и не вызывают сеть.

Приёмка: через настоящий локальный HTTP handler и настоящий social-stats/SQLite. Москва2026-09-30T21:30Z входит в октябрь в project, отсутствует в прежнем UTC. Самостоятельно проверяются повторный параметр, неверное значение, запрет доступа и чужая компания; данные соседней компании не попадают в сводку. Production/liveAPI/права/секреты/commit/push/deploy не затрагиваются.
