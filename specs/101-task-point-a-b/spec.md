# Задача: «Точка А → Точка Б» и шаги приёмки — задача доски №60

Источник: задача доски №60, условия решены заранее и переданы координатором 04.11.2026. Строится поверх PR 482 (ветка `codex/waiting-vlad-20261103`, head 795d7d6); сливать после 482.

## Цель

Владелец открывает карточку и сразу видит, что было и что будет, и по каким проверяемым шагам задача считается принятой. Закрыть шаг может только проверяющий и только с доказательством.

## Требования

- FR1. Поля «Точка А», «Точка Б», «Пример», «Шаги приёмки» (список) и https-ссылки на картинки А и Б хранятся в `coordination.data.pointAB` существующей таблицы `task_coordination` с её ревизией и неизменяемой историей. Новых таблиц и колонок нет. Обычное сохранение карточки (`save`, `task_update`, синхронизация старого CRUD) переносит блок без изменений.
- FR2. Блок меняют отдельные действия `task_point_ab`, `task_step_close` и `task_step_reopen` в существующем обработчике `/coordination/mcp/<name>` (только владелец, в пределах проектов, `revision` проверяется при передаче). Клиент не может сам выставить шагу состояние «закрыт»; закрытый шаг нельзя переписать без повторного открытия. Открытый шаг нельзя убрать из списка через `task_point_ab` (400); убрать можно закрытый шаг или снять шаг действием `task_step_remove` с обязательной причиной — запись идёт в ревизию и историю, шаг остаётся в блоке с пометкой «удалён». Снятие исполнителем только предлагается: шаг продолжает блокировать «Готово», пока его не снимет или не закроет проверяющий ≠ исполнитель (решение ревью PR 490).
- FR3. Картинки А/Б и доказательства шагов принимаются только как `https:` без учётных данных; проверка на сервере и в интерфейсе. Загрузка файлов в этой итерации не делается.
- FR4. Шаг закрывается только с https-доказательством (ссылка или картинка) и только не исполнителем задачи. Исполнитель — `tasks.assignee_name`. Закрывающий — principal CRM (`userName`, `person:<userId>`), а также имя `author`, которым представился агент (агенты работают под ключом владельца). Совпадение без учёта регистра/ё и пробелов → 403.
- FR5. Процент задачи: `done` → 100. Без шагов — подтверждённые этапы × 25. С шагами — `round((этапы×25 + 100 × закрытые/все) / 2)`. Сервер отдаёт `acceptance_steps {total, closed}` и `progress` в `tasks_list` и `task_get`; кабинет считает по той же формуле. Карточка модуля показывает «N из M шагов» (сумма по задачам состава), строки задач — свои «N из M шагов».
- FR6. Обратная совместимость: если блок не сохранён, он разбирается из описания по строкам «Точка А:», «Точка Б:», «Пример:», «Шаги приёмки:». Блок многострочный до следующей метки (также «Состав:», «ЦКП:», «Модуль №N»). Шаги — строки с `[ ]` или `[x]` (допускаются маркеры списка). Одна метка «Пример:» блок не создаёт. Сохранённый блок важнее описания. При любом изменении описания (PATCH старого CRUD), если блок не сохранён, а прежнее описание содержит блок, сервер в той же транзакции сначала сохраняет его в coordination (шаги открыты, пометки наследия сохраняются), затем применяет новое описание — стереть шаги правкой описания нельзя. Шаги из описания считаются открытыми независимо от `[x]`: отметку можно поставить правкой текста без доказательства. `[x]` даёт только пометку наследия «закрыто до введения доказательств (наследие)» — в интерфейсе «нужно доказательство»; пометка сохраняется при сохранении блока через форму. Закрыть такой шаг можно после сохранения блока, проверяющим и с доказательством (решение ревью PR 490).
- FR7. Перевод в «Готово» при открытых шагах → 409 с текстом «Нельзя перевести в «Готово»: открыты шаги приёмки — N из M…». Проверка общая для `task_update` (и `session_end`), `selfStatus`, `task_create` и POST старого CRUD со статусом done, PATCH старого CRUD (по прежней и по объединённой с новым описанием строке) и приёмки поручения (`task-dispatch accept`).
- FR8. Карточка задачи в кабинете: блок «Было | Будет» с картинками; на ширине ≤ 640px (проверено 390px) колонки друг под другом. Весь текст через `esc()`/`linkedText()`, картинки — только https. У готовой задачи заголовок «Было → Стало» и подпись «Стало».
