# Feature Specification: Eva — личный задачник SynapseBusiness

**Feature Branch**: `docs/private-project-context-20261002`
**Created**: 2026-10-02
**Status**: Draft — реализация разрешена; подключение и production отдельно
**Input**: Владелец поручил кнопочный Telegram задачник Eva без AI-диалога и без новой базы задач.

## User Scenarios & Testing

### User Story 1 — задачи в одном месте (P1)
Владелец открывает Eva, выбирает Сегодня, Проекты, Все задачи или Ждут меня,
открывает карточку с проектом, статусом и следующим шагом, возвращается к тому же списку.

Acceptance: списки содержат существующие ID; удалённые задачи исключены; пустое состояние
отличается от ошибки загрузки; длинный список разбит на страницы; неизвестное не заменено выдуманным.
Сегодня включает открытые просроченные задачи и задачи со сроком сегодня в настроенном часовом поясе.
Все задачи включает завершённые и отменённые. Ждут меня использует явное назначение владельцу
или подтверждённое серверное ожидание его ответа/приёмки, а не наличие произвольного блокера.

### User Story 2 — только владелец (P1)
Другой пользователь, группа, пересланная/поддельная/устаревшая кнопка не открывают данные.
Проверка отправителя и приватного чата обязательна при каждом действии. При изменении или
удалении задачи старая кнопка не выдаёт прежний сохранённый контекст.

### User Story 3 — независимый серверный запуск (P2)
Владелец лично вставляет полученный в BotFather токен в скрытое поле серверной консоли.
После отдельно разрешённого запуска бот работает без Windows-компьютера и без расходов на LLM.
Токен не появляется в чате, git, аргументах команды, журнале или ответе ошибки.

### Edge Cases
Нет срока/следующего шага/привязки проекта; повреждённая или недоступная БД;
различия схемы; больше одной страницы; смена компании; повтор update после перезапуска;
потеря связи после отправки; второй poller; установленный webhook; незаданный owner ID.

## Requirements

- FR-001: Единственный источник задач — существующая CRM, её ID и company_code. Не создавать/копировать/удалять задачи.
- FR-002: Четыре входа и карточка с возвратом/главной; интерфейс на русском, имя Eva, бренд SynapseBusiness.
- FR-003: Владелец определяется настроенным числовым Telegram ID; username и callback данные не являются авторизацией.
- FR-004: Каждое открытие перечитывает текущие данные. Callback содержит только непрозрачный ограниченный идентификатор навигации.
- FR-005: Первая версия только читает. Смена статуса и создание доступны прежнему кабинету; новый канал не обходит его права/приёмку.
- FR-006: Runtime не вызывает модели, не отправляет плановые/инициативные сообщения, не открывает публичный endpoint.
- FR-007: Повторные входящие события не меняют данные и не дублируют ответы после нормального сохранения курсора. Не обещать exactly-once сеть.
- FR-008: Ошибки, аудит и постоянное состояние не содержат токенов, текстов задач/чатов или приватной памяти.
- FR-009: Настройка и запуск не происходят автоматически; токен вводит человек. Один работающий poller на токен и state volume.
- FR-010: База контекста остаётся приватным дополнением AI_HANDOFF; источники, даты, подтверждённость и неизвестные server ID явно указаны.
- FR-011: По дополнительному поручению владельца исправить подтверждённую дедупликацию POST /tasks:
  совпадение source_ref у другой компании или другого источника не возвращает чужую задачу;
  повтор в той же области сохраняет прежний ID. Без миграции/удаления существующих данных.

### Key Entities
Task = CRM task id; Project = существующий company_code/name; coordination = nextAction/blocker;
dispatch = серверный этап ожидания; update cursor = только транспортное состояние, не реестр задач.

## Success Criteria

- SC-001: Четыре вида списка и карточка проходят локальные проверки с существующей схемой и фиктивными данными.
- SC-002: Все негативные проверки авторизации возвращают ноль сведений задач и не вызывают источник.
- SC-003: Тесты подтверждают отсутствие записей в CRM, повторной обработки update и утечки токена через ошибки.
- SC-004: Пакет содержит конкретные шаги личного ввода токена, запуска, проверки и остановки; публикация отмечена отдельно.

## Assumptions and boundaries
Сервер Linux/Docker согласно текущему compose; реальное имя тома, права файлов, Telegram ID,
часовой пояс и доступность username проверяются оператором перед запуском. Mount CRM read-only
даёт процессу доступ к файлу всей CRM; это отдельный постоянный доступ, требующий согласования.
Настройка токена не означает запуск. Скрытое состояние/поведение моделей не переносится.
