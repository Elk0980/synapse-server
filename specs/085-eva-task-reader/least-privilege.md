# Граница доступа Eva

Проверка исходников 02.10.2026, база08984a2. Production volume и реальные записи не читались.

## Почему не mount CRM

Read-only mount ограничивает запись, но открывает процессу весь SQLite-файл, WAL/SHM и
остальные файлы тома. По изученным схемам CRM это как минимум контакты, телефоны/email,
заметки и даты рождения; заявки, комментарии и сообщения; юридические/банковские реквизиты;
расходы и суммы продаж; клиентские документы с file_data; аналитические события; полные
описания/авторы задач, coordination JSON/history и dispatch с вопросами, результатами и lease_token.
Также подключён модуль зашифрованного хранилища Onlypult; его записи и схема здесь не проверялись.
Состав реального volume может быть шире. Отсутствие secrets не заявляется по одному SQL SELECT.
Источники: ops/crm/server.js, task-coordination.js, task-dispatch.js.

## Существующие API

- CRM /tasks использует общий x-api-key; companyCode является фильтром, а не ограничением
  прав ключа. Такой ключ не выдаётся Eva.
- /coordination/tasks требует owner identity от проверенной content-сессии. Подделывать
  её заголовок нельзя. GET вызывает dispatch.get/reconcile, способный обновить историю/состояния;
  поэтому этот путь не используется как источник чистого чтения.
- Отдельный HTTP capability потребовал бы нового persistent credential и управления отзывом.
  Готового ограниченного machine credential в изученном коде не найдено.

## Подготовленный вариант

Существующий CRM-процесс выполняет только SELECT через опциональный приватный UNIX socket.
Нет TCP listener, browser route, общего CRM key или копии реестра. Сервер разрешает только
GET /v1/tasks без параметров и ровно заданные в EVA_TASK_PROJECTS коды проектов.
Неуказанные, новые и отсутствующие проекты не становятся доступными автоматически.

Eva получает поля id, title, companyCode, companyName, status, dueAt, nextAction, blocker,
waitingForOwner; техническая оболочка version/readAt. Полные descriptions, contacts,
документы, source-author, coordination/history и dispatch history не передаются.
Свободный текст title/nextAction/blocker всё равно может содержать пользовательские рабочие
сведения: согласование передачи этих полей в Telegram необходимо.

Socket находится в отдельном закрытом каталоге0700, файл0600. Eva видит только этот volume
read-only, собственные cursor/lock и token file. Read-only mount не ограничивает сообщения
socket: ограничения метода, пути, scope и полей реализованы серверным обработчиком.
Права и Linux/Docker E2E проверяются при разрешённом подключении отдельно от unit-тестов.

Derived snapshot был рассмотрен: допустим как машинная проекция с atomic replace,
generatedAt/expiresAt и отказом при просрочке, без ручного редактирования/обратной синхронизации.
Он добавляет задержку и копию клиентских текстов; текущая реализация использует свежий socket-запрос.

## Минимальное согласование перед включением

1. Merge/deploy конкретного проверенного commit и ограниченный перезапуск CRM для опционального handler.
2. Новый отдельный socket volume и доступ только CRM + Eva; exact company_code list подтверждает владелец.
3. Один Eva poller и передача перечисленных полей только в личный Telegram настроенного owner ID,
   только в ответ на его действия. Никаких автоматических сообщений/моделей/записи задач.
4. Владелец лично вводит token в скрытое поле серверной консоли, оператор не получает token через чат.

Подготовка файлов не выдаёт эти права. Никакой новый доступ, credentials или deployment этой работой
не активированы. Данные проектов и сам список разрешённых company_code не помещаются в публичный PR.
