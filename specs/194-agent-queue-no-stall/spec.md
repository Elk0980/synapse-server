# 194 — Очередь агентов без простоев: видимость обработчика, передача запасному, профиль ревью и слияния

Решение Влада 07.11.2026 02:32 («придумай, как избежать этих остановок в работе»), «да» на автозапуск (№202) и поправка оркестратора 08.11 15:15 (комментарий 1329). Задача доски №194. Процесс 1.0.0.

## Точка А
- Запуск Codex по №193 простоял в очереди 2 ч 13 мин: локальный обработчик `ops/content/agent-launch-local-worker.js` на ПК Влада не был запущен, доска показывала «в работе», никто не видел, что запуск не начался.
- Сигнала «обработчик жив» без задания нет: heartbeat есть только у захваченного запуска.
- Обработчик принимает только `codex-code` (черновой PR) и не умеет ревью и merge, поэтому PR Claude ждут человека.
- Автозапуска при входе в Windows нет.

## Точка Б
1. Доска → «Агенты» и карточка задачи Codex показывают «Обработчик Codex: в сети / не в сети (последний сигнал N мин назад)», сколько запусков в очереди и сколько передано запасному за сутки.
2. Обработчик раз в минуту шлёт сигнал через существующий `agent_worker_update` (`event:"presence"`, без run_id). Опрос очереди тоже считается сигналом. «В сети» — сигнал не старше 3 минут.
3. Запуск, который 10 минут никто не забрал, сервер сам (раз в минуту, без запроса агента) снимает из очереди: комментарий в задаче «Не стартовал за N мин: обработчик Codex не в сети (последний сигнал …)», исполнитель задачи → «Claude — запасной исполнитель», следующий шаг заполнен; одна строка в утренней сводке сторожа. Ночных пушей нет.
4. Профиль `codex-review-merge` для PR Claude: оркестратор ставит `agent_launch(task_id, executor_profile:"codex-review-merge", pr_number:N)`. Обработчик готовит копию ровно на head PR, Codex делает независимое ревью и пишет замечания в задачу. При вердикте approve доверенный обработчик (не модель) проверяет, что head не сдвинулся и все проверки CI зелёные, пишет «КОД ПРИНЯТ — PR #N, head …» в задачу и сливает обычным merge с `--match-head-commit`. Метки защиты не ставятся и не снимаются, deploy не выполняется.
5. Автозапуск: `ops/content/agent-launch-worker-autostart.ps1` ставит задачу планировщика Windows текущего пользователя (при входе, перезапуск при сбое, без прав администратора). Секретный адрес MCP лежит в приватном файле настроек, не в аргументах задачи.

## Требования
- FR-1. `agent_worker_update` с `event:"presence"` принимает только `worker_id`, необязательные `platform` (≤40) и `active_runs` (0–100); `run_id`/`lease_token` запрещены. Обычные события по-прежнему требуют аренду и не принимают поля присутствия.
- FR-2. Сервер хранит последний сигнал по владельцу и обработчику (`task_dispatch_agent_workers`, не более 20 строк на владельца, запись не чаще раза в 30 с при опросе).
- FR-3. `agent_workers_status` (только владелец и его компании): `online`, `last_seen_at`, `minutes_ago`, пороги, до пяти обработчиков (8 символов идентификатора), запуски в очереди с минутами ожидания, передачи за 24 часа.
- FR-4. Передача запасному: только состояние `queued` без запроса остановки, только если запуск владеет очередью задачи и разрешён; 10 минут считаются от постановки или продолжения. Если обработчик в сети и занят тремя процессами, запуск ждёт слота. Во время `agent_worker_claim` передача не выполняется — опрашивающий обработчик получает запуск. Запуск получает `stopped`, запись `task_dispatch_agent_handoffs`, комментарий, исполнителя и следующий шаг. Повторный `agent_launch` после передачи разрешён.
- FR-5. Периодическая проверка `sweep()` в `server.js` раз в минуту действует от имени владельца запуска только в компаниях его запусков.
- FR-6. Профиль `codex-review-merge`: только `pr_number` (1–1 000 000), без `code_only` и `allowed_paths`; номер PR и профиль неизменяемы (триггер); продолжение (`agent_message`) запрещено, завершённое ревью получает `stopped` и не занимает задачу; из текста задачи проверяется только отсутствие указаний на deploy/выпуск на сервер, слово «merge» разрешено.
- FR-7. Обработчик: PR открыт и не черновик, база `main`, ветка `claude/…` этого же репозитория (`isCrossRepository=false`, владелец head и автор = владелец репозитория), сохранённый head совпадает с полученным; база для diff — свежий `main`. Модель не может написать «КОД ПРИНЯТ» ни в одном поле своего MCP (с учётом похожих латинских букв и невидимых символов); доверенный комментарий — от отдельного автора. Слияние только при всех проверках pass/skipping (хотя бы одна pass), ожидание CI не дольше 15 минут и не позже чем за 2 минуты до лимита запуска; при сдвиге head — отказ без комментария о приёмке; после ошибки gh состояние PR перечитывается.
- FR-8. Индикатор не ломает доску, если сервер ещё без нового инструмента.

## Не входит
- Фактический запуск Claude-агента сервером: сервер передаёт задачу запасному исполнителю на доске; подхватывает её Claude-оркестратор (плановая проверка). Автозапуск облачного Claude из сервера — отдельное решение.
- Изменение защиты веток, меток и managed-release.
