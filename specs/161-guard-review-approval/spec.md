# Проверка путей без метки Влада: принятое ревью точного head (№163)

Поручение Влада 05.11.2026 15:37 (повторено в пятый раз): «убери это, чтобы без меня не вставала работа».
Задача доски №163.

## Точка А
`site-path-approval` (`.github/workflows/protect-prod-sites.yml` → `tools/protect-prod-sites/guard.py`)
для инфраструктуры и клиентских сайтов требует метку «сайты: инфраструктура» / «сайт <slug>».
Метку ставит только Влад, поэтому каждый такой PR ждёт его.

## Точка Б
PR с такими путями проходит проверку без Влада, если в обсуждении PR есть комментарий независимого
ревью первой строкой `ПРИНЯТ PR <номер> @<полный sha текущего head>` (ревью 923: полный sha вместо 8 символов). Метка остаётся
альтернативой. Без принятого ревью точного head проверка красная.

## Требования (с правками ревью 923)
- FR-1 guard читает комментарии PR (`/issues/<n>/comments`, все страницы, больше 30 — закрытый отказ)
  только через API; код PR не исполняется. Дата коммита не используется: её задаёт клиент.
- FR-2 «ПРИНЯТ» засчитывается, если первая строка комментария целиком —
  `ПРИНЯТ PR <номер> @<полный 40-символьный sha>` (допуск обратных кавычек), номер — этого PR, sha — текущий
  head, автор — участник репозитория (OWNER/MEMBER/COLLABORATOR). Цитаты, код, текст вокруг, короткий sha — нет.
- FR-3 Более поздний комментарий участника, первая строка которого начинается с «НЕ ПРИНЯТ» (любой регистр,
  разметка, пунктуация) или содержит иной неоднозначный вердикт со словом «принят», закрывает проверку
  независимо от sha. Оба вердикта в одном комментарии — отказ. Решает последний по времени вердикт.
- FR-4 Обычные пути проходят как раньше и не читают комментарии; при метке комментарии не нужны.
- FR-5 Событие `issue_comment` (created/edited/deleted, текст содержит «ПРИНЯТ») перезапускает доверенную
  проверку из ветки по умолчанию; статус `production-sites/path-approval` — на текущий head PR.
  Посторонние комментарии не отменяют идущую проверку (отдельная группа concurrency).
- FR-6 Текст ошибки guard не содержит готовой фразы одобрения, только заглушку
  «ПРИНЯТ PR <номер> @<полный sha>».

## Приёмка
Тесты `tools/protect-prod-sites/test_guard.py`: метка проходит; ПРИНЯТ на текущий head проходит; на старый
head — нет; раньше push — нет; три обхода ревью 923 (префикс sha, цитата/инструкция, отказ без sha/с разметкой) — нет; НЕ ПРИНЯТ — нет; позже НЕ ПРИНЯТ поверх ПРИНЯТ — нет; обычные пути — как раньше.

## Ограничения
Не меняет настройки защиты ветки, права, секреты. Независимость ревьюера технически не проверяется, если
агенты пишут под одним аккаунтом GitHub — остаётся правилом доски. Этот PR сам меняет `.github` и guard и
проверяется ещё старым guard из main: ему последний раз нужна метка Влада.
