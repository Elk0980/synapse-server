## Переиспользование

`addVersion` уже принимает segments и сохраняет их атомарно с версией. `setSegments` уже изменяет существующую версию. Разметка не требует миграции БД. Новый MCP-адаптер ограничивается чтением/записью разметки и текущими project scopes; не предоставляет claim, публикацию, запуск кода или произвольный URL. Схема MCP и серверная проверка независимы. Для предотвращения потерь — контрольная ревизия текущих отрезков; идентичный повтор возвращает подтверждение.

## Копия просмотра

Уточнение проверяющего: на телефоне долго грузится тяжёлый файл. Копия `mobile-v1`: H.264 Main3.1/yuv420p, до720×1280/30fps,900k–1100k видео +AAC96k, faststart. Конверсия читает только локальный MP4 (никаких URL/сети), один процесс/один поток, очередь до8, timeout120с, ошибки повторяются не чаще5минут. Временное имя уникально, готовый файл появляется атомарно в отдельном `assets/publishing-previews/mobile-v1/`; CRM и исходный файл не меняются. Сверяется длительность/кодеки/размер; ошибка не публикует полуготовый файл.

Публичный существующий asset URL с `?preview=mobile-v1&status=1` возвращает маленький no-store JSON state; безstatus отдаёт готовую копию с Range. `cached=1` у миниатюр не запускает конверсию и не тянет оригиналы. Открытие карточки запускает только нужную копию; доready у video нетsrc. Статус ожидания/ошибка/повтор явно видны, послеготовности play вызывается только новым пользовательским жестом. WEBM/внешние ссылки сохраняют прежний просмотр, без новых внешних загрузок сервером.
