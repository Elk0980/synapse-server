# CF8: связанная проверка уведомлений подготовки плана

Процесс Spec Kit 1.0.0. Только новый синтетический интеграционный тест; существующая логика только чтение.

## Требования
- FR-001. Настоящие события succeeded/failed/delayed/needs_input проходят через content-plan-runner.sync и существующую durable очередь hugh-owner-alerts в owner HTTP DTO соответствующей компании; участник не получает ownerAlerts.
- FR-002. ack-alert подтверждает постановку в очередь: состояние pending, а не sent. Настоящий createProjectChat bridge выдаёт audience owner и chatId null; синтетическая квитанция через acknowledgeTelegram переводит в sent.
- FR-003. Потеря CRM-квитанции после вставки уведомления, до или после обработки ack-alert, и повтор sync не создают дубля.
- FR-004. После потери Telegram-квитанции и закрытия/повторного открытия файловой БД отправка становится uncertain после срока аренды; повторной отправки нет.
- FR-005. Если доступна имеющаяся jsdom, настоящий readonly клиент общей QA показывает владельцу состояния pending/sent/uncertain из настоящего HTTP DTO. Без исполнения DOM/live не заявлять.

## Ограничения
Только ops/content/content-plan-notifications.test.js и этот новый пакет 058. Общая копия, QA, существующие файлы, manifest/state только чтение. Только синтетические компании/учётные записи/БД/HTTP, без сети, реальных секретов, Telegram, коммитов, публикации и новых агентов. Дефекты сообщить координатору; production logic не исправлять.
