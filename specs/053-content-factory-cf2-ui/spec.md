# Контент завод CF2 — клиентская часть составления плана

**Поручение**: Влад, 01.10.2026 — параллельная работа Claude и Codex, рабочий вариант сегодня (`AI_HANDOFF/SYNAPSE_BUSINESS/CONTENT_FACTORY_PARALLEL_20261001.md`). Контракт сверен с Codex 01.10.2026 (`CONTENT_FACTORY_CF2_UI_CONTRACT_PROPOSAL_20261001.md` + его ответ).
**Владение**: Claude — `sites/` и UI-тесты этого пакета; Codex — `ops/` (очередь, исполнитель, маршруты). Пакет не меняет `ops/`.
**Статус**: клиент по контракту; серверные маршруты в рабочей системе ещё не подключены — интерфейс честно показывает недоступность.

## Цель
Из «Составить план» владелец запускает серверное составление плана на выбранный месяц, видит состояние задачи, вопросы, предложения по дням и создаёт из выбранных предложений черновики материалов. Ничего не согласуется, не планируется и не публикуется автоматически.

## Сценарии
- **US1 (P1)** Открытие «Составить план» показывает сводку вводных и состояние последней задачи месяца; ничего не запускает.
- **US2 (P1)** «Составить план на <месяц>» отправляет одну задачу; статус обновляется сам до конечного состояния.
- **US3 (P1)** Готовые предложения сгруппированы по дням (свёрнуто), фильтруются по площадкам; выбранные переносятся в черновики «Материалов».
- **US4 (P2)** needs_input — вопросы с указанием раздела настроек; после правки — новый запуск.
- **US5 (P2)** failed — причина от сервера; повтор только вручную и только если сервер разрешил.

## Требования
- **FR-001** Контракт: `POST /media-mentor/generation {clientRequestId, month}` → `{companyCode, job}`; `GET /media-mentor/generation?companyCode&month` → `{companyCode, jobs}` (последние 20; клиент сам выбирает последнюю по createdAt, id); `POST /media-mentor/generation/:id/drafts {proposalIds}` → `{companyCode, jobId, drafts:[{proposalId, postId}], createdCount}`. Job: id, month, status (queued|running|needs_input|succeeded|failed), attempts, maxAttempts, createdAt, updatedAt, startedAt|null, finishedAt|null, inputs{briefRevision, profileRevision, monthRevision}, executor null|{kind api|test, model}, coverage{requested, proposed}, questions, proposals, errorCode, errorMessage, retryable. Proposal: ideaId, date, platform, format, role, topic, hook, text, mentorNote, assetId, basis[], warnings[].
- **FR-002** Открытие сводки и смена месяца — только GET. Запуск — отдельной кнопкой; на время запроса кнопка заблокирована и повторное нажатие запросов не шлёт; при активной задаче (queued/running) запуск недоступен; needs_input/failed/succeeded — конечные.
- **FR-003** clientRequestId — один на нажатие. Если ответ не получен (сеть/5xx), предлагается «Отправить ещё раз» с тем же ключом. 409 GENERATION_ACTIVE / REQUEST_CONFLICT объясняются и состояние перечитывается. 404/405/501 — «составление на сервере пока не подключено», ничего не выдумывается.
- **FR-004** Опрос только при queued/running: 3 с, затем +3 с до 15 с; останавливается на конечном статусе, при закрытии сводки и смене компании; ответы прежней компании, месяца или задачи отбрасываются.
- **FR-005** Автоматического повторного POST нет. «Повтор возможен» показывается только при `retryable === true` от сервера. errorMessage — текст сервера; код не показывается вместо причины.
- **FR-006** Время и модель не обещаются до ответа сервера; `executor.kind=test` помечен «Тестовый исполнитель (QA)»; неизвестный статус показывается как есть.
- **FR-007** Предложения неизменяемы: несохраняемых правок нет. Дни свёрнуты по умолчанию, фильтр площадок, счётчик «показано N из M»; число предложений не ограничивается клиентом. Правка — только после создания черновика в существующем редакторе.
- **FR-008** Черновики: выбор видимых/снять выбор, «Создать черновики (N)» → POST drafts. Отметка «Черновик №… создан» — только по ответу сервера этой компании и этой задачи. 404/405/501 и ошибки — честное сообщение, ничего не отмечено, выбор сохранён; повтор безопасен. После успеха «Материалы» перечитывают список; «Открыть черновик» открывает его прямым GET без одобрения.
- **FR-009** Если снимок вводных задачи отличается от текущих ревизий брифа/профиля/месяца — предупреждение.
- **FR-010** Без права `autoposting.edit` — только просмотр состояния и предложений.

## Приёмка
- **SC-001** DOM-тесты FR-002…FR-010 на синтетическом сервере в памяти; тест «Материалов» на события черновиков.
- **SC-002** Отрицательная проба на дереве R2 `e2b582c5`, мутации, весь набор кабинета, снимки 1366/390 (SAMPLE-ответы в браузере и реальное «не подключено» временного сервера).

## Ограничения
Без `ops/`, production, живых клиентских API, прав, commit/push/deploy. Исполнитель, очередь, проверка результата, маршруты — Codex. Живые API и выпуск — отдельное решение.

## Поправка CF2-UI-R1 (замечания Codex, 01.10.2026)
- **FR-011** Перенос в черновики без ответа сервера (сеть, таймаут, 5xx) — результат неизвестен: «Черновики могли быть созданы», ничего не отмечается созданным, выбор сохраняется, повтор безопасен (сервер возвращает уже созданные). «Не созданы» говорится только при 404/405/501 (маршрут не подключён) и при отказе 4xx. Итог успешного ответа не утверждает состояние уже существующих черновиков.
- **FR-012** Открытие материала из предложения показывает его фактическое состояние из свежего `GET /autoposting/posts/:id` (статус и согласование), без безусловного «не согласован и не запланирован».
- **FR-013** Основание предложения: известные метки (`event`, `priority`, `occasion`, `question`, `proof`) — понятной подписью «Событие — …»; неизвестные, пустые и не-строковые метки скрываются.
- **SC-011** DOM: сервер сохранил черновики, ответ потерян, повтор вернул те же postId; повторное открытие изменённого материала; подписи основания без префиксов.

Основание: `AI_HANDOFF/SYNAPSE_BUSINESS/CONTENT_FACTORY_PALITRA_UX_20261001.md`, разделы 2 и 4. База — дерево CF2-UI-R1 `d8a77069`. Только `sites/` и `specs/053`; `ops/` не меняется, новых API нет.

Данные — существующий `GET /autoposting/calendar` за весь месяц; заголовка и дубля «Материалы» нет.
- **FR-015** Карточка: превью при наличии файла, название, площадка цветом и подписью, время по поясу проекта (или «время не задано» при дате плана), формат, цель ОВП и одна понятная метка статуса из существующих полей (`status`, `review`, `approval`, `platformApprovals`, `deliveries`); у согласованной — кто и когда. Цвет статуса — только в его метке.
- **FR-016** Фильтры площадка, формат, цель ОВП, статус; число активных и «Сбросить»; пустой результат объясняется. Фильтры и навигация ничего не пишут и не сбрасывают выбор или несохранённый ввод.
- **FR-017** Нажатие на карточку открывает существующий редактор публикации окном поверх доски (тот же `<details id="autoposting-editor">`, те же действия, права и ревизии). «Закрыть», Escape и уход из вкладки не теряют ввод (правки остаются в окне и отмечаются на карточке).
- **FR-018** Флажок на карточке — только выбор для существующего «Согласовать выбранные»; он не согласует, не меняет статус и не открывает окно.
- **FR-019** Телефон: список по дням, полоска дат недели, фильтры отдельной панелью, окно публикации на весь экран, «Сохранить черновик» закреплено снизу; перенос даты — полем в окне, без перетаскивания.
- **FR-020** Пустая доска приглашает заполнить «Настройки модуля» и составить план или создать публикацию; генерация и безопасный перенос предложений в черновики не меняются.
- **FR-021** Вопрос сервера о часовом поясе (`profile.timezone`, `timezone`, `company.timezone`) ведёт к существующей настройке компании «Актуальность» → «Часовой пояс», а не в «Настройки модуля»; блок «Планирование и согласование» ссылается туда же. Целевое действие остаётся необязательным.
- **SC-021** DOM-тесты FR-014…FR-021, отрицательная проба на `d8a77069`, мутации, весь кабинет; локальное демо на синтетике Palitra на настоящих CRM и сервисе контента; снимки 1366/390 с заполненной доской и открытой карточкой.

## Поправка CF3-R1 (поручение Влада через Codex, 01.10.2026)
База — дерево CF3-BOARD `3e5105c6`. Только `sites/` и `specs/053`, без новых API; комментарии с таймкодами и удаление — область Codex, в UI не имитируются.
- **FR-022** Окно публикации на ПК: слева файл, «Предпросмотр», проверка и согласование; справа поля в порядке «Название → Куда опубликовать → Формат и Цель (ОВП) → Дата и время → Текст → файл → свёрнутые подписи, опции, служебные поля». На телефоне — сначала поля, затем проверка и согласование; заголовок окна с «Закрыть» компактный.
- **FR-023** «Формат» и «Цель (ОВП)» — видимые поля вместо скрытой «Роли»; одна подпись цели «Охват / Влюбление / Продажи» на доске, в окне, в очереди и в предложениях плана (значения данных прежние).
- **FR-024** Одна метка статуса: доска, заголовок окна, строка «Статус: …» и список «Открыть материал» показывают одно и то же; после согласования, возврата или отправки на согласование метка обновляется.
- **FR-025** Одна явная кнопка «Согласовать · версия vN» / «Снять согласование» вместо галочки: существующий `POST /autoposting/posts/:id/approve {revision, approved[, platformIds]}`, права `autoposting.approve`, недоступна при несохранённом вводе; ничего не ставит в план. «Согласовать и поставить в план» остаётся отдельным, прямо названным действием.
- **FR-026** `beforeunload` спрашивает подтверждение только при несохранённом вводе — в открытом окне или отложенном в другой карточке.
- **FR-027** В строке действий только «Составить план» и «Создать публикацию»: ссылки «Предложения плана» в прежний модуль нет; предложения месяца — в «Составить план и предложения месяца». Старый адрес `#content-factory/plan/proposals` работает для прежних ссылок.
- **SC-022** DOM-тесты FR-022…FR-027, отрицательная проба на `3e5105c6`, мутации, весь кабинет; демо и снимки 1366/390 с проверкой в настоящем браузере.

## Пакет CF4-UI (поручение Влада через Codex, 01.10.2026)
База UI — дерево CF3-R1 `c51f3d32`. Контракт — `CONTENT_FACTORY_CF4_REVIEW_CONTRACT_20261001.md` (backend Codex, specs/054). Только `sites/` и `specs/053`.
- **FR-028** Компактная форма «Добавить замечание» в окне публикации: категория (Текст / Музыка / Изображение / видеоряд / Другое) и комментарий; время раскрывается кнопкой «Указать момент». Время допустимо для любой категории.
- **FR-029** Три вида привязки различаются явно: ко всему материалу (`whole`, без времени), момент в существующем файле этой версии (`material`, начало и файл обязательны, «Отметить текущий момент» берёт время из видео предпросмотра, известная длительность видео проверяется) и пожелание к монтажу без файла (`editing_wish`, начало обязательно). Конец не раньше начала.
- **FR-030** Несколько замечаний за один возврат (до 30) уходят одним существующим `POST …/reject` в `annotations`; статус — «На доработке». Права, CSRF, компания и ревизия прежние.
- **FR-031** История замечаний показывается по группам `reviewNotes`: версия содержимого, автор, время; файл и индекс — из снимка группы, а не из текущей версии. Текст выводится экранированным.
- **FR-032** Связанная задача — только из `reviewTasks`: номер, версия, статус, исполнитель/срок или «Не назначен» / «Срок не указан». Никаких обещаний исполнения или уведомления.
- **FR-033** Ответ 400 — «ничего не изменено», замечания остаются. Нет ответа, 409 или 5xx — карточка перечитывается, отправка не повторяется; успех показывается только по ответу сервера или по перечитанной карточке.
- **FR-034** Попутно: файл после предпросмотра показан один раз; пояснения согласования короче без потери смысла; «одобрить» → «согласовать»; состояние возврата — «На доработке». Подсказки «?» с примером у новых полей. Отдельная явная постановка в план сохранена; обычное согласование её не включает.
- **SC-028** DOM-тесты FR-028…FR-034, отрицательная проба на `c51f3d32`, мутации, весь кабинет; демо ПК/телефон на настоящем CRM неизменяемого снимка в собственной QA-копии.
## Пакет CF5-UI (поручение Влада через Codex, 01.10.2026)
База UI — дерево CF4-UI `a2f68ce6`. Контракт — `CONTENT_FACTORY_CF5_RECOVERY_CONTRACT_20261001.md` (backend Codex, specs/055). Только `sites/` и `specs/053`.
- **FR-035** «Удалить черновик» в окне публикации — для черновика, ошибки отправки и отменённого, только с правом правки и без несохранённого ввода. Сначала понятное подтверждение («Удалить «…»? Материал уйдёт в «Удалённые материалы»; текст, файлы, замечания и задачи сохранятся»), «Отмена» ничего не пишет; удаление — один `POST …/archive {revision}`.
- **FR-036** Запланированное удалить нельзя, пока оно не снято с публикации отдельной кнопкой «Снять с публикации»; отправляемое, опубликованное и с подтверждённой публикацией — без кнопки удаления.
- **FR-037** Удалённое не показывается как действующее: его нет на доске, в календаре, в «Открыть материал» и в выборе для согласования; открытие по ссылке или из предложений показывает его в «Удалённых материалах» с датой удаления, окно не открывается.
- **FR-038** «Удалённые материалы» — свёрнутый список внизу доски (`GET /autoposting/archived`, до 200, новые сверху): название, дата удаления в поясе компании, число замечаний; «Восстановить» — отдельное действие `POST …/restore {revision}`. Восстановленный — черновик без согласования и даты отправки; ничего не согласуется и не отправляется.
- **FR-039** Нет ответа, 409 или 5xx при удалении и восстановлении — карточка перечитывается (`GET /posts/:id`, читает и архив), повторной отправки нет; результат показывается по перечитанной карточке; 400/403 — «ничего не изменено».
- **FR-040** Повтор переноса предложения, вернувший `archivedAt`, отмечает черновик удалённым («Вернуть можно в «Удалённых материалах»»), новый не создаётся и удалённый не восстанавливается.
- **FR-041** Подсказки «?» с коротким примером у всех полей окна публикации (название, площадки, формат, ОВП, дата, пояс, текст, файл, подписи и опции площадок, день, происхождение, ссылки, служебные поля плана, возврат, отметка о публикации). Подпись связана с полем через `for`, «?» не входит в имя поля; подсказки доступны и при просмотре. Длинные пояснения под полями перенесены в подсказки.
- **SC-029** DOM-тесты FR-035…FR-041, проверка «Отметить текущий момент» по `video.currentTime` и повторного возврата с новой ревизией; отрицательная проба на `a2f68ce6`, мутации, весь кабинет; демо ПК/телефон на настоящем CRM неизменяемого снимка CF5 в собственной QA-копии, с синтетическим видео.
## Пакет CF6-UI (поручение Влада через Codex, 01.10.2026)
База UI — дерево CF5-UI `3d03f43a`. Контракт — `CONTENT_FACTORY_CF6_STATS_LINK_CONTRACT_20261001.md` (backend Codex, specs/056) и существующий `/social-stats`. Только `sites/` и `specs/053`.
- **FR-042** «Статистика контента»: один компактный дневной график выбранной площадки и показателя (просмотры / переходы по ссылке) только из `platforms[p].days[date][metric]` активной системы суток аккаунта (`activeInterval`). `totals`, `latest` и lifetime не подставляются. Подтверждённый 0 — точка; нет записи, `null` или нераспознанная разметка — разрыв; неполные и с неизвестной полнотой — отдельная метка. Есть текстовая сводка и таблица значений по дням; у выбора площадки и показателя — подсказки с примером.
- **FR-043** Нет подключения, только накопительные значения, нет права «Аналитика: просмотр» или сбой — ложного графика нет, причина словами. Поздний ответ прежней компании не рисуется.
- **FR-044** «Открыть материал» в таблице публикаций — только при положительном safe-integer `crm.posts[].autopostingId` и праве просмотра; внешняя ссылка остаётся отдельно. Переход на Контент-план, затем существующее `sb:content-factory-open-draft` с новым GET карточки; запрос из статистики помечен источником и ждёт загрузки вкладки.
