# Ручные отметки менеджера Palitra

Владелец: Codex lead_flow_review. Процесс 1.0.0. Зависимость: backend PR425.

## Сценарий
Менеджер после своей отправки отмечает «Фото готового заказа отправлено» и «Памятка по шарам отправлена», видит автора/время и может снять ошибочную отметку. Это ручное заявление, не доказательство доставки системой.

## Требования
- FR-001: две независимые отметки photo/guide только для сайта palitra компании palitra-love. Старые заявки по умолчанию без отметок; остальные компании без нового поведения.
- FR-002: каждая отметка хранит checked, revision, автора (тип/ID/подпись), время; каждое изменение, включая снятие, добавляет событие аудита атомарно.
- FR-003: явное значение вместо toggle; повтор не добавляет событие и не обновляет автора/время. Устаревшая версия не перезаписывает новое состояние.
- FR-004: ЛК — существующий owner+CSRF, автор берётся из сессии. Telegram — действующий оператор, личный чат и подтверждённое соответствие bot/chat/message/order из client_bot_map; чужая компания, подмена order и отключённый оператор отклоняются.
- FR-005: UI сообщает «Ручная отметка менеджера», показывает автора/время и понятное снятие. Telegram — две короткие дополнительные кнопки, обновление клавиатуры без сообщений клиенту.
- FR-006: отметки не меняют обработку заказа, доставку уведомлений, переписку или очереди. Автоматическая отправка фото/памятки и проверка её содержимого отсутствуют. Режимы и права не изменяются.
- FR-007: в Palitra верхний блок получателя подписывает результат как последнюю ручную проверку с датой; историческая ошибка сохраняется отдельно от доставки конкретных заявок, без автоматического повторного теста.

## Приёмка
- SC-001: unit тесты отметки/снятия/повтора/устаревшей версии/атома аудита и неизменности очередей.
- SC-002: HTTP owner/CSRF/isolation и Telegram mapping/operator isolation.
- SC-003: DOM автор/время/снятие/экранирование/конфликт и регрессии обработки/уведомлений.

Границы: без production, сообщений, установки бота, изменения прав, проектного чата и CRM. Привязка менеджера и доступный мост — внешние условия использования кнопок.
