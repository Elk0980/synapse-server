# Метки статистики только доказанной опубликованной версии

Процесс Spec Kit 1.0.0. Пакет CF27, исполнитель Codex; независимая приёмка выполняется root отдельно.

## Цель и сценарии

Формат и ОВП текущего черновика не должны приписываться ранее опубликованному содержимому. Владелец сохраняет квитанцию версии 1 с `post/reach`, затем меняет карточку на версию 2 с `reel/sale`: статистика прежней публикации возвращает обе метки `null`.

Если несколько квитанций одного канонического выхода доказывают одну текущую версию своей карточки, разрешены её метки. Если версии расходятся, неизвестны или отсутствуют, обе метки остаются `null`. Отдельная новая публикация текущей версии может иметь метки независимо от старой публикации той же карточки.

## Требования

- FR-001 Читать номер опубликованной версии из существующего `autoposting_publication_receipts.content_revision`; номер текущей версии из `autoposting_posts.content_revision`. Не выдумывать и не приводить неизвестную версию к 1.
- FR-002 Выдавать метки только при прежней доказанной однозначной связи `autopostingId` своей активной компании и единственной положительной безопасной целочисленной версии всех квитанций данного канонического выхода, равной текущей версии карточки. При несовпадении/неоднозначности обе метки `null`.
- FR-003 Сохранить whitelist `format: post/story/reel/carousel`, `ovpRole: reach/affection/sale`. Неизвестные значения отдельно остаются `null`; остальные `meta` не выходят в DTO.
- FR-004 Сохранить изоляцию компаний, защиту от fake/unknown/external IDs, конфликтующих карточек/contentId и усечения квитанций. Отсутствие таблиц, `meta` или колонок версии не ломает чтение и не доказывает метки.
- FR-005 Только read-only проекция в существующем DTO: не менять данные, квитанции, публичный состав receipts, идентификаторы/связь с обращениями; не выполнять миграции, API-запросы или сборы. Сохранить один ограниченный batch SELECT метаданных.

## Приёмка

- SC-001 Целевая регрессия с реальными локальными модулями autoposting/social-stats сначала падает на старом коде, затем проходит: `post/reach` -> receipt -> edit `reel/sale` -> старый выход `[null,null]`.
- SC-002 Проверены несколько равных/разных/неизвестных версий квитанций, раздельные старый и новый выходы одной карточки, spoof/unknown IDs, чужая компания, whitelist и legacy schema.
- SC-003 Тесты меток и существующий suite social-stats проходят; `total_changes()` подтверждает отсутствие записи при чтении. Evidence различает свои проверки и приёмку root.

## Границы

Разрешены только `ops/crm/social-stats.js`, существующий `ops/crm/social-stats-tags.test.js`, новые четыре документа этого каталога. Остальной код, QA, immutable packages, manifest/state — read-only. Без сети, UI, production, секретов, прав, публикаций, commit/push/deploy и новых агентов.
