# План CF27

Владелец выделенной области: Codex. Root выполняет отдельную приёмку и интеграцию. Владение не распространяется на autoposting, media-mentor, server, QA или manifest.

1. В `social-stats-tags.test.js` добавить целевую регрессию с настоящими `createAutoposting`/`recordReceipt`/`update` на синтетической SQLite in-memory БД; доказать красный результат до production-правки.
2. В `social-stats.js` читать существующую версию receipt с безопасным fallback `NULL` при отсутствии колонки. Держать версии только во внутренней проекции каждого канонического выхода; публичные receipts не расширять.
3. В существующий ограниченный batch SELECT метаданных добавить текущую версию карточки (при отсутствии колонки — `NULL`). Применять whitelist только после доказательства единственной равной опубликованной версии; неоднозначность даёт обе метки `null`.
4. Расширить fixtures меток реальными колонками версии и покрыть смешанные/неизвестные версии, равные дубли, независимые выходы одной карточки, old schema и IDs. Существующие guards компании/contentId/усечения сохранить.
5. Запустить только целевые локальные suites `social-stats-tags.test.js` и `social-stats.test.js`, проверить Spec Kit gate и соответствие FR/SC через converge, записать evidence и окончательные SHA, остановить запись.

Схема БД и публичный DTO не меняются; миграций нет. Сеть и внешние adapters в проверках отсутствуют. Риск ограничен более осторожным `null` при недостатке доказательств, в том числе на legacy schema.
