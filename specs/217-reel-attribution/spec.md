# 217 — Аналитика до денег: рилс → переходы → заявки → продажи → выручка → ROMI

Решение Влада 07.11.2026 (П6 Контент-завода, задача доски №217, родитель №212). Процесс 1.0.0.

## Цель
Каждая публикация Контент-завода несёт метку. Переход по ссылке из подписи на сайт компании, заявка с этой меткой, продажа и её сумма связываются с конкретным рилсом и его темой. На вкладке «Статистика» Контент-завода видно: рилс → переходы → заявки → продажи → выручка → ROMI. Только реальные строки CRM; где пусто — «нет данных», а не ноль.

## Точка А
- Заявки CRM уже хранят UTM (POST /leads, сшивка с визитом spec 112), визиты сайта — таблица `events` с UTM.
- Аналитика соцсетей (`/social-stats`, social-stats.js) связывает заявки с постами по URL поста или `utm_content = external_id` карточки, но только для постов, которые собраны с площадки или подтверждены владельцем. Продаж и выручки по рилсу во вкладке нет, ROMI по рилсу и теме нет.
- Подпись публикации не содержит ссылки с меткой: связывать нечего.

## Точка Б (первый срез)
1. Владелец на вкладке Контент → Статистика видит блок «Рилс → переходы → заявки → продажи → выручка» и переключатель «Включить метки» (по умолчанию выкл.).
2. После включения каждая новая отправка карточки на площадку получает в конце подписи строку «Подробнее: <сайт компании>?utm_source=<площадка>&utm_medium=social&utm_campaign=cf&utm_content=post-<номер карточки>».
3. Человек переходит по ссылке → визит с меткой → заявка CRM с той же меткой (форма или сшивка с визитом) → менеджер ставит «продажа» с суммой.
4. В блоке появляется строка рилса: площадки, переходы, заявки, продажи, выручка, ROMI (если расход рилса внесён в «Расходы» с источником `cf-post-<номер>`), и свёртка «По темам».

## Требования
- FR-1. Метка: `utm_source` = площадка канала (instagram, tiktok, youtube для youtube_shorts, vk, telegram, max), `utm_medium=social`, `utm_campaign=cf`, `utm_content=post-<id карточки autoposting_posts>`. Чужие `utm_*` в адресе сайта заменяются, прочие параметры и якорь сохраняются. Только http(s) без логина/пароля. 2ГИС (ручная площадка) метку не получает.
- FR-2. Настройка компании `reel_attribution_settings`: `enabled` (по умолчанию нет строки = выкл.), `label` (≤60, по умолчанию «Подробнее:»), серверная `enabled_at`, `revision` (409 при устаревшей). Меняет только владелец (CRM 403 и прокси 403); чтение — analytics.view своей компании.
- FR-3. Сайт — `profile.websiteUrl` последней подтверждённой версии данных компании (OD-2026-09-15-COMPANY-TRUTH). Нет сайта — ссылка не ставится, настройка возвращает причину.
- FR-4. Ссылка дописывается ТОЛЬКО в момент передачи транспорту (autoposting.processDue), сохранённые подписи карточки не меняются. Задним числом не меняется: ссылку получает карточка, у которой время решения (последнее согласование, общее или по площадке; без согласования — создание) не раньше `enabled_at`.
- FR-5. Если с ссылкой подпись превышает лимит площадки (план) или канала (`caps.maxText`, при медиа `caps.maxCaption`) — подпись уходит без ссылки, отметка `skipped_limit`. Пустая подпись (Story) — `skipped_empty`. Ссылка уже в подписи — `present`. Ошибка модуля меток не мешает отправке.
- FR-6. Каждое решение записывается в `reel_attribution_links` (карточка, канал, площадка, ссылка, статус, версия содержимого).
- FR-7. Связь заявки/визита с публикацией: та же компания, `utm_campaign=cf` (без учёта регистра), `utm_content=post-<N>`, карточка N принадлежит этой компании. Иначе — счётчик `unmatched`, ни одному рилсу не приписывается. Визит — только `type='visit'`; переход = уникальный `client_id` на рилс и площадку.
- FR-8. Отчёт `GET /social-stats/reel-attribution?companyCode&from&to`: по рилсу и площадке — переходы, заявки, продажи (этап «продажа»), выручка (сумма `sale_amount`), продажи без суммы отдельно; статус метки и доставки; по теме (исходная идея через связи адаптаций/продолжений) — суммы. Период — сутки UTC.
- FR-9. ROMI — за всё время метки: выручка всех продаж с меткой рилса против расходов этой компании с источником `cf-post-<N>`. Нет расхода — `null` с причиной; расход 0 — `null`.
- FR-10. Режим данных: `LIVE` — есть строки CRM; `NO_DATA` — ничего нет. SAMPLE этот срез не создаёт.
- FR-11. Вкладка «Статистика»: блок загружается вторым запросом; сбой, старый сервер (404) или ответ чужой компании не ломают остальную статистику и показывают честный текст.

## Не входит в первый срез
- Ссылка в «шапке профиля» (link-in-bio) для Instagram/TikTok — в подписи там ссылка не кликабельна.
- Блок в «Аналитике» кабинета (вкладка Аналитика) — следующий срез, тот же API.
- Короткие ссылки/редиректы, учёт кликов на нашей стороне, Метрика.
- Расход рилса как отдельное поле карточки (сейчас — строка «Расходы» с источником `cf-post-<N>`).
