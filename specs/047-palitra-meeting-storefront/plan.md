# План реализации

Используются существующие HTML/CSS/JS без сборки и существующий /api/site-orders/palitra.

1. config.js задаёт обратимый FLOWERS_VISIBLE и точные списки категорий/товаров/фото. price-render.js publicData создаёт публичную проекцию без мутации. Редактор передаёт editor:true. catalog-live.js, JSON-LD и индекс корзины используют ту же проекцию.
2. price-render.js сохраняет компактную карточку, переносит подробности в dialog и переиспользует галерею/корзину. styles.css сохраняет мобильные две колонки, добавляет горизонтальные категории и диалог.
3. Все 24 HTML подключают новую версию ресурсов и полную корзину; главная — короткий запрос. order.js валидирует согласованный с backend структурный контракт, условно переключает контакты, сохраняет старый payload без contactChannel. quiz.js переносит ответы в короткую заявку, в том числе без доступного товарного примера.
4. app.js и статическая подача скрывают известные цветочные элементы, сохраняют доступ к каталогу по прямым старым ссылкам. Неподтверждённые коммерческие условия убраны из публичных обещаний.
5. node:test + jsdom проверяют правила, реальную разметку, сценарии DOM и существующие функции. Spec Kit converge сверяет реализацию с требованиями; визуальная/live-приёмка — отдельная работа координатора.

Миграций данных в frontend нет. Новые поля: contactChannel, contact, telegramUsername; cart — deliveryAddress, deliveryDate, deliveryInterval, comment. Контакт хранится только в форме/запросе; browser storage хранит id/qty и отпечаток, прежний неперсональный черновик квиза сохранён.

Зависимость выпуска: сначала серверный пакет 007, затем этот frontend. При откате сервера откатить frontend до версии форм без contactChannel. Флаг цветов можно вернуть в true без правки прайса; после смены конфигурации перезагрузить страницу. Неподтверждённые цветочные позиции в смешанных live-категориях требуют точной проверки координатора, а не автоматической догадки.
