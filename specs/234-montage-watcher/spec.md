# Сторож очереди «Монтаж»

Задача №285, комментарий №1913, родитель №280. Код Codex, ревью Claude.

## Требования
- FR-001: один постоянный обработчик каждые 150 секунд читает GET `/internal/reel-materials/requests` и `/internal/reel-materials/queue` с существующим служебным ключом из окружения. Пустая очередь — ноль вызовов модели.
- FR-002: постоянный SQLite-журнал координации, атомарный захват и одна активная проверка; одна просьба/правка передаётся один раз. Связанная просьба redo и её edit считаются одной работой. После рестарта неизвестная отправка не повторяется вслепую.
- FR-003: сообщения без правки разбирает самая дешёвая из доступных настроенных моделей. Переиспользуется существующий изолированный Hugh `/status` + идемпотентный `/reply` (jobId), а при подключении в content — готовый fallback с его бюджетом. Нового провайдера, ключей, каталога моделей или бюджета нет. Известные тарифы сравниваются для одинакового входа/потолка ответа; неизвестная цена не считается нулём.
- FR-004: простой ответ сохраняется через существующий requests/:id/reply со статусом. Модель не получает инструменты, ключи и право публиковать; изменение монтажа передаётся действующему исполнителю через явно настроенный контракт. EDL передаётся детерминированно без вызова модели. Подтверждение доставки не выдаётся за готовую версию или фактический claim.
- FR-005: pending/accepted без фактического подхвата 10 минут, отказ обработчика или неизвестный результат → обычная задача CRM для Claude со ссылкой на ролик, стабильным sourceRef без дубля. Исходная очередь сохраняется. Ошибка чтения очереди также фиксируется задачей, без текста исключения.
- FR-006: компании/идентификаторы берутся из проверенного ответа CRM; операции содержат companyCode, повторная проверка остаётся в CRM. Нет браузерной личности/поддельного Owner. Секреты только из окружения; журнал stdout содержит только коды, время и счётчики. Переписка/ключи не журналируются.
- FR-007: старые просьбы и открытые сеансы поддерживаются; existing API/права/учётные записи/данные не меняются. Никаких отправок внешним людям, публикаций или обхода защиты. Сервис завершает запросы перед закрытием БД.

## Приёмка
Пустая очередь, смешанные компании, duplicate/restart/два экземпляра, reply с потерей ответа, crash при dispatch, таймаут 10 минут, сбой сети и отсутствие монтажёра. Настоящий CRM проверяет служебную авторизацию и sourceRef. Тесты выбора модели и отсутствия текста/ключей в журнале. Gate и отдельный PR со Spec. Выпуск отдельно после ревью, backup до сборки, rollback/health; реальный монтаж подтверждается новой версией, не локальной заглушкой.
