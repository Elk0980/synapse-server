# Spec 182: Постинг — удалить опубликованное с площадок

Поручение владельца 06.11.2026: «в опубликованных — удалить», в ЛК → Контент → «Постинг».

## Цель
У опубликованного материала есть действие «Удалить с площадок». Человек с правом `autoposting.edit`
видит, что Synapse снимет сам и что нужно удалить вручную, подтверждает и получает итог по каждой площадке.
Агент и фоновые задачи ничего не удаляют.

## Матрица площадок (официальная документация, проверено 06.11.2026)

| Площадка / путь публикации | Что говорит API | В Synapse (этап а) |
|---|---|---|
| Любая через Onlypult, пост ещё черновик/запланирован | `DELETE /posts/{id}` — «Delete a draft or scheduled post», 204 (onlypult.com/dev/openapi.yaml) | **Автоматически**, статус перечитывается `GET /posts/{id}` перед удалением |
| Любая через Onlypult, пост уже вышел | Удаления опубликованного в контракте нет | **Вручную** по ссылке |
| Telegram, прямой бот | Bot API `deleteMessage`: сообщение не старше 48 ч; бот с `can_post_messages` удаляет свои сообщения в канале | **Автоматически** для одиночного сообщения < 48 ч; альбом (хранится только первый message_id) и > 48 ч — **вручную** |
| ВКонтакте, прямой ключ | `wall.delete`: ключ пользователя (Implicit Flow) с правом `wall`; ключ сообщества в документации не указан | Этап (б); сейчас **вручную** |
| YouTube Shorts | `videos.delete`: OAuth владельца канала (`youtube`/`youtube.force-ssl`), 50 единиц квоты, 204 | **Нужна настройка доступа** (OAuth канала в Synapse нет); сейчас вручную, этап (б) |
| Instagram | IG Media поддерживает `DELETE` (посты, Stories, Reels, карусели) при собственном токене Instagram API | **Нужна настройка доступа** (сейчас только Onlypult); вручную |
| TikTok | Content Posting API: эндпоинта удаления опубликованного нет | **Только вручную** |
| MAX (через Onlypult) | Прямого подключения нет | **Вручную** |
| Отметка «опубликовано вне ЛК» | — | **Вручную** по сохранённой ссылке |

## Сценарии
1. Опубликованный материал → «Удалить с площадок» → окно со списком площадок: «удалит Synapse автоматически» / «удалите вручную», пояснение и ссылка на пост → «Подтвердить удаление» → итог по каждой площадке.
2. Для площадок «вручную» человек удаляет пост сам и нажимает «Я удалил вручную».
3. Повтор не трогает уже снятое; изменившийся список требует открыть окно заново.

## Требования
- FR-1 Сервер проверяет `autoposting.edit` (POST) / `autoposting.view` (GET) и компанию; чужой материал — 404.
- FR-2 Выполняется ровно список, показанный в окне (`targets` совпадает с планом сервера, иначе 409 `PLAN_CHANGED`); версия карточки сверяется (`REVISION_CONFLICT`).
- FR-3 Onlypult DELETE только при статусе `draft`/`scheduled`, перечитанном перед удалением.
- FR-4 Telegram `deleteMessage` только тем же подключением (ревизия канала совпадает с ревизией при публикации), иначе `CHANNEL_CHANGED` без вызова.
- FR-5 Отказ площадки → «не удалось», сетевая неопределённость → «не подтверждено»; удалением это не считается, автоповторов нет.
- FR-6 Журнал `autoposting_unpublish_events`: кто, когда, площадка, результат, ссылка, код ошибки. Карточка, доставки и расписки не стираются; состояние «снята» / «ожидает ручного удаления» вычисляется из журнала.
- FR-7 Одновременно одно снятие на карточку (`UNPUBLISH_RUNNING`).
- FR-8 Кнопка только с правом правки; окно на 390 px без горизонтальной прокрутки.

## Ограничения
Новых ключей, прав и фоновых задач нет. Реальные API в разработке и тестах не вызываются. Нет merge/deploy.
