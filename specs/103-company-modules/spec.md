# Модули компании в CRM

Задача доски №74. Статус: реализовано, проверено локально; не развёрнуто, не принято.

## Цель

Владелец Synapse видит и включает для конкретной компании-клиента модули каталога «Финансы → Модули и пакеты» с параметрами. Серверный код читает состояние модуля через `companyModule(code, key)`. Первый перевод на модули — адреса писем о новых заявках.

## Сценарии

1. Владелец открывает карточку компании CRM → вкладка «Модули»: все модули каталога, состояние, отметка «приобретён в сделке» со ссылкой на сделку, история изменений.
2. Модуль отмечен в сделке компании (`deal_orders.data.modules[].purchase = 'purchased'`) → кнопка «Включить — приобретён». Включение не выставляет счёт и не подтверждает оплату.
3. Владелец задаёт для модуля CRM получателей писем о заявках → письма компании уходят на эти адреса; без параметра или при выключенном модуле — прежние настройки компании.
4. Сотрудник без роли владельца не видит вкладку и получает 403 на API.

## Требования

- FR1 Таблица `company_modules` (company_code, module_key, enabled, params JSON, version, updated_by/updated_by_id/updated_at) и `company_module_audit` (before/after, автор, время). Миграция обратима, прежние таблицы не меняются.
- FR2 `module_key` — id каталога `commercial.js` (рабочая версия из БД). Модуль, удалённый из каталога, виден и может быть только выключен.
- FR3 `GET /company-modules?companyCode=`, `PUT /company-modules/<key>?companyCode=` — только владелец (проверка в content-прокси и в CRM), компания проверяется в CRM (активная, по коду), PUT — с CSRF (общий прокси), оптимистичная версия (409).
- FR4 Параметры — только описанные в схеме модуля; имена, похожие на секреты (pass/secret/token/smtp/api key), отклоняются. Секреты не хранятся.
- FR5 `companyModule(code, key)` → `{enabled, params}`; нет записи — выключен.
- FR6 Связка со сделкой: приобретённые модули сделок этой компании (по productId, для старых строк — по названию). Сделки других компаний не учитываются.
- FR7 Письма о заявках: включённый модуль `crm` с заданным `leadEmailRecipients` главнее прежних «Получателей заявок» этой компании; пустая строка — письма отключены; без параметра/выключен — прежнее чтение. ALVI/Авокадо без модуля — без изменений (тест). Отправитель SMTP и сохранённые пароли не затрагиваются.
- FR8 Экран «Модули» в карточке компании: desktop и 390 px, весь вывод через `escapeHTML`, ответ прежней карточки отбрасывается.

## Ограничения

Права людей не меняются. Счета, оплаты и рассылки не создаются. Развёртывание и включение модулей в рабочей системе — отдельное решение владельца.

## Правки по ревью (04.11)

- FR9 Имена параметров проверяются только по собственным полям схемы (`Object.hasOwn`): `__proto__`, `constructor`, `toString` — 400.
- FR10 Повреждённая строка истории не роняет раздел (показывается как «запись не читается»).
- FR11 Пустой список адресов при снятом «как в прежних настройках» — подтверждение «Письма о заявках этой компании перестанут приходить. Продолжить?».
- FR12 Диагностика почты (`email-diagnostics.js`) учитывает адреса из модуля; поле `recipientSource: 'module'` появляется только при переопределении.
- FR13 Модули каталога со статусом «в разработке» — подпись рядом с переключателем.
