# 214 · Автомонтаж Хью: черновик из дублей и правки «Редактировать» одним движком

Задача доски №214 (родитель №212, П3 «Контент-завод под ключ»). Решение Влада 07.11.2026.

## Цель

Из дублей съёмки по сценарию система сама собирает черновик ролика (порядок сцен, обрезка, титры из сценария, обложка),
кладёт его новой версией в «Материалы → Монтаж» и тем самым отправляет на согласование. Правки из окна «Редактировать»
(`kind:edl` — ручные правки на дорожке; `kind:request` — «Хью, измени…») исполняет тот же движок и даёт vK+1.

## Что уже есть (не переписывается)

- Очередь правок и служебный API монтажа в CRM: `ops/crm/reel-materials*.js` — `GET /internal/reel-materials/queue`,
  `POST …/edits/:id/claim`, `POST …/reels/:id/versions` (только ключ сервиса без личности). EDL v1 проверяется `validateEdl`.
- Дубли «Съёмки»: `ops/content/shooting.js` (`kind=take`, номер кадра = номер сцены сценария), локальное хранилище тома content.
- Разбор сценария: `sites/synapse/cabinet/shooting-script.js` (UMD; «ДО СЪЁМКИ: …» и строки «время | кто | реплика | в кадре | действие | титр»).
- Этап идеи: `ops/crm/content-stages.js` — у ролика идеи есть версии → «Монтаж на согласовании», открытая правка → «на доработке».
- Движка монтажа (ffmpeg) в репозитории не было: комментарий `reel-materials.js` ссылался на `tools/reels-check`, которого нет.

## Сценарии

1. СММ нажимает «Собрать черновик» у рилса со снятыми дублями → задание в очереди → воркер собирает ролик → в «Материалах»
   у ролика идеи появляется новая версия, этап идеи — «Монтаж на согласовании».
2. Пользователь в «Редактировать» переставил куски, вырезал лишнее, выключил звук, поставил 1,25× и нажал «Отправить» (`kind:edl`)
   → воркер собирает vK+1, правка закрыта; «Исправлено: … готова vK+1» появляется в личном чате автора с Хью существующим
   путём (`reel-materials-chat.js` подтягивает журнал правок при открытии чата; push-уведомления этот срез не добавляет).
3. Сборка не удалась (битый файл, нет места, таймаут) → честная причина в задании; после 2 попыток задание не крутится по кругу.
4. Флаг выключен или компания не подключена → кабинет получает 503 `MONTAGE_OFF`, воркер не берёт заданий.

## Требования

- FR-1. Один движок рендера (`ops/montage/render.js`): план = входные файлы + видеоклипы + аудиоклипы (громкость 0…2, без звука) +
  титры + скорость 1/1,25/1,5. Клипы за концом исходника обрезаются по его длине; пустая дорожка — ошибка `EMPTY_TIMELINE`.
- FR-2. EDL v1 «Материалов» исполняется буквально: порядок клипов = порядок на дорожке, `inMs/outMs` — вырезки, звуковая дорожка
  отдельно (короче видео — тишина, длиннее — обрезка), титры на шкале до ускорения, кадр обложки `coverMs`.
- FR-3. Результат — MP4 H.264/AAC, кадр по умолчанию 1080×1920 (вертикаль для всех шести площадок), `+faststart`, плюс JPEG обложки.
- FR-4. Правка `kind:edl`: воркер берёт её (`claim`), качает базовую версию только из хранилища публикаций своей компании,
  собирает, загружает результат и пишет версию через существующий `POST …/reels/:id/versions` с `editId` → правка `done`, vK+1.
- FR-5. Черновик: сцены — кадры сценария; на сцену — последний дубль (`kind=take`, `frame=n`, наибольший id). Сцены без дубля
  пропускаются и перечисляются в заметке версии. Дубли с «Другое» (без номера) не используются.
- FR-6. Обрезка черновика: у реплик (`type=line`) срезается тишина в начале и в конце (`silencedetect`, −35 дБ, 0,35 с; запас 150/250 мс);
  у вставок и действий дубль берётся целиком. Совсем тихий дубль не режется.
- FR-7. Титры черновика — колонка «Титр» сценария на время своей сцены. Без титров — так и пишется в заметке.
- FR-8. Версия черновика пишется к ролику идеи (`reel_materials.idea_id`, в т. ч. через перенесённую публикацию); ролика нет —
  создаётся с названием темы идеи, датой и площадками идеи. Повторная сборка — vK+1 того же ролика.
- FR-9. Обложка загружается в хранилище публикаций компании; ссылка — в заметке версии (отдельного поля обложки у версии пока нет).
- FR-10. Безопасность: воркер — отдельный контейнер во внутренней сети без выхода наружу, знает только `content`; ключ воркера
  отдельный (в content хранится его SHA-256), ключа CRM у воркера нет; шлюз пускает только компании из `MONTAGE_WORKER_COMPANIES`;
  ffmpeg/ffprobe — `-protocol_whitelist file`, аргументы массивом без оболочки, текст титров через `textfile`, `expansion=none`.
- FR-11. Ресурсы: одно задание за раз; лимиты CPU/памяти контейнера; проверка свободного места до скачивания (≈3× исходников +
  запас); лимит размера исходника и результата; таймаут процесса ffmpeg; рабочая папка задания удаляется всегда.
- FR-12. Флаг по умолчанию выключен: content — `MONTAGE_ENABLED=1` + `MONTAGE_WORKER_KEY_SHA256` + `MONTAGE_WORKER_COMPANIES`
  (все три), воркер — `MONTAGE_WORKER_ENABLED=1`. Без override-файла compose сервиса воркера нет.
- FR-13. Сбой: правка `kind:edl` и задание черновика получают причину; после 2 неудач — статус `failed`, повторов нет.
