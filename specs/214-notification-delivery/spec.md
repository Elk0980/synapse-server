# 214 — Рассылка уведомлений Контент-завода по матрице «этап × роль»

Решение Влада 07.11.2026. Процесс 1.0.0. Продолжение specs/208-notification-matrix (выбор «кому о каком этапе») и specs/209-cf-stages (этап идеи считает сервер).

## Цель
Когда этап рилса меняется сам по действию людей, нужные роли компании узнают об этом один раз: «№N тема — новый этап: …, ссылка в кабинет». По умолчанию ничего не отправляется; владелец включает рассылку для своей компании, сначала можно включить «пробно» — только журнал.

## Сценарии
1. Владелец открывает Настройки → Контент-план → «Уведомления»: под матрицей переключатель «Отправлять уведомления» — «Выкл.» (по умолчанию), «Пробно», «Вкл.».
2. Владелец на вкладке «Участники» отмечает, кто в ролях «Контент (СММ)», «Съёмка», «Монтажёр». Владелец — учётные записи-владельцы; согласующий — уже существующий выбор «Кто согласует контент-план».
3. Включено «Пробно»: первый проход запоминает текущие этапы. Оператор загрузил дубли — идея перешла «Запланировано → Отснято»; в журнале появляются строки «№N тема · Запланировано → Отснято · СММ (Контент) — ушло бы», ничего никому не уходит.
4. Включено «Вкл.»: то же событие ставится в существующую очередь уведомлений людей (people) — push или Telegram из профиля человека, если он сам включил уведомления. Иначе журнал честно пишет причину.
5. Настройщик (settings.edit) видит режим и журнал, но не может менять режим.
6. Выключение сбрасывает запомненные этапы; повторное включение снова начинается без рассылки старых этапов.

## Требования
- FR-1. В настройках контента компании необязательные ключи: `notificationDelivery` ∈ `off|trial|on` (нет или повреждено — `off`); `rolePeople` = `{content:[id], shooting:[id], editor:[id]}` — люди с доступом к компании, без повторов (иначе 400). PUT без ключей сохраняет прежние значения.
- FR-2. Режим меняет только владелец (`role=owner`); другой пользователь с settings.edit может прислать прежнее значение (403 при попытке изменить). Каждый выход из `off` ставит серверную отметку включения (`deliveryEnabledAt`, `deliveryEpoch`) — клиент её не задаёт.
- FR-3. Детектор раз в минуту обходит только компании с режимом `trial|on`. Этапы читаются из CRM действием people `contentStages` (только владелец, только своя компания) с доверенными фактами съёмки своей компании; при обрезанных/недоступных фактах проход пропускается (без ложного отката этапа).
- FR-4. Первый проход после включения (новая отметка) только запоминает этапы. Новая идея в плане — запоминается без события. Удалённая из плана — забывается.
- FR-5. Переход этапа известной идеи — событие `{company, ideaId, from, to}` с ключом `cf-stage:<company>:<ideaId>:<seq>:<to>`; `seq` растёт на каждый переход, поэтому повторный настоящий переход (доработка → согласование → доработка) — новое событие, а повторный проход без изменений — нет.
- FR-6. Получатели: роли из матрицы компании для этапа `to` → люди: владелец — учётные записи-владельцы с доступом к компании; согласующий — `approverUserIds`; контент/съёмка/монтажёр — `rolePeople`. Человек в нескольких ролях получает одно сообщение. Этапы вне матрицы (черновик, в монтаже, запланировано к выходу) только запоминаются.
- FR-7. Текст: заголовок `№N тема` (≤120), тело «Новый этап: … (было: …). Открыть в кабинете: <CABINET_PUBLIC_URL>#content/plan» в одну строку; push-ссылка `/cabinet.html#content/plan`.
- FR-8. `trial` — строки журнала со статусом «ушло бы», очередь не трогается. `on` — `people-notifications.enqueue` (согласие человека, право получать, уникальность по событию/каналу). Если глобальная доставка people выключена (`PEOPLE_NOTIFICATIONS_ENABLED`/`…_TEXT_APPROVED`), в очередь не ставится — статус «отправка на сервере выключена».
- FR-9. Перед отправкой очередь people проверяет событие: режим всё ещё `on`, этап идеи и `seq` не изменились, человек всё ещё в нужной роли. Иначе событие отменяется (`SOURCE_CHANGED`).
- FR-10. Журнал `GET /content/content-stage-notify/log?companyCode=` — последние 50 строк своей компании для владельца и settings.edit (иначе 403): кто, роли, переход, статус, причина.
- FR-11. Изоляция: снимки, журнал, получатели и проверка события — только по своей компании; человек другой компании не назначается в роль и не получает.

## Приёмка

## Ограничения
Новые каналы, боты и секреты не заводятся. Доставка — существующая очередь people с её согласием и глобальным выключателем. Права учётных записей не меняются: получать через people может владелец или исполнитель компании (`human_executor`), остальным журнал пишет «нет права получать». Реальных отправок в тестах нет. Сервер выпускается вручную (Root, managed-release).
