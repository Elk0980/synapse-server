# №193 · Автосинхронизация контент-плана с Google Таблицей

Цель владельца: «автоматическая синхронизация с Google Таблицами, работает без ИИ». Вариант A.

## Сценарии

1. Менеджер меняет план в ЛК → в течение минуты служебный лист таблицы компании обновляется, меняются только изменённые строки.
2. Команда меняет «Статус» или «Правки/Комментарии» в листе → в ЛК приходит предложение; план не меняется, пока человек не примет решение существующим согласованием.
3. Обе стороны изменили одну строку → в лист пишется значение ЛК, правка листа сохраняется предложением с conflict=true.
4. Google недоступен или ключ не задан → очередь сохраняется, статус показывает причину.

## Требования

- FR-1 Эталон — ЛК (OD-2026-09-15-COMPANY-TRUTH); модуль не пишет в план ЛК.
- FR-2 Ссылка — существующее поле contentPlanSheetUrl; spreadsheetId извлекается по тем же правилам, что валидация настроек.
- FR-3 Пишется только лист «Synapse · план», колонки A–H: ideaId, №, Дата, Тема, Формат, Площадки, Статус, Правки/Комментарии. Ручные листы и строки без нашего ideaId не меняются.
- FR-4 Дифф: записываются только изменённые строки; пустая пачка не отправляется.
- FR-5 Ночная полная сверка раз в сутки (по умолчанию 20:00 UTC).
- FR-6 Импорт раз в 5 минут, только при новом Drive modifiedTime, только колонки A, G, H; результат — onProposal({companyCode, ideaId, field, value, source:'google-sheet', lkValue, conflict}). Одно и то же предложение повторно не отправляется; при ошибке onProposal предложение повторяется.
- FR-7 Очередь в SQLite (CREATE TABLE IF NOT EXISTS), экспоненциальная задержка повторов, задача не теряется.
- FR-8 Авторизация сервисным аккаунтом: JWT RS256 через node:crypto, кеш токена; без GOOGLE_SHEETS_SA_JSON — состояние «не подключено» без сетевых запросов. Без новых npm-зависимостей.

## Приёмка

Тесты node:test для FR-2…FR-8 на заглушке fetch и временной SQLite проходят; `gate.py check` проходит; инструкция подключения в docs/google-sheets-sync.md.

## Ограничения

Не трогать server.js и существующие файлы, не регистрировать модуль, без миграций боевой базы, без реальных ID таблиц и секретов в репозитории. Спецификация не разрешает подключение к реальным таблицам, публикацию или развёртывание.
