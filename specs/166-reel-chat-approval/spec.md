# 166 · Согласование рилса в чате компании и ссылки на публикации

Поручение владельца 05.11.2026 17:22 (Бангкок): «Лене отправляй прямо в чате рилс, чтобы его можно было посмотреть и согласовать там же; после отправки все ссылки на соцсети, в которых прошла публикация, скинь ей в чат». Доска: №166 (модуль №98).

## Цель
Согласующий (например, Лена) смотрит рилс прямо в общем чате компании и одним нажатием согласует его или просит правки. После публикации в тот же чат приходит сообщение со ссылками на опубликованные посты по каждой площадке. Новой системы согласования, задач или публикации нет: чат показывает и вызывает существующие.

## Сценарии
1. СММ открывает «Контент → Материалы → рилс» и нажимает «Отправить на согласование в чат». Выбирает площадки, проверяет подпись к публикации. В общем чате компании появляется карточка рилса: встроенный плеер (playsinline, controls, постер), название, подпись, площадки, версия, кто отправил, статус «Ждёт согласования» и кнопки «Согласовано» / «Нужны правки».
2. Лена в «Чатах → Общий чат компании» смотрит ролик в карточке и нажимает «Согласовано». Срабатывает существующее согласование версии публикации для выбранных площадок; карточка показывает «Согласовано», кто и когда.
3. Или нажимает «Нужны правки»: окно с текстом, по желанию — кадр из плеера или свой скриншот. Правка уходит существующим requestEdit «Материалов» (задача монтажа на общей доске). Карточка показывает «Нужны правки» и номер задачи.
4. Согласованный рилс публикуется существующим путём автопостинга: «Постинг» → время → отправка. Автоматической публикации без человека для этих компаний нет, поэтому карточка показывает «Согласовано — ждёт публикации», а после постановки в план — дату.
5. Когда площадки вернули результат, в тот же чат приходит сообщение: по каждой площадке реальная ссылка из ответа площадки, либо «опубликовано, ссылка недоступна» с ID, либо ошибка. Повтор синхронизации не дублирует сообщение.

## Требования
- FR-1 Кнопка «Отправить на согласование в чат» — у рилса в «Материалах» для права `autoposting.edit` (как остальные изменения материалов). Сервер проверяет право, компанию и CSRF как существующие маршруты `/autoposting/reels…`.
- FR-2 Отправка привязана к публикации автопостинга для выбранной версии ролика: переиспользуется черновик ролика с тем же файлом, иначе создаётся существующим `createPublication`. Пустая подпись без подписи у черновика отклоняется до создания черновика (400). Изменение подписи и площадок — существующий `autoposting.update`; карточка переводится «на согласование» существующим `submitReview`.
- FR-3 Карточка в общем чате компании (комната `common` рабочего чата) создаётся один раз на запрос (повтор с тем же ключом не дублирует). Предыдущий неотвеченный запрос по тому же ролику помечается «Заменено новой отправкой».
- FR-4 «Согласовано» вызывает существующее `autoposting.approve` (версия содержимого, выбранные площадки). Право — владелец или `autoposting.approve`, как у согласования в «Постинге»; проверяется в content proxy и в CRM. Статус «Согласовано», кто и когда берутся из согласования публикации, поэтому согласование, сделанное в «Постинге», карточка показывает так же.
- FR-5 «Нужны правки» вызывает существующий `requestEdit` (вид `request`, базовая версия запроса, отрезок — отмеченный момент или весь ролик). Право `autoposting.edit`. Скриншот — только изображение из хранилища публикаций той же компании и разрешённого origin; ссылка добавляется в текст правки. Повторная отправка того же запроса не создаёт вторую задачу.
- FR-6 Если подпись, файл или площадки публикации изменились после отправки в чат, кнопки отключаются, статус «Публикация изменилась — отправьте заново» (409 на сервере).
- FR-7 Сообщение о результатах публикации содержит только реальные данные: ссылку доставки из ответа площадки (прямые Telegram/ВКонтакте), подтверждённую владельцем ссылку «опубликовано вне кабинета», иначе «опубликовано, ссылка недоступна» и ID (Onlypult: ID задания). Ошибка/неподтверждённый результат — тоже сообщением с понятным текстом. Одна площадка с одним итогом сообщается один раз.
- FR-8 Изоляция: запрос, публикация, ролик и скриншот принадлежат одной компании; чужие ID → 404/403. Служебный маршрут синхронизации — только ключ сервиса без личности браузера.
- FR-9 Видео отдаётся из существующего хранилища `publishing-assets` с текущей защитой (случайное имя, CSP sandbox, диапазоны), без новых маршрутов отдачи.
- FR-10 Вёрстка: телефон 390 px и ПК 1440 px — плеер вписан в пузырь, кнопки одной высоты 44 px, горизонтальной прокрутки нет. Плеер не пересоздаётся при опросе чата (воспроизведение не прерывается).

## Ограничения
- Ничего не публикуется из чата напрямую; новых прав, ключей и режимов ботов нет; деплоя и слияния нет.
- Onlypult по проверенному контракту (openapi.yaml 1.0.0, Post: id/status/content/profile_ids/published_at/media/error — без url) ссылку на опубликованный пост не отдаёт: ссылки по площадкам через Onlypult не выдумываются и не подбираются по времени/тексту.
- Видео, переписка и данные клиентов в репозиторий не попадают; тестовые ролики синтетические.
