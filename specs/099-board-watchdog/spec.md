# Сторож доски — №59, исправление ревью220

04.11.2026, Бангкок. Scope: CRM guards/наблюдение/доказательства, служебная передача task identity из существующих кабинета и MCP. Merge/deploy/рассылка не разрешены.

## Требования и поведение

- Режим по умолчанию observe: сохраняются прежние этапы/done, несовпадения пишутся как наблюдения. Только явный TASK_WATCHDOG_MODE=enforce включает ограничения. Перезапуск в observe снимает действие старых блокирующих триггеров без удаления данных/истории.
- Личность устанавливают внутренние сервисы, не author/agent/userName. Кабинет после проверки сессии и CSRF заменяет входящий task header; owner-session означает Влада с фактическим userId. MCP прошедший проверку ключ закреплён за конкретным agents.id; CRM проверяет agent_access owner/projects, повторно перед записью. Подпись существующим внутренним CRM ключом ограничена identity hash, method/path и60сек; ключ агентам не передаётся.
- Один общий ключ не представляет разных агентов по строке имени. Поддержаны отдельные ключи в одном MCP-сервисе с конфигурационной привязкой к registry ID и подмножеству проектов. Права Claude/release назначаются серверными registry ID, не полем kind реестра.
- HTTP вызывает authorize до записи и вне SQLite-транзакции: code — назначенный агент + существующий GitHub PR/коммит + зелёный CI точного SHA; connected — выделенный release/Claude + exact health.version; verified — назначенный независимый проверяющий + HTTPS evidence без credentials; accepted — только Влад.
- Результат проверки и principal ID фиксируются атомарно с ревизией/историей. Изменившийся assignment/данные/agent_access отменяют ранее полученный permit. В сводке отделены удостоверенные сторожем и прежние/не удостоверенные записи.
- В enforce done разрешён по удостоверенному accepted или при явном codeRequired:false от Влада + удостоверенном verified + комментарии Влада. cancelled не меняется. Кнопка диспетчера «Принять» сначала фиксирует accepted Влада, затем done в одной транзакции. В observe прежнее закрытие не блокируется.
- Отчёт засчитывается только под личностью исполнителя: authenticated task_comment либо agent_report с явным #id/№id и совпадением registry ID исполнителя. Чужой/неподписанный author, heartbeat и правка blocker не снимают тишину. Прошлые свободные author не считаются удостоверенными.
- in_progress без отчёта45мин получает no_report, ≥180мин — в digest. Текст: «ждёт исполнителя <имя>». После открытия старой страницы/перезапуска данные читаются из той же базы.
- Вопрос30мин даёт reminder-data. Сводка собирается из переходов истории за сутки, боевых коммитов, тишины/причин и ожидания Влада; локальные снимки08/20 Bangkok. Delivery выключен.
- Daily sample1–2 verified/accepted: GitHub/health; пустой healthURL — «Пропуск: health не настроено», не тревога. Недоступность настроенного источника — тревога о неподтверждении, не заявление об обмане.
- История и provenance неизменяемы UPDATE/DELETE/REPLACE. Частичные обновления сохраняют старые/неизвестные метаданные, независимые стадии, ссылки, IDs и пользовательские данные.

## Границы

Новые ключи не генерируются и не устанавливаются этой веткой. Для включения enforce нужны реальные credential→agent_access привязки, доверенные role ID и health deployment config. Это условия эксплуатации, а не оставшийся отсутствующий issuer в коде. Старый общий ключ без привязки продолжает работать в observe, но не удостоверяет агента. TOOLS/ops/tasks-mcp/tools.js не меняются; контракт PR477 при объединении server.js необходимо сохранить.

UI «Ждут…», кабинетные уведомления и owner-only Telegram остаются интеграциями полного №59; рассылка до просмотра текста Владом не включается. Результат этого исправления — серверный кандидат для повторного ревью220, не утверждение production-приёмки.
