# Сторож доски — №59

Дата: 04.11.2026, Бангкок. Авторизация: поручение Влада в чате Codex.

## Цель и требования

- Сервер проверяет доказательства и роли: code исполнитель + GitHub PR/коммит и CI точного SHA; connected выпускающий/Claude + настроенный health.version; verified независимый проверяющий + ссылка; accepted только Влад.
- Без принятия статус done запрещён на MCP, кабинете, selfStatus, legacy CRUD и dispatch через общий SQL guard. Исключение для задач без кода требует verified и доверенного решения Влада.
- in_progress без комментария исполнителя/явного отчёта #id 45 минут получает no_report, от 180 минут попадает в digest. Правка blocker и общий heartbeat не доказывают работу над задачей.
- Открытый ВОПРОС → получатель после 30 минут отображается как reminder-data до ОТВЕТ → от получателя. Это формат явного ответа, а не автоматическое понимание текста.
- Сводка из базы: переходы стадий за сутки по истории без повторов, connected-коммиты, тишина, причины, ожидание Влада. Снимки сохраняются утром/вечером 08/20 Bangkok. Рассылка выключена.
- Daily random sample до двух verified/accepted задач перепроверяет GitHub/health; отсутствие доказательства или недоступность источника — тревога, а не утверждение об обмане.
- История защищена от UPDATE, DELETE и REPLACE. Старые задачи, IDs, данные и доказательства не удаляются.

## Ограничения текущего draft

В main MCP использует общий Owner, автор — свободный текст. Это не trusted principal. Вопрос Claude №59/191, зависимость №55. Текущий production guard отклоняет все НОВЫЕ подтверждения; положительный authorize API только модульный контракт, HTTP issuer не подключён. Поэтому PR нельзя выпускать как готовое ТЗ. Прежние подтверждения читаются как исторические, не считаются новой внешней проверкой.

Осталось: trusted issuer, атомарная запись его личности/проверенных receipt в журнал; no-code исключение; exact health deployment config; UI «Ждут Claude» и тревоги в №26; подключение существующего owner-only Telegram после просмотра текста Владом. Поля author/agent по-прежнему самодекларация, поэтому отчёт об активности также не является удостоверением личности. Никаких ключей, изменения MCP tools.js/списка инструментов, merge/deploy и исходящих сообщений в этой ветке.
