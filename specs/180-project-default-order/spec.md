FR2: журнал user_project_prefs хранит user_id,company_code,last_picked_at,request_id. Счётчик за30дней вычисляется, последнее использование учитывается даже после30дней. UNIQUE(user_id,request_id) предотвращает повторный счёт после неизвестного ответа.

FR5: открытый сеанс/поздняя загрузка модуля, старая сохранённая компания, разные пользователи и отсутствие доступа обрабатываются без потери данных. Режим просмотра сотрудника предпочтения не меняет.
FR6: новая таблица/индекс создаются идемпотентно; существующие настройки/auth/session неизменны. FK ON DELETE CASCADE сохраняет прежнюю возможность удалить пользователя без висящих личных настроек. Реальный выпуск/миграция production не выполнялись.
FR7 (перенос на main, PR без #568/#519): cabinet.html и shell-modules.json не меняются.
