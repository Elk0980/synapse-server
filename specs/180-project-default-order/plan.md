Исправленная PR568 включена merge0aef0ee2 в ветку. Серверный модуль user-project-prefs — единственный журнал выбора; идентичность определяется сессией, никогда входным userId. whoami получает настройки синхронно из локальной БД до ответа, поэтому не нужен второй запрос для выбора default. Минимальная интеграция cabinet.html: чтение серверного last перед первым render, очередь выборов с requestId и передача prefs в контекст модуля. Это необходимо для устранения мигания и фиксации программного chooseProject даже при поздней загрузке модуля. Старый локальный выбор один раз попадает в журнал, если серверного ещё нет. Модуль сохраняет PUT, сортирует только существующие пункты и кэширует ответ. Сеть с неизвестным исходом оставляет тот же requestId. Production не затронут.
