# План

Изолированная codex/people-push-20261103 от ac4c7616. Один писатель на файлы: root — content API/runtime/client и документация; помощники — выделенные части. Первоначальный a50205b не менял ops/crm. После ревью Claude №86 и прямого поручения Влада добавляется только узкая CRM-авторизация people API и native selfStatus с историей от настоящего userId. Страница доски №26 и её Owner/MCP API не расширяются.

Человек передаётся в CRM с реальной ролью editor, единственной выбранной компанией и одним фактическим правом операции: tasks.self.view/edit или content-plan.approve. Узкий /internal/people API повторяет ACL на стороне CRM; человек не подменяется owner и не получает crm.edit. Существующие Owner/MCP guard сохраняются. Назначение person:id и родительская цепочка проверяются до выдачи данных, запись статуса — в одной транзакции с CAS и историей actual userId. Пятничный фон читает источник от настоящего свежего владельца, сохранившего правило, не от получателя с фиктивными правами; старое правило без owner metadata требует явного сохранения владельцем.

Добавочные таблицы в content SQLite содержат настройки, подписки, правила и delivery ledger с FK к auth_users. Нет нового реестра людей, цен, согласований или задач. Web-push библиотека и lock поставляются в content image; секреты — только runtime env, в Git нет ключей/подписок/идентификаторов частных чатов. Telegram resolver читает существующую связь пользователя и членство проекта, не использует owner fallback.

Пятничный планировщик читает существующий DTO Медиа-наставника; не вызывает autoposting.list/get/invalidate, не меняет материалы. Смена прав/opt-in перепроверяется перед доставкой. Ошибка транспорта не включает повтор отправки UNKNOWN.
