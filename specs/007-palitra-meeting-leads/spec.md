# Заявки Palitra: контакт, доставка и рабочая группа

Статус: реализация. Владелец серверной части: Codex lead_flow_review. Процесс 1.0.0.

## Сценарии
- US1: клиент оставляет короткую заявку с именем, удобным каналом и контактом; телефон нужен только для звонка/WhatsApp.
- US2: клиент оформляет корзину с адресом, датой, интервалом доставки и необязательными пожеланиями. Менеджер видит эти поля в ЛК и уведомлении.
- US3: любая новая заявка Palitra независимо от клиентского канала получает отдельное уведомление в текущую рабочую Telegram-группу. Личное уведомление менеджера сохраняется независимо.

## Требования
- FR-001: каналы phone/telegram/whatsapp/max; name до80, contact до100, phone до32 (10–15 цифр), Telegram @ник 5–32 латинских символа/цифры/подчёркивание, первый символ буква. MAX: телефон либо идентификатор/HTTPS-ссылка, без email/опасных схем.
- FR-002: новые cart с contactChannel требуют deliveryAddress до500, действительную deliveryDate YYYY-MM-DD, deliveryInterval до80. comment до1000. Поля сохраняются структурно.
- FR-003: без contactChannel прежние phone, occasion/date и fingerprint сохраняются. Повтор requestId не создаёт уведомлений; изменение любого значимого нового поля даёт409.
- FR-004: заявки и обе очереди создаются атомарно. Группа берётся только из текущей привязки своей компании; личный recipient остаётся положительным ID. Нет AI jobs, email, изменения прав или привязок.
- FR-005: групповые задания идут только через project_bot. Смена личного получателя/транспорта их не отменяет; смена группы останавливает ещё не отправленные задания в старую группу. Неизвестный результат не повторяется автоматически. Поздний ACK одного назначения не меняет статус другого.
- FR-006: ЛК показывает личную и групповую доставку раздельно, честно сообщает об отсутствующей привязке и позволяет владельцу явно повторить только нужное назначение с CSRF. Чужая компания недоступна через ID заявки.
- FR-007: существующие заявки не рассылаются ретроспективно. Групповой канал включён только для Palitra; ALVI и клиентские диалоги сохраняют прежнее поведение.

## Приёмка
- SC-001: unit/integration тесты подтверждают все четыре канала, доставку, legacy и идемпотентность на синтетических данных.
- SC-002: тесты доказывают изоляцию компаний/транспортов/назначений и отсутствие AI jobs.
- SC-003: DOM тест показывает структурные данные безопасно и независимые кнопки повторов. Рабочая система проверяется координатором после разрешённого релиза отдельно.

## Границы
Без production-изменений, сообщений, установки нового бота, настройки личного оператора, DNS и чек-листа менеджера. Frontend sites/palitra-love — отдельный единственный писатель site_meeting_upgrade; его зависимый контракт включает условный Telegram, обе формы, новый fingerprint без сохранения PII в browser storage. Скрытые товары и карточки относятся к отдельному frontend-пакету.
