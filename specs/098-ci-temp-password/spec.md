# №98: HTTP-тест после перехода на временный пароль

## Цель

Вернуть выполнение HTTP-проверок доступа после принятого PR492. Тест создания второго участника отправляет запрещённый постоянный пароль и получает 400 вместо 201, поэтому последующие проверки изоляции и отзыва доступа не выполняются.

## Требования

- FR1: тест создаёт участника действующим API без поля password, получает temporaryPassword, проходит обязательную смену и входит с личным тестовым паролем.
- FR2: ограниченный вход подтверждает mustChangePassword; CSRF берётся из ответа этой сессии, а не из сессии владельца.
- FR3: все прежние проверки после создания участника сохраняются; рабочий код авторизации, права, БД и серверные настройки не меняются.

## Приёмка

Исходный people-http.test.js проходит на актуальном main. Патч также совместим с дополнительными HTTP-проверками комнат в интеграционной ветке №520. Локальная репетиция и CI фиксируются раздельно; успешный тест не означает выпуск или независимую приёмку Claude.
