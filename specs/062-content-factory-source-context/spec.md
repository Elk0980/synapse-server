# CF12 — исходники компании в контексте подготовки плана

Процесс Spec Kit1.0.0. Исполнитель: Codex. Область поручена координатором Влада01.10.2026.

## Сценарии и приёмка

1. При новом запуске предложения учитывают доступные подписи и сведения библиотеки своей компании. В задаче остаётся точный снимок, поэтому последующие изменения библиотеки не меняют задание.
2. Повтор прежнего ключа возвращает прежнюю задачу после изменения исходников или вводных; другой месяц с тем же ключом отклоняется.
3. Модель может сослаться на исходник только через `source:<id>` из сохранённого снимка. Это предложение материала, без прикрепления, согласования или публикации.

## Требования

- FR-001. Content читает только последние100 записей stored/text своей компании из существующей библиотеки. Снимок содержит schemaVersion1, companyCode, total, truncated, assets и hash; общий JSON≤65536байт. total учитывает все доступные записи, truncated равно total>assets.length. При ограничении размера сохраняются целые записи.
- FR-002. У материала только id, revision, sha256|null, name, mime, size|null, status, caption, metadata. Нет файлов, delivery URL, disk/chat/message/author IDs, credentials или provenance. Подписи и допустимые metadata сохраняются целиком. hash детерминирован по рекурсивно отсортированным ключам JSON без hash.
- FR-003. CRM принимает manifest только отдельным серверным аргументом create; body по-прежнему содержит только month/clientRequestId. Компания, поля, типы, порядок, уникальность, пределы и hash строго проверяются до сохранения точного snapshot.sourceLibrary.
- FR-004. lookupRequest(company,key,month) возвращает прежний DTO до чтения context/inputs. Ключ другой компании независим, другой месяц с тем же ключом409. Fingerprint уже записанных задач не меняется.
- FR-005. Prompt включает сохранённую библиотеку как данные. Допустимые assetId объединяют прежние brief IDs и зарезервированные source:<id>; чужие и неизвестные ID отклоняются. Старые snapshots без библиотеки продолжают работать.
- FR-006. Не менять HTTP/server/UI/analytics/публикацию/права. Подключение закрытого lookup перед capture и plan-start выполняет координатор отдельно.

## Границы и предположения

Content и CRM — разные контейнеры: producer не импортирует CRM; CRM validator размещается в существующем модуле очереди. Отсутствующая таблица библиотеки означает пустой снимок. Capture выполняет один SELECT данных с window count, без чтения файлов и без общей транзакции двух служб. Изменения после capture не переписывают снимок. SHA описывает существующее содержимое файла, а не подтверждает факт или право использования.

## Критерии успеха

Все синтетические пробы изоляции, ограничений, replay, сохранности после пересоздания сервисов и проверки ссылок проходят. Ни одна проба не обращается к рабочей системе или внешним моделям.
