# Черновики чатов: граница учётной записи

Цель: перед первым выпуском нового экрана чатов закрыть воспроизведённый перенос неотправленного текста между пользователями в одной вкладке браузера. Права, серверные API и существующий отдельный чат не меняются.

- FR-1 Черновик и неподтверждённая отправка принадлежат конкретному viewerId, компании, комнате и задаче. До определения действительного пользователя чтение/запись общего неизвестного пространства запрещены.
- FR-2 Повторное открытие Alice после Bob восстанавливает её собственный черновик; Bob не видит текст, pending или прежний контекст Alice. Смена пользователя при уже открытом экране очищает чужой видимый контекст без переноса в пространство нового пользователя.
- FR-3 Неизвестный результат отправки сохраняет исходные text/clientMessageId/room/taskId в пространстве исходного пользователя. Смена аккаунта не вызывает автоматическую отправку или повтор.
- FR-4 Перед POST проверяется свежая личность через существующий whoami. При несовпадении POST не выполняется. CSRF фиксируется из того же ответа и не подменяется текущим токеном другого пользователя между GET и POST.
- FR-5 Опциональный четвёртый аргумент ctx.api.post/put/patch передаёт фиксированный csrfToken через прежний shell.apiJson. Три старых аргумента сохраняют прежнее поведение. Прямой fetch не обходит общую обработку запросов и ограничения просмотра от другого пользователя.
- FR-6 Прежние viewerless sbc-записи неизвестного владельца не показываются, не переносятся другому пользователю и не удаляются. Старое пространство team-chat отдельного чата не изменяется.
- FR-7 Оба входа нового разговора — основной экран и панель Хью — используют одну границу личности. Компания, комната и задача сохраняют отдельные черновики; composer остаётся последним элементом снизу.

Приёмка: настоящий JSDOM с общей sessionStorage — Alice → Bob → Alice, смена личности без перезагрузки, отдельные company/room/task, pending/ошибка связи, отсутствие POST при смене личности; проверка фиксированного CSRF и сохранения общего API wrapper. До независимой приёмки Claude новый UI не активируется.
