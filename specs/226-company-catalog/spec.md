# 226 — Каталог компаний кабинета и подключение нового клиента

Источник: аудит specs/225-cf-lena-onboarding (PR #610). Цель владельца на 07.11.2026: контент-менеджер ведёт всех клиентов, в том числе новых, в Контент-заводе без правки кода и выпуска владельцем.

## Проблема
Список рабочих компаний был задан в коде (`ops/content/auth-store.js` COMPANIES, 6 шт.). Его читали учётные записи, `whoami`, переключатель «Проект», права и модули (`Object.hasOwn(COMPANIES, code)` в 10+ местах). Новую компанию мог добавить только владелец через выпуск.

## Сценарии
1. Владелец или пользователь с правом `companies.create` открывает «Проект» → «+ Новый клиент», вводит название, код, город, часовой пояс → «Создать и открыть». Компания выбрана, открыт «Контент-план» без плана с кнопкой анкеты «+ Новый».
2. Пользователь без права кнопки не видит; сервер отвечает 403.
3. Прежние шесть компаний, их коды, доступы и данные работают как раньше.
4. Создатель видит новую компанию только у себя (и у владельца); другие пользователи — только после назначения владельцем в «Настройка аккаунтов».

## Требования
- FR-1. Каталог `workspace_companies` в базе content; сид 6 компаний (`INSERT OR IGNORE`, коды не меняются, сохранённые строки не перезаписываются). Ничего не удаляется.
- FR-2. Поля новой компании: код `^[a-z0-9](?:[a-z0-9-]{0,38}[a-z0-9])?$`, уникален, не из зарезервированных; название 1–80; город до 80; часовой пояс IANA (по умолчанию `Asia/Irkutsk`); модули ⊆ {content-factory}, Контент-завод обязателен.
- FR-3. Право `companies.create` в общем реестре прав; выдаёт владелец существующим редактором доступа; у владельца есть всегда.
- FR-4. Создатель-редактор автоматически получает компанию и права `autoposting.view`, `autoposting.edit`, `settings.view`, `settings.edit`, `analytics.view` (+ обязательная зависимость `company-information.view`). Не выдаются: `autoposting.approve`, `content-plan.approve`, `crm.*`, ключи, Onlypult.
- FR-5. Для модулей Контент-завода создаётся карточка CRM с тем же кодом (служебный ключ; код, название, город, часовой пояс). Существующую карточку CRM с этим кодом может переиспользовать только владелец; редактору — 409 `CRM_CODE_TAKEN`. Без CRM компания не создаётся (503/502).
- FR-6. `GET /content/companies` → каталог ∩ доступ пользователя и `canCreate`; `whoami.companies` — то же пересечение из каталога. Переключатель строится из ответа API.
- FR-7. Все серверные проверки области (`Object.hasOwn(COMPANIES, …)`, `companyCodes`, access-options) видят новые коды без правки модулей: `COMPANIES` — общий реестр, наполняемый каталогом.
- FR-8. Журнал: `auth_audit` действие `COMPANY_CREATED` (кто, когда, код, название, город, пояс, модули, добавленные права); `workspace_companies.created_by/created_at`.
- FR-9. UI на 390 и 1440 px без наложений.

## Приёмка
`ops/content/company-catalog.test.js` (настоящие content+CRM), `sites/synapse/cabinet/company-create.test.cjs`, полные наборы кабинета и ops/content без новых падений, `gate.py check`, скриншоты.

## Ограничения
Без развёртывания, без изменения живых данных/прав/ключей. Права в модели глобальны для пользователя (не по компании): добавленные создателю права действуют во всех его компаниях — см. риски в plan.md.
