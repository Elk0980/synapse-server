# 102 · Контент → Материалы, Постинг, упрощённый редактор

Поручение Влада 04.11.2026 (ночная задача №98, агент «Г»). Доска: №100.

## Цель
После монтажа команда компании видит готовые рилсы, проверяет их в маске каждой площадки, скачивает, создаёт публикацию и просит правки. Монтаж делает только Claude-агент монтажа (tools/reels-check); браузер не рендерит видео.

## Сценарии
1. СММ открывает «Материалы»: сетка рилсов с превью, фильтры «дата выхода от/до» и «площадка».
2. Нажимает рилс: предпросмотр, выбор площадки (Instagram Reels, TikTok, YouTube Shorts, VK Клипы, Telegram, MAX), маска интерфейса с безопасными зонами; «Скачать»; «Создать публикацию».
3. «Редактировать»: дорожки видео и звука, обрезать края, разделить, удалить кусок, переставить, громкость, без звука; титры, кадр обложки, скорость 1,25×/1,5×. «Отправить в монтаж» сохраняет EDL к версии.
4. «Отметить от … до …» ✓: окно с миниатюрами кадров и полем «Хью, измени…». Отправка создаёт задачу монтажа и запись в личном чате пользователя с Хью.
5. Агент монтажа забирает правку, монтирует, загружает новую версию; в журнале появляется «Исправлено: готова vN».
6. «Постинг» — прежний автопостинг; создание публикации ведёт в «Материалы».

## Требования
- FR-1 Ролики и версии хранятся по компании; ролик принимается только из хранилища публикаций той же компании (`/content/publishing-assets/<code>/…`) и только с разрешённого origin (`PUBLISHING_ASSET_ORIGINS`, по умолчанию `https://synapse.synapsebusiness.ru`) либо относительным путём своего хранилища. Чужой хост → 400 `MEDIA_HOST` — и из кабинета, и в служебном API агента монтажа (ревью №98, п. 4). Рилс плана с видео на чужом хосте в «Материалы» не попадает.
- FR-2 Рилсы контент-плана (карточка автопостинга с видео) показываются как v1 без копирования; при первой правке берутся в «Материалы» один раз.
- FR-3 Фильтры по дате выхода (ГГГГ-ММ-ДД) и площадке выполняются на сервере.
- FR-4 EDL v1 проверяется сервером (закрытая схема, пределы времени, громкость 0…2, скорость 1/1,25/1,5, до 100 клипов и 50 титров).
- FR-5 Правка создаёт обычную задачу общей доски (`tasks`) на «Claude · монтаж»; повтор с тем же `clientRequestId` не создаёт дубль.
- FR-6 «Создать публикацию» вызывает существующий `autoposting.create`: черновик без даты и без отправки; дальше согласование и план автопостинга.
- FR-7 Права: просмотр — `autoposting.view`, изменения — `autoposting.edit` (proxy и CRM). Служебный API — только ключ сервиса без заголовка личности.
- FR-9 Журнал правок («Хью, измени…», «Исправлено: готова vN», «отменена») попадает в личный чат автора с Хью — комната `hugh:<id>` рабочего чата (PR 504), её показывает плавающая панель hugh-chat. Content забирает записи автора из CRM (`GET /internal/reel-materials/hugh-log`, ключ сервиса) после ответа на `/autoposting/reels…` и перед чтением `hugh:<id>`; запись идемпотентна, в общий чат не попадает. Без комнат (504 не выпущен) — пропуск без ошибки.
- FR-8 Экран адаптивен: 390 px без горизонтальной прокрутки, ПК 1280–1920 px.

## Приёмка
node --test для серверного модуля и HTTP; jsdom для экранов; снимки Playwright 390/1440 с заглушкой API. Фактические цифры — в evidence.md.
