# Общий набор деталей сайтов — задача доски №62 (модуль №61)

Владелец реализации — Claude (ветка claude/site-kit-20261104). Процесс Spec Kit 1.0.0. Решение и формулировка — Влад: «исправил раз — исправилось на всех сайтах».

## Цель

При каждом новом сайте владелец заново исправляет одни и те же детали (пример — системный выпадающий список вместо списка в стиле сайта). Нужен один источник таких деталей: правка в нём применяется ко всем подключённым сайтам, автоматически проверяется на каждом из них, а новый сайт собирается уже с прежними правками.

## Точка А (04.11.2026, origin/main fb59836)

- Общей папки деталей нет. `sites/palitra-love` — 24 html-страницы с нативным `<select>` без оформления (системная стрелка и системный список); `sites/synapse` — ЛК и редакторы; ещё `board`, `chat`, `drafts/peptides`. У ALVI/Авокадо select нет.
- Caddy раздаёт каждый сайт изолированно: `root * /srv/sites/<сайт>`; `sites` монтируется в контейнер целиком, но путь вне корня сайта с домена недоступен.
- `site-apply.js` лежит отдельной копией в alvi, avokado, avokado2, avokado3 (4 разных версии).

## Сценарии

1. Влад правит вид выпадающего списка один раз в `sites/_kit` → `sync.js` обновляет все подключённые сайты → тест и скриншоты CI показывают результат на каждом.
2. Кто-то правит копию в сайте вместо источника → тест падает с указанием файла.
3. Новый сайт или новая страница с `<select>` без kit → тест падает, пока сайт не подключён или явно не отложен с причиной.
4. Посетитель на ПК открывает список: список в цветах и шрифте сайта, управляется мышью и клавиатурой; форма отправляет то же значение, что и раньше; код сайта получает `change`.
5. Посетитель на телефоне: контрол в стиле сайта, список системный (удобнее пальцем).

## Требования

- FR1. `sites/_kit/select.css`, `select.js`, `fields.css`: оформление по переменным `--kit-*` (bg, fg, accent, radius, font и др.) с запасными значениями; системный вид select снят (`appearance:none`), своя стрелка; видимый фокус; без JS контрол оформлен.
- FR2. `select.js` — прогрессивное улучшение: нативный select остаётся в DOM и форме (имя, значение, required, FormData, change/input); кнопка `role=combobox` + `listbox`; клавиатура (стрелки, Home/End, PageUp/Down, Enter/Space, Escape, Tab, набор буквы); disabled-пункты пропускаются; подпись `<label>` открывает список; disabled/reset/программная смена value синхронизируются; динамически добавленные select обрабатываются; на `pointer:coarse` — системный список; отказ `data-kit-native`.
- FR3. `sites/_kit/README.md` (подключение, переменные) и демо `sites/_kit/index.html` с `noindex`, не раздаётся ни одним доменом, не попадает в sitemap.
- FR4. palitra-love: все страницы с `<select>` подключают kit после собственных стилей; тема — из существующей палитры сайта. Тексты, цены, разметка контента не меняются.
- FR5. Доставка на домен: копии в `sites/<сайт>/assets/kit/` строит `tools/site-kit/sync.js` из одного источника, `?v=<хеш>` для сброса кеша; `--check` для CI.
- FR6. `sites/site-kit.test.cjs`: копии синхронны; каждая страница подключённого сайта с select подключает kit в правильном порядке; стили сайта не возвращают `appearance`; каждый сайт с select подключён или отложен с причиной; поведение select.js в jsdom; демо не индексируется.
- FR7. Скриншоты Playwright до/после (1280 и 390) вне git; workflow CI с правами read, скриншоты артефактом.
- FR8. Дефект `section-backdrop` под видеофоном: найти корень и оценить общее исправление. `ops/content` и чужие сайты в этой задаче не меняются — только описание следующей задачи.
