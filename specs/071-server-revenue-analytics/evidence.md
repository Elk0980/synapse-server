Проверены общий grant двух компаний, одновременное продление, сохранение бизнес-ревизий и отдельно заменённого владельцем доступа, таймаут/отзыв/неопределённый результат и перезапуск с незавершённой арендой, новый доступ после отзыва, короткий срок токена, неизменившийся refresh_token и отказ расширенного scope. Ошибка продления не удаляет прежний снимок; человек видит причину в кабинете. Сбор данных по-прежнему GET; отдельный OAuth POST не повторяется вслепую. Сценарии сбора: повтор не удваивает оплату; возврат и финансовая дата отдельны; отмена/подтверждение/неявка не являются посещением; удалённая транзакция исчезает при полном снимке; ошибка второй части не сохраняет половину поколения. Проверены аренда/её истечение/потеря, изменение настройки в процессе, остановка, AES-GCM без отдачи ключей, HMAC клиентского ID и изоляция компаний. Пагинация, неверный профиль, отказ доступа, запрещённый хост и неполный ответ завершаются отказом с сохранением предыдущих данных.

Официальные контракты сверены с [YCLIENTS API](https://developers.yclients.ru/), [Reports API Метрики](https://yandex.com/dev/metrika/ru/stat/openapi/data_1), [целями](https://yandex.ru/dev/metrika/ru/stat/metrics/visits/conversions), [источниками](https://yandex.ru/dev/metrika/ru/stat/attributes/visits/source) и [OAuth refresh](https://yandex.ru/dev/id/doc/ru/tokens/refresh-client). Используются документированные заголовки YCLIENTS, `attendance=1` для посещения и метрики `ym:s:goal<ID>visits/reaches/conversionRate`. Адаптеры данных читают только GET; OAuth refresh — отдельный POST фиксированному провайдеру.

Рабочие ключи ещё не получены и новый модуль не опубликован.
