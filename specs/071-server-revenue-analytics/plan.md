# План

Единственный писатель — Codex в чистом прикреплённом worktree, отдельная ветка от принятой атрибуции PR455. Общий checkout и production не записываются. В существующем Claude Synapse Business подтверждён Opus5.5 и STOP, но выбор High в доступном интерфейсе отсутствует; поэтому серверный модуль реализует Codex в разрешённой запасной роли.

Новые модули revenue-analytics-access / adapters / store / http используют node:sqlite, crypto, fetch и существующий companyModuleContext. Аддитивные таблицы отделены от CRM-заявок и ручных отчётов 2ГИС. Периодическое чтение запускается из текущего серверного процесса; Docker уже перезапускает его и хранит SQLite на постоянном томе. Не требуется cron на ПК, LLM или пользовательская браузерная сессия.

Сбор YCLIENTS: начальный импорт изменённых с historyFrom записей, затем changed_after с перекрытием; финансовый снимок всей заданной истории реальных денег заменяется атомарно после полного чтения. Статьи дохода/возврата задаются после сверки с конкретным филиалом, неизвестные исключаются из выручки. Метрика: часовые цельные снимки 7/30 дней и historyFrom→сегодня; произвольный период собирается явной командой владельца. Базовые данные и цели/UTM публикуются только целым поколением.

Проверки: синтетические API-ответы и SQLite в памяти; существующие ACL/HTTP и аналитические проверки; Spec Kit gate; затем PR. Живое подключение и публикация требуют доступа и свободного общего ресурса, локальные тесты их не подменяют.

OAuth refresh: расширенный зашифрованный credential и отдельная сохраняемая аренда grant в SQLite. POST только на фиксированный oauth.yandex.ru/token, без редиректа/автоматического повтора. Продление раз в 90 дней либо за сутки до истечения; общий refresh_token сериализуется между компаниями и процессами. Ротация ключей не меняет ревизию бизнес-конфигурации; сравнение grant и текущих секретов защищает замену владельца. После неопределённой отправки grant блокируется до новой авторизации. Старый credential {token} поддерживается без обещания автоматического продления.
# Независимый этап контроля качества — 08.10.2026

Дополнительный независимый этап — чистая `compareMetrikaSnapshot` в `ops/crm/revenue-analytics-reconcile.js`, только для приёмки: без нового HTTP-маршрута или прав. Синтетические тесты проверяют ошибки области, потерю нулевых целей, дубликаты, изменения UTM/выборки и отсутствие значений. Частная локальная проверка использует уже сохранённые официальные агрегаты обеих компаний, пропускает их через существующий SQLite/отчёт и сравнивает каждый диапазон. Это проверка хранения и вычисления на реальных агрегатах, не второй живой сбор и не production-цикл; бизнесданные остаются вне Git.

По прямому поручению Влада не ждать серверного окна или YCLIENTS для разработки. Один писатель Codex в этом worktree; существующий fallback из плана сохраняется. Изменение аддитивное, без миграций, новых запросов к сервисам, разрешений и секретов. Метрика проверяется по времени конкретного снимка; YCLIENTS получает явные метаданные текущей ревизии/часового пояса/снимка.
