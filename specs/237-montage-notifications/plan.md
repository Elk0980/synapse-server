## Контракты и безопасность
Ключ события постоянный: edit:id:status:version или request-event:id; уникальность по company+author+event. Клиентский GET возвращает только свои метаданные; mark-read ограничен переданным номером уже видимого события. Фоновый feed доступен только сервису без браузерной identity и не выдаётся через общий proxy.

Входящий Telegram ID устанавливает существующий chat, не браузер. Content связывает его с auth_user и разрешёнными компаниями; task sourceRef строится из bot/update ID и не зависит от текста. При нескольких компаниях требуется явный выбор, связанный с тем же пользователем и одноразовым сроком. Подтверждение taskId идёт после сохранения. При файлах использовать существующие ограничения и маршруты, не скачивать адрес из сообщения.

Ответ для редактора требует явного действия существующего доверенного агента/Owner с clientRequestId; обычные комментарии задачи автоматически наружу не копировать. Переиспользовать существующую авторизованную сессию Owner, как team-chat-agent, но отдельное узкое действие привязано только к задаче из входящего Telegram. Owner открывает форму ответа автору по ссылке из внутренней задачи; сервер проверяет сессию/CSRF и постоянную связь task→author→company. Это не ослабляет ACL чужого hugh-чата. Обычные task_comments и строка author=Claude не являются разрешением на отправку и автоматически не пересылаются.
