# Сторис без публичной подписи: от черновика до очереди публикаций

Процесс Spec Kit 1.0.0. Поручение root 30.09.2026, исполнитель — Claude, единственный автор.

**Редакция 2 (30.09, после приёмки root).** Редакция 1 доводила сторис только до сохранения и согласования, а отправку запрещала. Это промежуточный этап; её патч сохранён отдельно и не применяется. Редакция 2 описывает полный путь: уведомление → просмотр → согласование текущей версии и площадки → очередь → отправка.

**Редакция 3 (30.09, по замечанию приёмки root).** Контракт Onlypult подтверждён root по первичной схеме. Временная остановка отправки снята. Тело запроса для сторис без текста — без поля `content`.

## Контекст и факты
- Авторский пакет Palitra требует сторис без подписи: смысл несут текст на кадре и нативные стикеры.
- `meta.format` (`story`, `post`, `reel`, `carousel`) — тип материала в контент-плане. Он ничего не отправляет.
- Реальный режим публикации — `platformOptions.instagram.is_story === true`. Эта опция уходит провайдеру и входит в согласуемую версию.
- Instagram Stories в Synapse публикуются только через Onlypult: у площадки `providerOnly: 'onlypult'`. Прямых Stories для Telegram и ВК в транспорте нет.
- Пустой текст отклоняет **наш** транспорт (`autoposting-transport.js`: `!text.trim()` → `CONTENT_LIMIT`), для всех площадок.
- Официальный справочник Instagram Graph API (`POST /{ig-user-id}/media`) описывает `caption` для изображений, видео и каруселей, а для контейнера `STORIES` задаёт `media_type` и `image_url`/`video_url`. Подпись для сторис на уровне Instagram не требуется.
- Официальная страница Onlypult «How to directly post Instagram stories»: автопубликация Stories доступна бизнес-аккаунтам; при нескольких вложениях планируется только первое.
- Официальная схема Onlypult `https://onlypult.com/dev/openapi.yaml` — OpenAPI 3.0.3, `info.version` 1.0.0.
  - Её получил root 30.09 в 23:26 (HTTP 200, `application/octet-stream`, UTF-8 YAML) и сохранил копию `ONLYPULT_OPENAPI_ROOT_REVIEW_20260930.yaml` (SHA256 `24a69953…2479`). Исполнитель прочитал эту копию.
  - `components.schemas.PostCreateRequest`: `required: [profile_ids]`; `content` — `string` без `minLength`, описание «Required unless media_ids or media_urls is provided».
  - `PlatformSettings.is_story`: «Story (Instagram, Facebook, VK). Mutually exclusive with is_reels, is_shorts».
  - Схема подтверждает контракт, но не доступ конкретного профиля.

## Сценарии
- US1: редактор сохраняет карточку с материалом без текста и подписей, у которой формат `story` или включено «Публиковать как Story».
- US2: владелец получает обычное напоминание о несогласованной карточке, смотрит предпросмотр и согласует текущую версию для площадки Instagram.
- US3: согласованная сторис с Instagram-каналом в режиме Story ставится в очередь и уходит провайдеру без текста, как только контракт подтверждён. До подтверждения отправка останавливается с явной причиной и без POST.
- US4: та же карточка, выбранная для Telegram, ВК или Instagram без режима Story, не ставится в план. Причина называет канал.

## Требования
- FR-001: сохранение. Карточка с материалом, без текста и подписей сохраняется, если выполнено одно из двух: `meta.format==='story'` или `platformOptions.instagram.is_story===true`. Без материала или для прочих форматов без режима Story — прежний отказ.
- FR-002: готовность содержимого. Для такой карточки нет замечания «Нет текста и подписей площадок». Проверки материала, SHA256 пакета и лимитов не меняются. Согласование — существующее, по версии содержимого и площадкам.
- FR-003: доставка. Сторис без подписи адресуется только каналу, чья площадка — Instagram, при сохранённом и согласованном `platformOptions.instagram.is_story===true`. Такой канал проходит постановку в план без текста.
  - Для любого другого выбранного канала — 409 `MEDIA_ONLY_TARGET`. Сообщение называет канал и говорит, что пустой текст не отправляет транспорт Synapse; ограничение не приписывается площадке.
  - Остальные условия постановки не меняются: согласование версии и площадки, подключение канала, дата в будущем, область компании, профиль компании, отметка о внешней публикации, статус карточки.
- FR-004: транспорт. Пустой текст разрешён только одновременно при: `channelId==='instagram'`, провайдер `onlypult`, `is_story===true`, хотя бы один публичный HTTPS-материал. Для всех прочих каналов и режимов пустой текст по-прежнему даёт `CONTENT_LIMIT`: пустые обычные посты запрещены.
- FR-005: провайдер. В режиме Story без текста действуют лимиты профиля (`maxCountStory`), взаимоисключение Story/Reels, запрет без материала.
  - Отправляется один POST с `profile_ids`, `media_urls`, `publish_now`, `platform_options.instagram.is_story: true` и **без поля `content`**. Контракт делает `content` необязательным при `media_urls`; пустую строку он не требует.
  - Сторис с текстом по-прежнему отправляет `content`. Пустой текст вне режима Story или без материала — `CONTENT_LIMIT` до POST.
  - Повторов POST нет; неизвестный ответ — `needs_review`, как и прежде.
- FR-006: календарь и редактор показывают ту же доставочную причину по каналу. В редакторе «Поставить в план» доступна, только если все целевые каналы — Instagram в режиме Story. Прежняя общая причина «ЛК не отправляет сторис без подписи» убирается.
- FR-007: права, ключи, подключение аккаунтов, другие компании, production не меняются. Новые настройки и флаги не добавляются.
- FR-008: контракт. Решение по телу запроса основано на первичной схеме (см. «Контекст»). Внешнего блокера контракта нет. Доступ конкретного профиля и живая отправка проверяются root только после подключения профиля и согласования конкретного материала.

## Приёмка
- SC-001: серверные тесты.
  - Сохранение и согласование по обоим признакам.
  - Постановка в план на Instagram-Story-канал.
  - `MEDIA_ONLY_TARGET` для Telegram/ВК и Instagram без Story.
  - Прежние отказы: пустой материал, пустые посты/Reels/карусели, дата, канал, согласование другой площадки.
  - Календарь.
- SC-002: поток «очередь → реальный транспорт → заглушенный Onlypult».
  - Один POST без поля `content`, с `media_urls`, `publish_now` и `is_story`; затем только GET, без ложного «опубликовано».
  - Сторис с текстом отправляет `content`.
  - Пустой обычный пост в Instagram и Telegram — `CONTENT_LIMIT` без POST.
- SC-003: DOM. Сохранение, выключенная постановка для не-Story каналов, доступная постановка для Instagram Story, отсутствие старой общей причины.
- SC-004: root отдельно применяет патч, проверяет CI и live на подключённом профиле и согласованном материале. До этого: реализовано и проверено локально, не подключено, не принято.
