# №249 — автоматическое слияние контента

Основание: решение владельца 08.11.2026 «Все три», первый этап №248. Цель: контент PR клиентского сайта проходит существующий CI и сливается squash без сообщения в приложение Codex. Сервер, доступы и сама автоматизация сохраняют независимое ревью.

FR1: allowlist корней/расширений задаётся доверенным workflow; только обычные статические файлы ≤5 МиБ, ≤200 файлов. Весь diff обязан соответствовать; смешанный PR не принимается.
FR2: точный head, свежий main, отсутствие конфликтов/запросов исправления, полный успешный набор проверок и доверенный статус защиты обязательны. Обнаруженные гонки останавливают обработку; ожидаемый head передаётся merge API.
FR3: write-job никогда не исполняет код PR. Только metadata API и доверенная версия из main; новые секреты, admin и снятие правил запрещены.
FR4: существующие и новые подходящие PR обрабатываются по событию проверки и резервному расписанию; лог фиксирует причину отказа и реальный merge SHA. Нет ложного статуса «опубликовано» по факту merge.
Приёмка: живой контентный PR сливается ≤5 минут после зелёных проверок и появляется на домене; PR с ops-файлом остаётся открыт. Код/подключение/живая проверка/приёмка владельцем фиксируются раздельно.
