# 231. Материалы: решение по ролику, просьбы агенту и «живой монтаж»

Задача доски №280 (поручение владельца). Версия процесса Spec Kit: 1.0.0.

## Цель

Сотрудник с доступом к Контент-заводу выбранной компании открывает «Монтаж» (модуль «Материалы»), смотрит ролики съёмки, правит подпись публикации, отмечает по каждому ролику «берём / не берём / переделать» и прямо с ролика просит ИИ-агента что-то сделать: переделать, опубликовать, перенести дату, заменить текст, убрать из плана или просто пишет сообщение. По каждой просьбе видны статус и ответ агента простым языком. Отдельно — «живой монтаж»: отрезки версии можно выключить или оставить без звука, без перестановки.

## Что уже есть (проверено по коду origin/main 61e271e2)

- `ops/crm/reel-materials.js`, `reel-materials-http.js`: ролики компании, версии v1, v2…, правки к версии (`kind=edl` — список правок EDL v1; `kind=request` — «Хью, измени…» по отрезку). Каждая правка создаёт обычную задачу доски на исполнителя «Claude · монтаж»; агент забирает очередь `GET /internal/reel-materials/queue`, берёт правку (`claim`) и загружает новую версию. Рендера на сервере нет.
- «Создать публикацию» (`POST /autoposting/reels/:id/publication`) создаёт черновик автопостинга; дальше работают согласование и план автопостинга (`autoposting.js`: `approvalRequired`, `approval`, `platformApprovals`).
- Архив ролика и версии (specs/224), связь ролика с идеей плана и текст публикации из контент-плана (specs/209, 227).
- Журнал правок автора попадает в его личный чат с Хью: CRM отдаёт `GET /internal/reel-materials/hugh-log`, `ops/content/reel-materials-chat.js` переносит записи в комнату `hugh:<id>`. Это единственный готовый механизм «агент ответил» внутри кабинета; он пропускает только ключи `reel-edit:<id>:(request|done|cancelled)`.
- Границы компаний: браузер ходит через прокси `/content/crm/autoposting/…` (`ops/content/server.js` проверяет `autoposting.view/edit` для компании и CSRF), CRM повторно проверяет личность и компанию (`companyModuleContext`), ролик ищется только по `company_id`.
- Интерфейс «Монтажа» лежит в `sites/synapse/cabinet/materials.js` и `reel-editor.js`: лента роликов, плеер с масками площадок, версии, подпись из плана или публикации, окно «Редактировать» с отметкой отрезка и ручным EDL (разделить, удалить, **переставить**, громкость). Этот каталог вне разрешённой области данной задачи.
- Чего нет: своей подписи у ролика и её истории; отметки «берём / не берём / переделать»; истории правок карточки (кто, когда, что); просьб агенту, кроме правки монтажа; статусов и ответа агента по просьбе; списка отрезков версии и правки «выключить отрезок / без звука» без перестановки.

## Сценарии

1. Сотрудник открывает ролик, меняет подпись, ставит «переделать» с комментарием. В карточке видно, кто и когда что изменил.
2. Сотрудник нажимает «Переделать», пишет, что не так (по желанию — отрезок времени). Создаётся правка монтажа и задача доски; на ролике видна просьба «принято». Агент взял — «в работе»; загрузил новую версию — «готово, посмотрите» с текстом ответа.
3. Сотрудник нажимает «Опубликовать». Создаётся черновик автопостинга существующим механизмом. Если публикации нужно согласование владельца — просьба получает статус «ждёт владельца» с понятным текстом. Когда автопостинг опубликует — «опубликовано».
4. «Перенести дату», «Заменить текст», «Убрать из плана», свободное сообщение: запись просьбы и задача доски для агента; агент отвечает через служебный маршрут, ответ и статус видны на ролике.
5. «Живой монтаж»: у версии список отрезков; сотрудник выключает отрезок 2 и убирает звук у отрезка 4, отправляет. Сохраняется правка EDL к версии; агент монтажа забирает её как обычную правку.

## Требования

- FR-1. У ролика есть своя подпись (`caption`, до 4000 знаков), отметка `decision` (`take` — берём, `skip` — не берём, `redo` — переделать, пусто — без решения) и комментарий к отметке (до 1000 знаков). Изменяются существующим `PATCH /autoposting/reels/:id` (право `autoposting.edit`).
- FR-2. Каждое изменение названия, даты, площадок, подписи и отметки записывается в историю: поле, было, стало, кто, когда. История отдаётся в карточке ролика (`history`).
- FR-3. Своя подпись ролика при «Создать публикацию» подставляется как текст публикации и имеет приоритет над текстом из контент-плана. Лимиты площадок соблюдаются так же, как в specs/227: длинный текст не обрезается и не подставляется в площадку, возвращается предупреждение. Без своей подписи поведение прежнее.
- FR-4. Просьба агенту: `POST /autoposting/reels/:id/requests` с видом `redo`, `publish`, `reschedule`, `replace_text`, `remove_from_plan`, `message`. Текст обязателен для `redo`, `replace_text`, `message`; дата обязательна для `reschedule`. Повтор с тем же `clientRequestId` не создаёт дубль.
- FR-5. Статусы просьбы: `accepted` (принято) → `in_progress` (в работе) → `ready` (готово, посмотрите) → `published` (опубликовано) / `rejected` (отклонено); отдельно `waiting_owner` (ждёт владельца). У просьбы есть ответ агента и история статусов. Просьбы видны в карточке ролика (`requests`), в списке — число открытых (`openRequests`).
- FR-6. `redo` создаёт правку монтажа существующим `requestEdit` (та же задача доски, та же очередь агента, тот же лог в чат с Хью). Статус просьбы следует за правкой: взята — «в работе», новая версия — «готово, посмотрите», отменена — «отклонено».
- FR-7. `publish` идёт только через существующий `createPublication`. Отправки на площадку нет. Если черновику требуется согласование и оно не получено — `waiting_owner` с перечислением площадок. Статус `published` ставится только по факту: автопостинг перевёл публикацию в `published`. Агент не может объявить «опубликовано» сам. Вторая открытая просьба о публикации той же версии отклоняется (409).
- FR-8. Остальные виды создают одну задачу доски (таблица `tasks`, исполнитель «Claude · монтаж», `source_ref=reel-request:<id>`). Второй доски и второго чата нет.
- FR-9. Агент работает через служебные маршруты по ключу сервиса: очередь открытых просьб и ответ со статусом и текстом. Переходы из конечных статусов запрещены.
- FR-10. Автор может отменить свою просьбу, пока она «принято».
- FR-11. У версии может быть список отрезков (`segments`: начало, конец, подпись), идущих подряд от нуля без пропусков. Его задаёт агент монтажа при загрузке версии или отдельным служебным маршрутом.
- FR-12. «Живой монтаж»: `POST /autoposting/reels/:id/live-edit` принимает для каждого отрезка `enabled` и `sound`. Сервер сам строит EDL v1: видеодорожка — включённые отрезки в исходном порядке, звук — те же отрезки, `muted` у отрезков без звука. Границы обязаны совпадать с отрезками версии; если у версии отрезков нет — подряд от нуля до конца ролика. Перестановка невозможна по построению. Нужен хотя бы один включённый отрезок и хотя бы одно изменение.
- FR-13. EDL v1 расширен необязательным полем `live.segments` (исходные переключатели). Прежние EDL без `live` проверяются и хранятся как раньше; неизвестные поля по-прежнему отклоняются. Если `live` передан, дорожки обязаны ему соответствовать.
- FR-14. Всё в границах компании: ролик, версия, правка и просьба ищутся только по `company_id` проверенной компании; чужой идентификатор — 404, чужая компания без доступа — 403. Проверка выполняется на сервере CRM независимо от прокси.
- FR-15. Новых площадок, автопубликаций, прав, ролей и учётных записей нет. Сообщения людям не отправляются.

## Приёмка

- A1. PATCH с подписью и отметкой меняет карточку; в `history` по записи на каждое изменённое поле с именем автора; пользователь только с `autoposting.view` получает 403; чужая компания — 403/404.
- A2. Публикация ролика со своей подписью уходит в автопостинг с этим текстом; без подписи — прежний результат (существующие тесты specs/227 не меняются).
- A3. `redo` создаёт одну правку и одну задачу; повтор — без дубля; `claim` → `in_progress`; новая версия → `ready` с ответом, где назван номер версии.
- A4. `publish` создаёт ровно один черновик; при `approvalRequired` без согласования — `waiting_owner`; после `published` у публикации — `published`; агентский ответ со статусом `published` отклоняется.
- A5. Остальные виды: задача доски с кодом компании; ответ агента меняет статус и текст; ответ для чужой компании — 404; после `rejected` ответ — 409.
- A6. `live-edit`: выключенный отрезок отсутствует на видеодорожке, отрезок без звука — `muted:true`; чужие границы, «всё выключено», «ничего не изменено» — 400; правка видна в очереди агента.
- A7. Прежние тесты `reel-materials*`, `content-archive`, `content-stages` проходят без правок ожиданий.

## Ограничения и вне объёма

- Разрешённая область задачи — только `specs/` и `ops/crm/`. Интерфейс кабинета (`sites/synapse/cabinet/`) и перенос ответов агента в чат (`ops/content/`) в этой работе не меняются: см. plan.md, раздел «Не сделано».
- Данные клиентов, переписки и секреты в спецификацию и тесты не входят; тесты на синтетических данных.
- Выпуск, загрузка роликов и выдача прав — отдельные действия человека с доступом.
