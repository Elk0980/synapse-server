# План реализации

Владелец изменения: Codex, ограниченная задача Palitra. Один писатель в отдельной ветке `codex/palitra-approval-queue-20260930`.

- `ops/crm/autoposting.js`: явная политика по каноническому коду компании, DTO признаков политики, единое транзакционное ядро существующих approve/schedule. Проверка ревизии после ожидания настроек канала. Схема данных не меняется.
- `ops/crm/server.js`: существующий защищённый POST `/autoposting/posts/:id/approve` принимает явный `schedule:true` для объединённой операции. Сохраняются действующие проверки компании, edit и approve. Самостоятельный approve не планирует.
- `sites/synapse/cabinet/autoposting.js`: кнопка и описание сохранённых даты/каналов; проверка текущего предпросмотра, полномочий, подключения и отсутствия правок. При частичном согласовании обычная постановка использует только одобренные каналы.
- Связанные сервисные, HTTP и DOM-тесты проверяют транзакционность, гонки ревизий, изоляцию компаний, остановку очереди и явное действие пользователя.

Запрещённые области: transport/provider, project-chat, content server, production. Доступы площадок и доставка уведомления накануне — отдельный этап.

Существующий content proxy уже защищает `/approve` проверками компании, edit и approve. Его контракт и выдача прав участникам не меняются.
