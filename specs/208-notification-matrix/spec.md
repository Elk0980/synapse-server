# 208 — Настройки → Контент-план → «Уведомления»: матрица «этап × роль»

Задача доски №208 (пакет E, макет Контент-завода 07.11). Процесс 1.0.0.

## Цель
Владелец компании отмечает галочками, кому из ролей сообщать о каждом этапе рилса. Отметки сохраняются сразу, отдельно для каждой компании. Отправка уведомлений по матрице в эту задачу не входит.

## Сценарии
1. Владелец открывает Настройки → Контент → «Уведомления» и видит 9 этапов × 5 ролей с отметками по умолчанию.
2. Владелец ставит или снимает галочку — сохранение без кнопки, версия настроек растёт.
3. Пользователь без права настройки видит таблицу только для чтения.
4. Кабинет обновился раньше сервера: сервер отклоняет новый ключ — показывается «Сохранение заработает после обновления сервера», остальные настройки работают.

## Требования
- FR-1. Ключ `notificationMatrix` в настройках контента компании: объект ровно с этапами `script_review, script_rework, planned, shot, edit_review, edit_rework, ready, published, publish_error`; значение — массив ролей из `owner, approver, content, shooting, editor` без повторов. Иное — 400.
- FR-2. Значения по умолчанию: согласующему — сценарий и монтаж на согласовании; контенту — доработка сценария, согласован, отснято, монтаж на согласовании, готово, ошибка; съёмке — согласован; монтажёру — отснято, монтаж на доработке; владельцу — сценарий на согласовании и ошибка; всем — опубликовано.
- FR-3. PUT без ключа сохраняет прежнюю матрицу; повреждённая запись читается как значения по умолчанию.
- FR-4. Права, компания и версия проверяются как у остальных настроек контента (owner или settings.edit, 409 при чужой версии).
- FR-5. Клиент сохраняет каждое изменение сразу, последовательно, с актуальной версией; при отказе старого сервера не повторяет запросы и не шлёт ключ из основной формы.

## Приёмка
Тесты `ops/content/content-settings.test.js` и `sites/synapse/cabinet/content-settings.test.cjs`; скриншоты 390/1440.

## Ограничения
Отправка уведомлений, выбор канала доставки (профиль человека) и назначение людей в роли — вне задачи. Серверная часть выпускается вручную (Root, managed-release).
