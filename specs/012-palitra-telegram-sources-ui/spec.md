# Исходники Telegram в Контент заводе

## Цель и границы
Подключить готовый приватный список из spec 048 к общей оболочке кабинета. Без изменения модуля списка, API, приёма Telegram, прав, публикаций или данных. Основа: d9339bccba92bf57fce8983e499c467771429810. Единственный писатель интеграции — lead_flow_review.

## Требования
- FR-001: вкладка «Исходники из Telegram» рядом с материалами и этапами, маршрут `#content-factory/sources`, общий заголовок «Контент завод». Прямой alias `#telegram-sources` ведёт туда же.
- FR-002: существующее `autoposting.view` или owner, плюс выбранная компания из identity.companies. Общее `content-factory.view` само по себе недостаточно; нет новых прав и обхода серверного ACL.
- FR-003: adapter использует `SbCabinet.telegramSources.mount` и штатный `apiJson` только для чтения. При закрытии, выходе и смене компании вызывает destroy; старый ответ не попадает в новый экран. В скрытом экране запросов нет.
- FR-004: исходный список сохраняет выключенное состояние, безопасные ссылки, пагинацию и повтор после ошибки. Никакого включения приёма, автоимпорта истории, создания/согласования публикаций.
- FR-005: переходы сохраняют существующие черновики в материалах; выбранная компания и вкладка остаются согласованы. Модуль списка загружается раньше adapter.

## Приёмка
- SC-001: DOM-интеграция реального router + adapter + списка проверяет вкладку, alias, ACL, чужую сохранённую компанию, смену проекта, поздние ответы, выход/возврат и GET-only.
- SC-002: проходят существующие тесты Контент завода и подготовленного списка, проверки синтаксиса и spec gate. Live не заявляется проверенным.

## Риски
Подключение вкладки не включает Telegram intake; это отдельная серверная конфигурация. Проверки локальные с фиктивными компаниями и исходниками. Производственные данные не читаются и не записываются.
