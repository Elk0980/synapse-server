# CF15 — назначенная просроченная доработка
Процесс Spec Kit 1.0.0. Пакет только чтения CRM и постановки факта в существующую owner queue.

## Требования
- FR-001. Collector читает existing autoposting_review_tasks/tasks/posts/companies. Только самая свежая post_revision связь публикации, совпадающая current content_revision, активная компания, задача своей компании не удалена и не done/cancelled, публикация не архивирована/published/publishing/cancelled. Исключаются review_state='approved' и действующее полное approval текущего содержимого с учётом selected platform reviews/legacy; partial/stale не объявляются полным одобрением.
- FR-002. Нужен фактический due_date. due_date — YYYY-MM-DD по существующему validDay; просрочка начинается со следующей календарной даты компании. companies.timezone используется явно; пустой timezone — UTC как существующий calendar, timezoneSource='utc_fallback'; неверный timezone исключается. Нет назначенного срока — нет уведомления. Пустое assignee_name не отменяет срок и отражается «ответственный не назначен»; assignee_role не подменяет имя человека.
- FR-003. pending({companyCode?,limit=100,afterTaskId=0}) возвращает <=100 items и hasMore, nextAfterTaskId, detectedAt. Строгий taskId ASC, одна связь на taskId; nextAfterTaskId — последний taskId при hasMore, 0 в конце. Только company/post/task/version/status/assignee/dueDate/timezone/timezoneSource/asOfDate/eventKey; без названия/текста/description/annotations/контактов. Не писать CRM и не исполнять задачи.
- FR-004. Key content-review-delay:<company>:<postId>:<taskId>:<dueDate>:<contentRevision>. Изменённый срок/версия — другой факт. Сохранённый факт явно содержит detectedAt; поздняя доставка не выдаётся за актуальное состояние.
- FR-005. Content .sync({signal}) получает закрытую сводку injected request('review-delays',{afterTaskId,limit:100},signal), целиком проверяет DTO и добавляет owner alerts через existing alerts.add. До 10 страниц за sync; cursor в памяти продолжается следующим sync, 0 в конце цикла. Cursor продвигается только после успешной записи всей валидной страницы; ошибка/abort сохраняет cursor для повтора. Без второй очереди, таймера, нового env и прямой отправки сообщений. Изменённые сроки/новые задачи во время paging могут попасть в следующий полный цикл.
- FR-006. INSERT OR IGNORE существующей durable queue сохраняет первый факт при повторе/потере результата/перезапуске. Pending означает постановку, sent — только существующая квитанция транспорта. Нельзя заявлять транзакцию двух БД.
