# №25: ротация ключа коннектора задач

Процесс Spec Kit1.0.0. Источник: прямое поручение владельца03.11.2026 выполнить25→24→26, merge/deploy только после фактической приёмки Claude. Текущая область — только25. Задачи24/26 не входят в этот выпуск.

## Цель

Заменить скомпрометированный TASKS_MCP_TOKEN новым криптографически случайным значением, сохранив настройки, данные и доступы сервиса. Значение и полный секретный URL не попадают в отчёты, аргументы CLI, Git или чат. Приёмка подготовки не называется выполненной ротацией.

## Сценарии

1. Оператор получает проверяемый план и локальные тесты, передаёт их Claude. До одобрения сервер и ключ неизменны.
2. После одобрения и свежей проверки окружения меняется одна env-переменная, пересоздаётся только tasks-mcp с прежним compose context. CRM, данные, MAP, права и другие контейнеры не изменяются.
3. Владелец самостоятельно обновляет секретный адрес в существующих Claude и ChatGPT/Codex. Каждый клиент проверяется отдельно; старый адрес получает401.

## Требования

- FR-001: Подготовка MUST включать минимальный локальный env-helper без автоматического Docker/deploy/подключения к серверу. Новый ключ генерируется только на сервере при разрешённой операции; тестовые значения синтетические.
- FR-002: Helper MUST менять ровно одно корректное присваивание TASKS_MCP_TOKEN. Сохраняются все прочие байты, включая комментарии иLF/CRLF. Пропуск, дубль, неоднозначная или некорректная запись — отказ до записи.
- FR-003: Запись MUST иметь явный expected SHA, собственный lock, безопасный временный файл, проверку версии перед атомарной заменой и отказ для symlink/hardlink/небезопасного POSIX-файла. Общая серверная блокировка и отсутствие конкурирующих писателей проверяются оператором отдельно; compare+rename не объявляется транзакцией против несогласованных писателей.
- FR-004: Результаты и ошибки MUST не содержать старый/новый ключ, полную строку env или секретный URL. CLI не принимает значение ключа аргументом. Состояние после изменения env явно требует recreate и проверки; неопределённый исход не повторяется вслепую.
- FR-005: Использовать фактический compose project/files/env context. Пересоздание MUST быть адресным tasks-mcp без build/pull/deps и без изменения остальных effective env, image, mount, network, Owner и allowlist.
- FR-006: Приёмка MUST различать old401, newinitialize/tools/list и работу двух реальных клиентов. /health и синтетический локальный тест не доказывают production/клиентскую приёмку.
- FR-007: Отказ MUST не приводить к автоматическому возврату засвеченного ключа. Восстановление сохраняет новый ключ; при неизвестном исходе сначала читается фактическое состояние, новый ключ повторно не генерируется.
- FR-008: Все операции с новыми credentials в UI MUST выполнять владелец самостоятельно. Ключ и URL не передаются модели, в Claude-пакет или MCP-комментарии.
- FR-009: Статусы задачи/комментарии/agent_report MUST отражать реальные этапы. До рабочей проверки и двух клиентов задача25 не отмечается done; ожидание Claude записывается в next_step.

## Приёмка

- SC-001: Синтетические файлы подтверждают сохранение чужих байтов, точечную замену, CAS/lock, отказ небезопасного файла и отсутствие секрета в выводе.
- SC-002: Настоящий локальный MCP на синтетических ключах до/после пересоздания подтверждает old401/newinitialize/tools/list, прежние allowlist/guards и отсутствие обязательностиMAP для чтения задач.
- SC-003: Отдельно зафиксированы фактический вердикт Claude для точного head, разрешённое применение, redacted production receipt и успешные вызовы из обоих клиентов. До выполнения соответствующий этап остаётся pending.
