# Единые задачи Synapse через MCP — PR-1

Процесс: Spec Kit 1.0.0. Задача: `SB-TASKS-MCP-20261103-01`, 03.11.2026, Asia/Bangkok. Ветка: `codex/tasks-mcp-20261103`, один PR в `main`. Постановщик — Claude, чат «Синапс Рабочая»; исполнитель кода и координатор — Codex по прямому поручению Влада; принимает Влад.

Цель: одна задача с прежним CRM ID доступна через MCP и существующий раздел «Задачи» кабинета. Изменения используют общий реестр `tasks` и `task_coordination`. PR-1 даёт данные, API и кабинет. PR-2 встраивает экраны в личное приложение после слияния его ветки; отдельную доску не строить.

## Требования

- FR1. Добавить миграцию 8: `parent_task_id`, `reviewer_name`, `client_ref`, источники `claude`/`gpt`, неизменяемые комментарии, каталог агентов, сессии и журнал активности. Сохранить старые ID, `sqlite_sequence`, внешние ключи, индексы, триггеры, историю и данные. Различавшиеся прежние назначения сохранить в неизменяемом архиве миграции.
- FR2. Подзадача имеет одного родителя той же компании; допускается один уровень, без циклов и удалённых родителей. Проверяющий отличается от исполнителя после нормализации пробелов и регистра; нарушение возвращает 400 через новый API и прежний CRUD. Ссылки хранятся один раз в координации.
- FR3. `task_create` атомарно использует уникальный `client_ref`; повтор возвращает прежнюю запись. Начальные статус и ссылки сохраняются в той же транзакции. Изменения прежним CRUD участвуют в общей ревизии; устаревшая открытая форма получает 409. Новые записи не должны скрывать старые задачи.
- FR4. Node 24 MCP использует Streamable HTTP и внутреннюю CRM с существующим ключом и identity Owner. Инструменты: `tasks_list`, `task_get`, `task_create`, `task_update`, `task_comment`, `agents_list`, `agent_report`, `session_start`, `doc_read`, `session_end`; описания по-русски. Список задач ограничен 100, комментарии и подзадачи доступны страницами. Без авторизации — 401, чужая компания или задача — 404. Контакты, лиды и сделки через MCP не выдаются.
- FR5. До OAuth 2.1 допускается временный секретный путь из окружения, явно обозначенный в README. Owner ID и список проектов задаются явно. Секреты не входят в Git, отчёт и журналы; новые переменные в `.env.example` пустые. Host, Origin, схемы и размеры ограничены.
- FR6. `session_start` возвращает правила, карту документов с причинами, задачи агента и `session_id`; до регистрации проверяет канон. Повтор возобновляет открытую сессию того же агента/Owner/набора проектов. `doc_read` читает только документы карты из `docs/handoff/`, без выхода из каталога. `session_end` атомарно сохраняет итог и статусы; повтор старой закрытой сессии не меняет новую. Карта принадлежит постановщику, подбор — совпадением слов без LLM.
- FR7. Агенты учитываются вручную, без автоматического запуска. При `state=work` и активной задаче без обновления дольше 60 минут показывать «нет отчёта». Запись в каталоге не доказывает активный процесс.
- FR8. Существующий кабинет показывает исполнителя/проверяющего, стадии с основаниями, источник, подзадачи и прогресс, ссылки/фото/видео, комментарии, агентов и план дня по Asia/Bangkok. Проверить старые записи, открытые формы, восстановление черновиков/страницы, desktop и 390 px, актуальную статику при старом query. `board` перенаправить в этот кабинет; добавить один сервис Compose и один блок Caddy для MCP.
- FR9. Ручной импорт утверждённого seed идемпотентен по `client_ref`; идеи получают `inbox`, родители создаются раньше детей. Повтор не сбрасывает последующие правки. Реальные 7 агентов и 36 задач импортировать только после предоставления JSON постановщиком.

## Приёмка и границы

Локально: миграция и совместимость старых данных; reviewer/parent/scope/CAS; идемпотентность; JSON-RPC create → get → update → comment; выбор документов сайта для «правка сайта Палитры» без видео на тестовой карте; MCP → настоящий кабинет → MCP; авторизация; desktop/390 px и восстановление страницы. Основания и ограничения фиксируются в `evidence.md` и отчёте по разделу 4.

Расхождение постановки сохраняется явно: перечислены 10 инструментов, приёмка требует 11. Произвольный одиннадцатый не добавляется. Настоящие MAP/канон/seed отсутствуют. Синхронизация реальных Claude/ChatGPT, OAuth, серверная установка, DNS/TLS и приёмка Owner остаются отдельными непроверенными шагами. «Код готов», «слито», «на боевом», «проверено» не объединяются.

Не менять лиды, контакты, сделки, чат-сервис, Хью-runtime и taskDispatch; не запускать агентов. Разрешённая область ТЗ сохраняется; минимальное подключение API и точные ответы ошибок правил задач в `ops/crm/server.js` дополнительно разрешены Владом. Спецификация не разрешает развёртывание, новые права или сообщения другим чатам.
