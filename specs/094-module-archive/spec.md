# Архив модулей — задача #38

Дата: 03.11.2026, Asia/Bangkok. Постановщик и проверяющий: Claude; исполнитель: Codex — Архив модулей. Поручение Влада: сначала карта данных только чтением, затем таблицы архива и archive_* в tasks-mcp; PR без merge. Доску #26 и auth #35 не менять.

## Результат и сценарии

Один журнал результатов по модулю и проекту сохраняет попытки, успехи, неудачи, отчёты, решения и следующие шаги. Агент находит архив через session_start, читает прежние записи и дописывает результат от имени открытой сессии. Исправление добавляется отдельной записью со ссылкой на исходную. Чтение и запись учитываются в аудите.

## Требования

- FR1. Карта «модуль → база/таблицы → кто пишет» проверяется по коду main и публикуется комментарием #38 до реализации. Различать тестовые фикстуры, рабочий код и фактическое развёртывание. Не объединять существующие БД и реестры.
- FR2. Семь исходных модулей: sites, content-factory, analytics, advertising, maps, crm, chat-hugh. Карточка содержит название, назначение, ЦКП, ответственного и источники данных. Не выдумывать ответственных или рекламное хранилище.
- FR3. Новые таблицы находятся в crm.sqlite. Именованная additive-миграция не занимает общий номер схемы #26, требует проверенную SQLite-копию перед DDL и сохраняет существующие таблицы, строки, типы, индексы, триггеры, FK и последовательности. Реальный запуск миграции не входит в PR.
- FR4. archive_list(module?, project?, session_id?, limit?, offset?) и archive_read(id, session_id?) работают только для Owner и явно разрешённых проектов. Чтение без сессии учитывается как Owner; указанная сессия должна быть открытой и принадлежать точному владельцу/набору проектов.
- FR5. archive_write требует module, project, type, text, session_id и client_ref; допускает links, task_id, supersedes_id. Типы: tried, succeeded, failed, report, decision, next_step. Автор берётся из существующей открытой agent_sessions, а не из аргумента author. Проверка сессии, запись и аудит атомарны.
- FR6. client_ref уникален у владельца. Повтор того же содержимого возвращает прежнюю запись и не дублирует журнал; другой payload даёт 409. Связанная задача и исправляемая запись должны существовать в том же проекте, исправление — в том же модуле.
- FR7. Записи и аудит защищены SQL от UPDATE, DELETE и замены через REPLACE. archive_list возвращает доступную сводку использования за семь дней с автором, модулем, проектом и числом чтений/записей. Она показывает учёт действий, а не запуск процесса агента.
- FR8. session_start возвращает подходящие карточки и точный вызов archive_list. Проверка MAP до регистрации сессии сохраняется; без архивной миграции прежние задачи работают, архив отвечает 503, подсказки пусты. Отсутствие MAP не обходится.
- FR9. Ссылки только HTTPS без credentials; kind=link/image/video/file. Архив хранит ссылки на существующее хранилище вложений, не скачивает URL и не принимает байты/base64. Реальные файлы, документы, базы и секреты в Git не добавляются.
- FR10. Проверить новую и прежнюю задачи, восстановление соединения/процесса с сохранённым архивом, закрытую/чужую сессию, отзыв области проектов, API кабинета и цепочку MCP → CRM на синтетических данных. Код/локальные тесты/CI/сервер/приёмка — разные стадии.

## Границы приёмки

В этом PR — таблицы, миграционный инструмент, MCP и общий существующий API CRM. Экран «Архив», схема агентов, физический телефон и первое наполнение из частных чатов/AI_HANDOFF выполняются соответствующими задачами после появления хранилища. Здесь не менять кабинет, доску, auth, роли, транспорт уведомлений, содержимое старых задач или права сервиса. Merge/deploy и сообщения людям не разрешены.
