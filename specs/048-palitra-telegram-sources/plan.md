## Дополнение: ручной импорт старого файла
Существующие publishing-assets публичны и ограничены 60 MiB, приватные вложения рабочей комнаты — 8 MiB; подходящего маршрута для старого MOV 65,7 МБ нет. Добавляется один owner POST /content/telegram-sources/company/manual-upload: multipart file + telegramUrl либо file + sourceChatId + provenance, необязательная caption. Узкий потоковый парсер пишет приватный временный файл, считает SHA256 и хранит только первые 32 байта для сигнатуры. Максимум 256 MiB по умолчанию + 64 KiB метаданных, одна ручная загрузка на процесс; входящий поток и скачивание не читают большой файл целиком. Сессия/CSRF проверяются до чтения и после асинхронного разбора. Новые поля import_method/imported_by/imported_at/origin_note в существующей таблице, прежние строки сохраняются. Финальный rename, проверка квоты и запись receipt выполняются синхронно; при сбое новый файл удаляется. История без ссылки использует отдельный ключ archive:sha, не Telegram message ID. Исходники не публикуются. companyLimits задаёт отдельную квоту/предел файла компании; default512MiB не меняется.

Единственный писатель site_meeting_upgrade: telegram-sources* backend/UI/tests, узкое подключение server.js и spec048. Старый bridge, auth, compose, рабочая группа и production не меняются. Визуальная/реальная загрузка остаётся координатору.
