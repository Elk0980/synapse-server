# Приватные исходники из дополнительного Telegram-чата

Процесс Spec Kit 1.0.0. Пункт 10 поручения владельца после встречи 30.09.2026.

## Сценарии
- US1: сотрудник присылает фото или видео в отдельно настроенный источник; оно появляется в приватном списке материалов компании.
- US2: файл больше ограничения облачного API остаётся видимой карточкой со ссылкой и статусом ручного импорта.
- US3: существующая рабочая группа продолжает чат и задачи; источник не получает ответов и не запускает ИИ.

## Требования
- FR-001: дополнительная связь source chat → company отделена от project_chat_rooms. По умолчанию выключена; переназначение компании и совпадение с рабочей группой запрещены. Ранее известный выключенный источник не переходит в legacy. Поздняя коллизия с рабочей комнатой выключает приём источника; миграция Telegram резервирует новый адрес выключенным до проверки конфигурации.
- FR-002: существующий poller и долговечный inbox используются без второго потребителя событий. Источник обрабатывается до команд/legacy; ноль AI jobs, outbox, ответов или задач.
- FR-003: отдельная квитанция chat/message предотвращает повторную запись и скачивание после перезапуска. Сохраняются подпись, группа альбома, идентификаторы Telegram, MIME/размер и ссылка на сообщение.
- FR-004: JPEG/PNG/WebP/PDF, MP4/MOV/WebM скачиваются только в пределах 20 МБ облачного getFile; сигнатура проверяется. Большие, недоступные и неподдерживаемые файлы сохраняют метаданные и manual_import без бесконечных попыток. Временный сетевой сбой остаётся в очереди.
- FR-005: файлы приватны, область компании обязательна для чтения и скачивания, действуют текущая сессия и существующее autoposting.view; owner имеет доступ. Публичного URL нет. Лимит хранения по умолчанию 512 МБ на компанию; превышение сохраняет карточку manual_import. Секреты и клиентские данные в репозиторий не добавляются.
- FR-006: отдельный UI показывает сохранение/ручной импорт, ссылку и выключенный режим. Смена компании не отображает запоздалый ответ прежнего проекта. UI не публикует и не включает приём.
- FR-007: история до подключения автоматически не загружается; MOV 65,7 МБ текущий API скачать не может. Не устанавливать local Bot API и не менять права/секреты/compose.
- FR-008: owner может вручную импортировать уже скачанный старый файл через потоковый bounded multipart в тот же приватный архив. Предел по умолчанию 256 MiB, конфигурируемый в пределах квоты компании. Нужны текущая сессия/sessionVersion, CSRF и зарегистрированный источник выбранной компании по точной ссылке t.me/c либо явному выбору источника и описанию происхождения для истории без ссылки. Файл не скачивается повторно из Telegram; автоматическая история не заявляется.
- FR-009: ручной импорт сохраняет origin, автора/время/метод импорта; путь по ссылке обновляет manual_import по существующей квитанции. Повтор того же SHA256 идемпотентен; другие байты для уже сохранённого сообщения дают конфликт. Архив без ссылки дедуплицируется по company/source/SHA и хранится как manual_archive с ключом archive:sha, telegramUrl=null; бот-квитанции и старая группа не подменяются. Квота общая с автоприёмом, по умолчанию 512 MiB; индивидуальное увеличение одной компании не увеличивает лимит других. Сигнатура, безопасное имя, размер и отсутствие чужой компании проверяются до сохранения. Отзыв сессии или прав во время чтения отклоняет запись, временный файл удаляется.
- FR-010: доступная владельцу форма в существующей вкладке явно объясняет ручной импорт старого файла. Смена компании/выход отменяют запрос и исключают поздний результат. Приватность, отсутствие AI/tasks/outbox/публикаций сохраняются.

## Приёмка
- SC-001: тесты повторов, перезапуска, выключения, изоляции компаний, квоты и больших файлов проходят; связанные существующие тесты bridge/content не регрессируют.
- SC-002: HTTP-проверка внутреннего ключа, приватного списка/скачивания, общей рабочей привязки; сценарии UI XSS/позднего ответа/статуса.
- SC-003: координатор отдельно проверяет подключение списка в ЛК, конфиг и права работающего бота, затем один разрешённый новый файл; до этого функция считается выключенной, не подключённой live.
- SC-004: локальные HTTP/DOM регрессии проверяют файл 65,7 МБ, upgrade карточки, повторы/конфликт, multipart/размер/сигнатуру/квоту, CSRF/owner/sessionVersion/company, прерванную загрузку и нулевые исходящие эффекты. Реальный файл импортирует и принимает координатор отдельно.

## Границы
Один писатель site_meeting_upgrade: bridge, новый модуль приватных исходников/его тесты, узкие строки подключения server.js, отдельный UI и specs/048. project-chat.js, CRM, auth, compose и production вне изменения. Merge/deploy/клиентские сообщения не разрешены этому исполнителю.
