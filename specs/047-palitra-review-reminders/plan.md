# План

Один писатель: Codex, ветка `codex/palitra-review-reminders-20260930` от `bfe05ea`.

- Новый `ops/content/content-review-reminders.js`: явная конфигурация, московские окна, постоянный журнал окон и уведомлённых версий, ограниченное чтение CRM, сборка сообщений.
- Узкая интеграция в `project-chat.js`: существующий серверный цикл, существующий insertMessage/outbox, системный автор и skipAi. Изменения сервера content не нужны.
- `ops/crm/autoposting.js` и служебный GET в CRM `server.js`: минимальная сводка из реальных дат/версий/одобрений, без чтения каналов или отправки.
- `sites/synapse/cabinet/autoposting.js`: открытие карточки по ссылке через существующий endpoint, сохранение ACL/предпросмотра и локальных правок.
- Тесты модулей, HTTP-контракта и DOM. NODE_PATH использует уже установленный временный jsdom; package/lock не меняются.

Две новые таблицы content DB создаются идемпотентно; FK на сообщения/комнаты. Откат функции — выключение конфигурации, журнал не удаляется. Ни миграций production, ни изменения live-параметров в этой задаче.

Конфигурация процесса content, без изменения server.js:
- `PALITRA_REVIEW_REMINDERS_ENABLED`: только строка `true` включает функцию; всё остальное выключает.
- `PALITRA_REVIEW_REMINDER_EVENING`: обязательное после включения местное `HH:MM`, без значения по умолчанию.
- `PALITRA_REVIEW_REMINDER_MORNING`: необязательное местное `HH:MM`; пусто означает отсутствие утреннего окна.

Все три настройки явно передаются только в сервис `content` через `docker-compose.yml`; значения по умолчанию — `false` и пустые времена. `.env.example` описывает формат и необходимость согласовать время. Общий `env_file` не подключается, production-конфигурация этим PR не меняется.

Ссылка напоминания использует `#autoposting?company=...&post=...&revision=...`: существующая оболочка переводит alias в `#content-factory/materials` с сохранением параметров. Интеграционный DOM-тест прогоняет реальную `viewFromHash` из `cabinet.html` перед модулем материалов.
- Часовой пояс `Europe/Moscow`, окно 60 минут. Неверные, пересекающиеся или переходящие через полночь окна выключают функцию. Время production ещё не принято; образцы env и server.js не меняются.

Журнал окна: `pending` → `queued`/`empty`/`blocked`. Ошибка CRM оставляет pending и повторяется не чаще раза в минуту только до конца окна. `queued` подтверждает запись в outbox, а не доставку Telegram. Отдельный журнал версий не очищается при sent/error/uncertain или перепривязке комнаты; существующий outbox не отправляет старую запись новой группе.
