# Связь статистики Контент завода с карточкой

## Цель и границы
Автор backend Codex, UI Claude в отдельной копии. Статистика должна открывать именно ту карточку, для которой есть доказательство связи. Изменения только `ops/crm/social-stats.js`, его тесты и эта спецификация. Без внешних запросов, отправки публикаций, миграций, прав и развёртывания.

## Требования
- FR-001: `crm.posts[].autopostingId` содержит положительный номер карточки только при единственном подтверждённом `autoposting_publication_receipts.post_id` своей компании для канонического адреса.
- FR-002: без подтверждения, при споре карточек/contentId или неполной выборке подтверждений возвращается `null`. Номера `social_posts`, внешние номера и текстовые contentId не подставляются.
- FR-003: связь не меняет значения, атрибуцию, порядок, источники и существующие границы периода статистики.
- FR-004: UI использует только это поле, открывает карточку с повторным чтением через существующий защищённый маршрут. Внешняя ссылка сохраняется отдельной ссылкой.

## Приёмка
Проверить настоящий DTO на синтетической SQLite базе: подтверждённая карточка, два написания адреса одной карточки, конфликт двух карточек, чужое подтверждение с подменённым company_id, отсутствие подтверждения, усечённые 205 подтверждений. Нет публикаций и сетевых вызовов. UI приёмка отдельная.

## Статус
Реализация начата. Подключение в рабочей системе и live API не проверены.
