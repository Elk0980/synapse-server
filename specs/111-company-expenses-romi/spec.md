# №92 PR1: расходы по компании → ROMI

Цель: в «Сквозной аналитике» выбранной компании (первой идёт Авокадо) видно расход
по источнику и ROMI с честной меткой данных. Сейчас ЛК пишет «по компании не ведутся».

Сценарий: владелец выбирает Авокадо, вносит расход источника `yandex-direct` за день.
В воронке и таблице «Площадки» появляются расход и ROMI по Директу. Чужие и общие расходы не учитываются.

- FR-1: у расхода есть необязательная компания (`expenses.company_code`). Добавочная миграция v11.
  Старые строки остаются общими (NULL), задним числом их никому не приписываем.
- FR-2: если таблица расходов не пустая, перед миграцией делается проверенный снимок
  (`VACUUM INTO`, integrity_check, сверка числа строк). Повторный запуск снимок не повторяет.
- FR-3: `POST /expenses` берёт компанию из тела или `?companyCode`. Расхождение → 400 COMPANY_MISMATCH.
  Неизвестная компания → ошибка. Код источника сохраняется в нижнем регистре.
- FR-4: `/dashboard`, `/summary` и `/expenses` с компанией учитывают только её строки.
  Нет строк → расход `null` («не внесены»), ROMI `null`. Без компании видны все расходы, как раньше.
  `expensesScope` равен `company` или `all`.
- FR-5: ROMI = (выручка − расход) / расход × 100, только при расходе > 0.
  ROMI площадки из нескольких кодов считается из сумм, проценты не складываются.
- FR-6: ЛК показывает «не внесены», «нет расходов для расчёта», метки РУЧНОЙ ВВОД / НЕТ ДАННЫХ
  и подсказку кодов площадок. Ответ старого сервера `global_unavailable` по-прежнему означает «не ведутся».

Приёмка: тесты ops/crm/company-expenses.test.js и sites/synapse/cabinet/analytics-expenses.test.cjs.
После выпуска (очередь #25 / №55) владелец вносит расход Директа Авокадо, ROMI виден в ЛК.
Ограничения: метка LIVE расходу не ставится, это ручной ввод. Автоимпорт статистики Директа — отдельный PR (6–8).
