FR-1: все фактические SQLite, сайты целиком, медиа, конфиги, секреты, managed
runtime/образы и mount sources включены по принятой инвентаризации.
FR-2: VACUUM INTO + integrity_check, SHA256, шифрование age до записи архива.
FR-3: ночью Бангкока. В архивном профиле — две серверные копии по review221;
после подтверждённого забора на D оставить последнюю. В потоковом профиле
полный архив хранится только на D, сервер хранит метаданные текущей попытки.
SSH list/get не расширяется. Нельзя заполнить диск.
FR-4: Windows pull-only read-only SSH, строгая проверка host key, 14 дней и
одна копия в месяц, догрузка при входе, еженедельная проверка.
FR-5: безопасное восстановление в новом каталоге; отдельный offline smoke CRM/сайта.
FR-6: утренний отчёт в №58; доступ создаёт только Влад.

Приёмка Claude: сегодняшний архив на D, SHA, настоящий restore CRM/сайта,
выключенный ПК → догрузка; измеренный RTO ≤1 часа. Локальные тесты этого не доказывают.
Запрещены server writes до приёмки, merge, секреты/данные в git.

## Поток на D — поручение 05.11.2026 01:25 Bangkok

Причина: полная копия по архивному профилю требует больше места, чем доступно на сервере. Новый профиль передаёт зашифрованные данные сразу на ПК; архивный профиль и прежние копии продолжают работать без изменения формата восстановления.

FR-S1: на сервере не создаются полный tar, полный ciphertext либо их промежуточные файлы. Постоянно сохраняются только ограниченные метаданные; в private scratch одновременно находится не более одного снимка SQLite. После передачи его байтов снимок удаляется, в том числе при ошибке.
FR-S2: age шифрует поток до передачи пользователю backup-read. Этот пользователь получает только ciphertext/разрешённые метаданные через фиксированные list/get; sudo, shell, запись, произвольные пути, чтение исходных файлов и новые права исключены. Root-производитель использует только заранее принятую inventory.
FR-S3: источник SQLite читается online, VACUUM INTO и integrity_check обязательны. Данные из WAL входят в снимок; raw WAL/SHM/journal не подменяют снимок. Пауза рабочих контейнеров, изменение бизнес-данных и перенос ключей запрещены.
FR-S4: постоянная память и временное место сервера ограничены буферами и крупнейшим снимком, а не общим размером данных/образов. Проверки места на D, предельного размера потока и бюджета восстановления остаются обязательными.
FR-S5: завершённая копия на D публикуется только после завершения обоих age-потоков и проверки SHA/размеров по окончательному receipt. Разрыв связи, повторное чтение, неправильный порядок, неизвестный исход, превышение бюджета и неверный receipt не создают VERIFIED/ACK. Нельзя дописывать к новому ciphertext непроверенный старый префикс.
FR-S6: первый pull и последующие недельные проверки по-прежнему выполняют расшифровку, внутренние SHA и SQLite integrity. Restore и sandbox сохраняют существующие контракты. Проверенный ciphertext, полный pull, sandbox и измеренный RTO — разные стадии.
FR-S7: после выключенного ПК новый pull получает свежую копию без открытого чата. Ожидание читателя, отмена/таймаут, отключение клиента и повторный запуск ограничены; не остаются age/docker-процессы, FIFO или SQLite scratch от завершённых попыток. Одновременно работает один производитель/читатель.
FR-S8: проверка источников, ссылок и изменений файлов не ослабляется. Не добавлять скрытые исключения runtime/OS. Известные внешние ссылки требуют принятой deployment inventory; этот PR не выдаёт их за решённые.
FR-S9: credentials/host key/SSH forced command и обязательная защита main не изменяются этим кодом. Метку «сайты: инфраструктура» ставит только Влад. Никакой установки до принятия независимым Claude.

Приёмка нового профиля: реальная age-копия WAL fixture и медиа на ПК, место сервера меньше полного архива, не более одного SQLite snapshot, прежний restore успешно проверяет содержимое, abort/retry не публикуют неполную копию; отдельные отрицательные тесты протокола/путей/размеров/ссылок. Live-установка и сегодняшний production backup остаются отдельной стадией после ревью.
