# Правила доски как механизм сервера (№142)

Поручение Влада 05.11.2026 12:14–12:20: «как я могу быть уверен, что правила прочитал ты и другие
исполнители… Ты сам нарушаешь правила — как быть? По такой логике невозможно выстроить систему».
Решение: правила перестают быть текстом и становятся проверками сервера задач. Сервер отклоняет,
а не советует. Задача доски №142.

## Точка А
Правила приходят в `session_start` текстом; выполняются ли они — видно только когда Влад заметил.
Стадии и статусы ставятся словами, «проверено» — без обязательного доказательства, задача создаётся
без Точки Б и шагов.

## Точка Б
Три механизма в существующем стороже доски (PR 485, `ops/crm/task-watchdog.js`), тот же режим
`observe`/`enforce`:

- FR-1 **Якорь «Сэр».** `session_start` отдаёт `rules_revision` (sha256 карты и правил) и `rules_version`;
  tasks-mcp передаёт их в CRM, CRM запоминает текущие (`task_watchdog_settings`: `rules_revision`,
  `rules_version`, `rules_at`). Исполнитель пишет первой строкой комментария в задаче
  `Сэр · правила <версия> · код <8 символов rules_revision>`. Якорь засчитывается, если его автор —
  исполнитель задачи (имя автора или удостоверённая личность комментария) и код равен первым
  8 символам текущего `rules_revision`. Код прежней версии = нет якоря (`stale`).
  - `task_get`/координация: поле `rules_anchor {state: ok|stale|missing|unknown, code, current}`.
  - `task_update` со стадией `code`/`connected`/`verified` без актуального якоря → **409** с текстом,
    какой код нужен. Пока сервер не получал ни одного `session_start` → 409 «выполните session_start».
  - Сводка сторожа: «По правилам: N. Не по правилам: M.» + список задач в работе без якоря.
- FR-2 **«Проверено» только с доказательством от другого.** Стадия `verified`:
  удостоверённый исполнитель не может ставить её сам (409); в `evidence` обязательны http-ссылка на
  живой экран и два снимка с пометками «390» и «1440» (ссылки или пути к файлам), иначе 409 со
  списком недостающего. Статус `done` при `codeRequired≠false` без подтверждённого `verified` → 409.
  Существующая проверка сторожа (независимый проверяющий по principal, HTTPS-ссылка) сохраняется;
  evidence теперь может содержать несколько ссылок — достаточно хотя бы одной HTTPS без учётных данных.
- FR-3 **Поля постановки.** `task_create` отклоняет (422) описание без строк «Точка Б:» и
  «Шаги:»/«Шаги приёмки:», текст ошибки говорит, что добавить. Исключение — структурные записи с
  заголовком «Цель ·» и «Модуль ·».
- FR-4 **Режим.** Та же настройка, что у сторожа (`TASK_WATCHDOG_MODE`): `observe` (по умолчанию) —
  ничего не отклоняется, каждая несостоявшаяся блокировка пишется в `task_watchdog_rules_log` и
  попадает в сводку «Отклонено бы (наблюдение, за сутки): K»; `enforce` — отказы и строка «Отклонено».
- FR-5 **Владелец** (principal `vlad`, кабинет) не ограничивается ни одной проверкой.
- FR-6 Совместимость: схемы MCP-инструментов не меняются (новые поля `rules_revision`/`rules_version`
  CRM принимает только от tasks-mcp при `session_start`); старые базы получают новую таблицу
  `CREATE TABLE IF NOT EXISTS`; старые записи не переписываются.
