## Разбор причины (по коду, без доступа к боевой базе)

- Текст «Площадка не подтвердила публикацию» в кабинете — код `PUBLISH_FAILED` у доставки `failed`. В main он ставится, только когда ошибка транспорта неоднозначной не считается (`ambiguous:false`). Для Onlypult это и документированный отказ на сам `POST /posts` (400/404/422/429 в формате контракта): код считал его доказательством «задание не создано». Ответ 422 в контракте Onlypult несёт `retryable`, то есть отказ ответа не исключает, что сервис продолжит работу; у рилса Instagram обработка видео асинхронная. Точный ответ Onlypult по посту №77 по репозиторию не установить — нужна строка доставки и журнал CRM с боевого (см. «Нужно от Влада»).
- Независимо от точной причины в main были ещё три разрыва: (1) статус `failed` от Onlypult больше не перечитывался; (2) задание без идентификатора (таймаут ответа на POST, ошибка ответа) не сверялось никогда; (3) повторное чтение `published` оставляло доставку `needs_review`, и этап идеи показывал «Ошибка публикации».
- Ссылки на пост: публикационный `Post` в https://onlypult.com/dev/openapi.yaml (OpenAPI 3.0.3, прочитан 07.11.2026) полей url/permalink не имеет; `MediaFile.url` — файл вложения. `AnalyticsTopItem.url` (permalink) есть только у аналитики и только для instagram/facebook/linkedin/tiktok/twitter. Для ВК, Telegram, YouTube, MAX через Onlypult ссылки на пост нет.
