## Разбор причины (по коду, без доступа к боевой базе)

- Текст «Площадка не подтвердила публикацию» в кабинете — код `PUBLISH_FAILED` у доставки `failed`. В main он ставится, только когда ошибка транспорта неоднозначной не считается (`ambiguous:false`). Для Onlypult это и документированный отказ на сам `POST /posts` (400/404/422/429 в формате контракта): код считал его доказательством «задание не создано». Ответ 422 в контракте Onlypult несёт `retryable`, то есть отказ ответа не исключает, что сервис продолжит работу; у рилса Instagram обработка видео асинхронная. Точный ответ Onlypult по посту №77 по репозиторию не установить — нужна строка доставки и журнал CRM с боевого (см. «Нужно от Влада»).
- Независимо от точной причины в main были ещё три разрыва: (1) статус `failed` от Onlypult больше не перечитывался; (2) задание без идентификатора (таймаут ответа на POST, ошибка ответа) не сверялось никогда; (3) повторное чтение `published` оставляло доставку `needs_review`, и этап идеи показывал «Ошибка публикации».
- Ссылки на пост: публикационный `Post` в https://onlypult.com/dev/openapi.yaml (OpenAPI 3.0.3, прочитан 07.11.2026) полей url/permalink не имеет; `MediaFile.url` — файл вложения. `AnalyticsTopItem.url` (permalink) есть только у аналитики и только для instagram/facebook/linkedin/tiktok/twitter. Для ВК, Telegram, YouTube, MAX через Onlypult ссылки на пост нет.

## Исправление по ревью PR 607 (07.11.2026)

- Дефект ревью подтверждён по коду: после 215 любой разобранный отказ на `POST /posts` помечался `submitted` → `needs_review/PROVIDER_UNCONFIRMED`; `schedule`/`update` отвечали 409 `PUBLICATION_REVIEW_REQUIRED`, ручная сверка ничего не меняла.
- Решение (координатор по поручению владельца): документированный отказ 400/401/403/404/429 и 422 `retryable:false` → `failed` (`PROVIDER_REJECTED`/`AUTH_FAILED`/`RATE_LIMITED`), поиска нет, отправку можно повторить; таймаут/5xx/неразобранный ответ → `PUBLICATION_UNCERTAIN`, 422 `retryable:true` → `PROVIDER_UNCONFIRMED`. После окна N дней последний полный поиск без совпадения → `failed/PROVIDER_NOT_FOUND` (FR-10), ошибка поиска вердикта не даёт. `GET /posts` читается постранично (до 10 страниц по 100, `meta.pages` по контракту openapi.yaml, перепроверен 07.11.2026); неполный поиск — ошибка, не «не найдено».
- `autoposting-verify.test.js` — 16/16: шесть отказов (400, 401, 403, 404, 429, 422 retryable:false) → `failed` с причиной, за 8 дней ни одного `GET /posts` и ни одного автоповтора, повторная отправка человеком — ровно один новый POST; 502 → `needs_review/PUBLICATION_UNCERTAIN`, `schedule` → 409; таймаут → «не найдено» в окне не вердикт, после окна при 503 доставка остаётся на проверке, ручная проверка после восстановления → `PROVIDER_NOT_FOUND`, карточка `failed`, поиск прекращён, повторная отправка проходит; 422 retryable:true → найдено последним поиском после окна → `published`, повторная отправка закрыта; адаптер: задание на 2-й странице найдено, 12 страниц и полная страница без `meta` → `RESPONSE_UNCERTAIN`. Во всех сценариях нет `/retry`/`/publish`.
- Адресные `autoposting*`, `content-stages*`, `social-onlypult*`, `reel-attribution*` — 275/275; кабинет `autoposting*.test.cjs` + `content-stages-proxy` — 134/134; полный `ops/crm/*.test.js` — 1098/1102, те же 4 прежних падения вне области (email-campaigns, media-mentor-http, reel-plan-file, task-products-http); gate — ok.
