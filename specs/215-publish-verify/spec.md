# 215 · Публикация и проверка выхода (П4 «соцсети под ключ»)

Задача доски №215 (родитель №212). Решение Влада 07.11.2026: после публикации из кабинета система сама получает ссылку на конкретный пост каждой площадки и подтверждает выход, без ручных отметок.

## Точка А (07.11, боевой, компания Авокадо, через Onlypult)

- Пост №77: Instagram — доставка `failed` («Площадка не подтвердила публикацию»), хотя рилс вышел.
- ВК и Telegram — в кабинете «вышло · сообщество», ссылки на пост нет. YouTube — ссылка есть.
- Код main: ни ответ Onlypult на отправку, ни повторное чтение со статусом `published` не переводили доставку из `needs_review`; идея в контент-плане при этом показывала «Ошибка публикации». Задание без идентификатора (таймаут ответа, ошибка на уже ушедший POST) не сверялось вовсе; статус Onlypult `failed` больше не перечитывался.

## Точка Б

Влад публикует рилс из кабинета → через несколько минут карточка сама становится «Опубликовано»; у Instagram/TikTok — ссылка на пост, если Onlypult её отдаёт; у ВК/Telegram через Onlypult — честно «вышло · сообщество» (ссылки на пост у сервиса нет). Ничего не публикуется повторно.

## Требования

- FR-1. Отправка ушла сервису (POST выполнен) — ошибка ответа не делает доставку окончательно `failed`: доставка `needs_review` с кодом `PROVIDER_UNCONFIRMED` (документированный отказ) или `PUBLICATION_UNCERTAIN` (таймаут/неразобранный ответ), фиксируются время отправки и SHA-256 нормализованного текста. Предварительные отказы до POST (лимиты, профиль, тариф) остаются `failed`.
- FR-2. Фоновая сверка только чтением: (а) известное задание — `GET /posts/{id}`: `draft/scheduled` — раз в минуту, `failed`/`published` без подтверждения — раз в 10 минут в окне N дней; (б) задание без идентификатора — `GET /posts?profile_id=…` строго: тот же профиль, совпадение отпечатка текста, создано в окне попытки (−10…+60 мин), кандидат ровно один и не присвоен другой доставке; найденное подтверждается отдельным `GET /posts/{id}`. Первый поиск — не раньше чем через 2 минуты после попытки, далее раз в 10 минут.
- FR-3. Повторное чтение задания со статусом `published` переводит доставку в `published`: `external_id = onlypult:<id>`, `provider_published_at`, `confirmed_via = provider_status` и `error_code = PROVIDER_LINK_UNAVAILABLE` без ссылки либо `confirmed_via = provider_permalink` со ссылкой. Все доставки опубликованы → карточка `published`. Ответ на POST выход не подтверждает.
- FR-4. Ссылка на конкретный пост: публикационный `Post` Onlypult ссылки не содержит (openapi.yaml, проверено 07.11.2026). Для Instagram и TikTok ссылка берётся из аналитики Onlypult (`/analytics/profiles` → `linked_publish_profile.id` = наш профиль → `/analytics/{id}/top-posts`), строго: время ±30 мин, совпадение подписи (точно или общее начало ≥40 символов), https на домен площадки, ровно один кандидат. Иначе — ссылки нет. Для ВК, Telegram, YouTube, MAX через Onlypult ссылки нет: кабинет показывает страницу сообщества из CRM с пометкой (как раньше), ничего не выдумывается. Прямые ВК/Telegram по-прежнему получают ссылку от самой площадки.
- FR-5. Периодическая сверка опубликованных за последние N дней (`AUTOPOSTING_VERIFY_DAYS`, по умолчанию 7): у Instagram/TikTok без ссылки — поиск не чаще раза в час, не больше 2 за проход (лимит top-posts 10/мин). Идемпотентно: найденная ссылка больше не ищется; за окном ничего не запрашивается.
- FR-6. В рамках сверки никогда не вызываются `POST /posts`, `/posts/{id}/retry`, `/posts/{id}/publish`, `/posts/retry-all-failed`. Повторная отправка опубликованной/проверяемой карточки закрыта прежними проверками.
- FR-7. Ручная «Проверить статус» (`POST /autoposting/posts/:id/reconcile`) выполняет те же шаги для своей карточки без ожидания интервала.
- FR-8. Этап идеи (content-stages): доставка `needs_review` с `PROVIDER_PENDING` — «Запланировано к выходу», а не «Ошибка публикации».
- FR-9. В DTO доставки добавочные поля `confirmedVia`, `providerPublishedAt`. Новые колонки `autoposting_deliveries` добавляются `ALTER TABLE` (TEXT, NULL), прежние данные не меняются.
