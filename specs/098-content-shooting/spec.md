# №98 · В — Контент → Съёмка

Поручение Влада 04.11 (Бангкок), задача доски №101 (родитель №98). Экран регистрируется в оболочке
агента А (`window.SynapseModules.register('content-shooting', …)`, «Контракт А», версия 1).

## Цель
Команда компании видит согласованные рилсы плана по порядку, понимает, что снимать кадр за кадром,
читает сценарий с суфлёра, делится репликами с актёром, загружает крупные дубли частями с
продолжением после обрыва, а монтажёр (Claude-агент) забирает дубли и возвращает черновик в ту же
карточку.

## Сценарии
1. СММ открывает «Съёмка»: список рилсов №1…N (порядок плана), у каждого дата выхода, день недели
   съёмки и дедлайн из «Настройки → Контент», статус «согласовано / снято / в монтаже / черновик».
2. Открывает рилс: «Общий план» — кадры по порядку (реплика с именем актёра, вставка/B-roll, реквизит,
   действие); напротив каждого кадра «Загрузить материал»; внизу «Другое / дополнительно».
3. «Суфлёр»: полный экран, весь сценарий или только реплики выбранного актёра; скорость, старт/пауза
   касанием, стоп, назад, зеркало, размер шрифта.
4. «Поделиться» рядом с выбором актёра: на телефоне `navigator.share` (текст и, если поддерживается,
   файл); на ПК — Telegram, WhatsApp, VK, «Скопировать» (MAX). Текст: реплики актёра жирным с «▶ ИМЯ».
   PNG и PDF: реплики актёра выделены цветом.
5. Загрузка MOV 25–1800 МБ с телефона: прогресс, обрыв сети, повтор — продолжение с принятого байта,
   а не с нуля. При нехватке места отказ ДО передачи с понятным текстом.
6. «Раскадровка»: по кадру — что в кадре, ракурс, смена плана, важное; правка сохраняется.
   «🧪 ТЕСТОВАЯ ВЕРСИЯ»: эскиз кадра картинкой OpenAI по ключу резервного провайдера Хью.
7. Монтажёр по своему ключу читает дубли только своей компании и загружает черновик в карточку.

## Требования
- FR-1 Список: только идеи формата `reel` с согласованной версией (`variants[].status==='approved'`),
  порядок — дата, затем порядок в плане. Статус: `productionStatus` плана (PR 496), иначе по
  загрузкам (черновик → «черновик», дубли → «снято»), иначе «согласовано». Метка «в монтаже»
  выставляется монтажёром через API.
- FR-2 День/дедлайн: дедлайн = дата выхода − `deadlineDays`; день съёмки — последний из
  `shootingWeekdays` не позже дедлайна. Нет настроек — честное «не задано» и ссылка на настройки.
- FR-3 Общий план строится из сценария (`script`, PR 496), иначе из хука и темы. Строки
  `Имя: текст` — реплики; `[…]`, `Вставка:`/`B-roll:` — вставки; `Реквизит:` — реквизит.
- FR-4 Суфлёр работает без сети, не пишет на сервер, освобождает таймеры и слушатели при выходе.
- FR-5 Поделиться: отправляется только сценарий выбранного рилса; ничего не публикуется само.
- FR-6 Загрузка частями: POST создаёт сессию (имя, размер, тип, кадр); PATCH с `Upload-Offset`
  дописывает кусок ≤ 16 МиБ; несовпадение смещения — 409 с текущим смещением; оборванный кусок
  откатывается. Тот же отпечаток файла возвращает незавершённую сессию (продолжение после
  перезагрузки). Завершение проверяет сигнатуру (MOV/MP4 `ftyp`, JPEG, PNG).
- FR-7 Хранилище — адаптер (`local` сейчас, интерфейс готов для S3): квота компании, резерв
  свободного места диска (по умолчанию ≥ 15 % и ≥ 5 ГиБ свободными после загрузки), учёт
  незавершённых сессий. Отказ — до приёма байтов.
- FR-8 Изоляция: компания из адреса проверяется на сервере; чтение — `autoposting.view`, загрузка и
  правка — `autoposting.edit`; файл другой компании — 404.
- FR-9 API монтажёра: ключ (хеш SHA-256 в приватном конфиге тома) привязан к компаниям; только
  чтение дублей своей компании, загрузка только `kind=draft`, отметка «в монтаже»; удалять не может.
- FR-10 Эскиз: только по нажатию, с пометкой «ТЕСТОВАЯ ВЕРСИЯ», лимит в сутки на компанию; нет
  ключа/права — «недоступно» с причиной. Ключ не читается в интерфейсе и не меняется.
- FR-11 Адаптивность 390 и 1440 px без горизонтальной прокрутки.

## Ограничения
Без merge/deploy, публикаций, сообщений, изменения ключей, прав и уведомлений. Видео и данные
клиентов в git не попадают. PR до ~500 строк: (а) сервер, (б) экран и загрузка, (в) суфлёр и
«Поделиться», (г) раскадровка и эскиз.

## Приёмка
Тесты: изоляция компаний, продолжение загрузки после обрыва и после «перезагрузки», отказ по месту,
API монтажёра, суфлёр в jsdom. Снимки Playwright 390/1440 с заглушкой API. Живой кабинет —
после выпуска, отдельно оркестратором.
